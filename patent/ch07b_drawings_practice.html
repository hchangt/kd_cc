Creating AI/ML Patent Drawings: Worked Examples

Step-by-step guide to creating block diagrams, flowcharts, and neural network figures

1. Neural Network Architecture Diagrams

Neural network figures are among the most common drawings in AI/ML patent applications. The USPTO requires drawings to be clear and unambiguous—every node and connection visible to a person of ordinary skill in the art. Effective NN diagrams satisfy three requirements: (1) every element recited in a claim must appear in at least one figure; (2) reference numerals must be consistent throughout all figures and the specification; and (3) the diagram must be reproducible in black-and-white at 300 dpi.

✎
Best Practices for NN Diagrams

Show layer boundaries explicitly. Group hidden layers with a brace or bracket when depicting deep networks—do not draw all 96 layers individually. Label weight connections with variable names (wij) only when a claim explicitly recites them. Use consistent node sizes. Avoid color: shading should be cross-hatching or gray fill expressly permitted under 37 C.F.R. § 1.84(b).

2. Transformer Block Diagram

Transformer-based architectures present a diagramming challenge: the multi-head attention mechanism involves parallel sub-computations that must be represented without clutter. The preferred USPTO-acceptable approach is a sequential block diagram showing the encoder or decoder stack as a vertical series of labeled rectangles connected by arrows. Each functional block corresponds to a claim element; the reference numeral assigned in the figure must appear verbatim in every claim that recites that element.

ℹ
Residual Connections

The "Add & Norm" blocks in a transformer encoder represent residual (skip) connections plus layer normalization. If your claims recite these operations separately, they must appear as distinct blocks with distinct reference numerals—do not collapse them into a single box unless your claims do the same.

FIG. 2 — Transformer encoder block comprising input embeddings 100, multi-head attention 102, add & norm layers 104 and 108, feed-forward network 106, and output 110; dashed line indicates residual connection

3. Algorithm Flowcharts

Flowcharts document algorithmic processes and are typically required when claims recite method steps. USPTO rules do not mandate specific symbols, but industry convention—oval for start/end, rectangle for process, diamond for decision—is universally understood and recommended. Each decision diamond must show all exit paths; an unlabeled branch is a prosecution pitfall. Arrange steps in top-to-bottom or left-to-right reading order. Loop-back arrows are drawn to the left or right margin, never obscuring other elements.

⚠
Decision Diamonds Must Have Labeled Exits

Every exit branch of a decision diamond must be labeled (e.g., "YES" / "NO" or "TRUE" / "FALSE"). Examiners frequently reject figures where the condition and its branches are ambiguous. If a loop runs a fixed number of epochs, label the "NO" branch "ITERATE" and the "YES" branch "CONVERGED" rather than relying on the reader to infer direction.

4. System Architecture Diagram

System diagrams show how modules interconnect and are the primary vehicle for apparatus claims. Each rectangle represents a claimed "module," "engine," or "processor." Data flow is indicated by directional arrows. When a module contains a sub-component recited in a dependent claim, show the sub-component as a nested box inside the parent. Reference numerals for nested components are conventionally assigned within the parent's range (e.g., training engine 304 contains neural network 306).

5. Writing Figure Descriptions

37 C.F.R. § 1.74 requires a "brief description of the several views of the drawings" as a distinct section of the specification, appearing after the Summary and before the Detailed Description. Each sentence identifies the figure number and gives a one-sentence functional summary. Keep these sentences purely descriptive—do not inject claim language or functional limitations here; save that for the Detailed Description.

Formal "Brief Description" Section

BRIEF DESCRIPTION OF THE DRAWINGS

FIG. 1 is a block diagram illustrating a feedforward neural network
100 in accordance with one embodiment of the present disclosure,
comprising an input layer, a hidden layer, and an output layer.

FIG. 2 is a block diagram of a transformer encoder block in
accordance with one embodiment, showing an input embedding layer,
a multi-head attention module, feed-forward network, residual
connections, and layer normalization operations.

FIG. 3 is a flowchart illustrating a training algorithm in
accordance with one embodiment, including data loading, forward
and backward passes, weight updates, and a convergence check.

FIG. 4 is a system architecture diagram of a machine learning
system in accordance with one embodiment, comprising a data
source, preprocessing module, training engine, model storage,
inference engine, and output interface.

In-Text Figure References in the Detailed Description

Every reference numeral in a figure must be introduced and explained in the Detailed Description. The accepted form is to open a paragraph with "Referring now to FIG. X" and then walk through each element. The description should track the claim structure: if claim 1 recites the input layer before the hidden layer, describe them in the same order.

Referring now to FIG. 1, a neural network 100 comprises an input
layer having input nodes 102, 104, and 106, each configured to
receive a feature value of an input vector. A hidden layer
comprises nodes 110, 112, 114, and 116, each fully connected to
every input node. An output layer comprises output nodes 120 and
122, each producing a scalar confidence value corresponding to
a predicted class label.

Referring now to FIG. 2, a transformer encoder block comprises
an input embedding layer 100 that maps each token in an input
sequence to a fixed-dimensional embedding vector. A multi-head
attention module 102 receives the embedding vectors and computes
scaled dot-product attention across Q, K, and V projections.
An add-and-normalize layer 104 sums the attention output with
the residual input and applies layer normalization...
⚠
New Matter Risk

A reference numeral that appears in the spec but not in any figure—or vice versa—creates an inconsistency that can support a new matter rejection under 35 U.S.C. § 132 if corrected after filing. Perform a numeral audit before filing: every numeral in every figure should appear in the Detailed Description, and every numeral in the Detailed Description should appear in at least one figure.

6. Complete Drawing Checklist

Use this checklist before filing. Each item addresses a distinct USPTO requirement or prosecution best practice.

  • Every element recited in an independent claim is illustrated in at least one figure.
  • Every element recited in each dependent claim is identifiable in the figures (either its own figure or inherited from independent claim figure).
  • All reference numerals used in the drawings appear verbatim in the Detailed Description of the Specification.
  • All reference numerals used in the Detailed Description appear in at least one figure.
  • Reference numerals are consistent—each numeral identifies one and only one element throughout all figures and the spec.
  • Figures are rendered in black-and-white only; no color or grayscale shading without a petition under 37 C.F.R. § 1.84(a)(2).
  • Lines are solid and have sufficient stroke weight (≥ 0.4 mm at final print size) to survive photocopying.
  • Figure labels ("FIG. 1", "FIG. 2", etc.) appear below each figure as required by 37 C.F.R. § 1.84(p)(1).
  • Margins comply with USPTO standards: top and left ≥ 2.5 cm; right and bottom ≥ 1.5 cm on 21.6 × 27.9 cm sheets.
  • Sheet numbers appear in the top center (e.g., "1/4") per 37 C.F.R. § 1.84(c).
  • No descriptive text appears in the figures beyond reference numerals and minimal labels (e.g., "YES"/"NO")—elaborate text belongs in the spec.
  • Flowchart decision diamonds have all exit branches labeled.
  • Loop-back arrows in flowcharts do not cross or obscure other elements.
  • Nested sub-components in system diagrams use dashed borders to visually distinguish containment from parallel components.
  • Neural network figures show layer boundaries explicitly, with at least the first and last node in each layer labeled.
  • The "Brief Description of the Drawings" section lists every figure in numerical order with a one-sentence description.
  • Figures are filed as searchable PDF (USPTO eFiling) or as clean TIF/PDF at 300 dpi minimum.
  • If the application claims priority, drawings have been checked against priority application figures to ensure no new matter is introduced.
  • Formal drawings (not informal) are submitted with the initial filing when possible to avoid a Notice to File Corrected Application Papers.
  • A legend or key is included whenever line styles (solid, dashed, dotted) carry distinct meaning in the same figure.
