1. Model Serving Fundamentals

Online vs Offline (Batch) Inference

The fundamental design choice in every serving system is whether predictions are generated synchronously (online) or asynchronously in bulk (offline / batch).

DimensionOnline InferenceBatch / Offline Inference
Latency target1–200 ms (P99)Minutes to hours
Throughput goalModerate QPS, low tail latencyMaximum throughput
TriggerUser request / API callScheduled job, new data arrival
Resource utilizationSpiky; must handle burstsSteady; fully utilizes GPUs
ExampleSearch ranking, fraud detectionContent recommendation precompute

Latency vs Throughput Tradeoff

These two metrics are inversely related in most serving architectures. Batching increases throughput by amortizing kernel launch overhead across multiple samples, but adds queuing latency. The optimal batch size is the largest value that keeps P99 latency within the SLA.

Performance insight: On A100 GPUs, a ResNet-50 reaches peak throughput at batch=256 (~4,000 images/sec) but P99 latency balloons to 120 ms. At batch=8, P99 stays under 8 ms while throughput is only ~1,200 images/sec. Always characterize the latency/throughput Pareto curve before choosing a batch size for your SLA.

SLA Requirements: P50 / P95 / P99

Percentile latencies are the language of production SLAs. P50 is the median experience. P99 is the worst 1% of requests — these are the ones causing user-visible slowness and cascade failures. P99.9 matters when you're serving 1M+ RPM because that is 1,000+ slow requests per minute.

  • P50 (median): Indicates typical request cost. Easy to optimize.
  • P95: Real-world user experience benchmark; target for API SLAs.
  • P99: Drives infrastructure sizing. Outliers caused by GC, memory pressure, cold paths.
  • P99.9: Required for financial / safety-critical systems.

2. NVIDIA Triton Inference Server

Triton is NVIDIA's open-source, production-grade inference server. At OpenAI and major hyperscalers it runs tens of thousands of GPU-hours daily. It abstracts away framework differences and gives you a uniform HTTP/gRPC API regardless of whether your model is a TensorRT engine, PyTorch script, or a custom C++ backend.

Python Client for Triton

"""tritonclient — synchronous and async inference examples."""
import numpy as np
import tritonclient.http as httpclient
import tritonclient.grpc as grpcclient
from tritonclient.utils import InferenceServerException

# --- HTTP client ---
def triton_http_infer(server_url: str, model_name: str, image: np.ndarray) -> np.ndarray:
    client = httpclient.InferenceServerClient(url=server_url, verbose=False)

    # Health check
    assert client.is_server_live(), "Triton server is not live"
    assert client.is_model_ready(model_name), f"Model {model_name} is not ready"

    # Prepare input tensor (NCHW float32)
    inp = httpclient.InferInput("input", image.shape, datatype="FP32")
    inp.set_data_from_numpy(image, binary_data=True)

    # Prepare output placeholder
    out = httpclient.InferRequestedOutput("output", binary_data=True)

    # Infer
    response = client.infer(model_name=model_name, inputs=[inp], outputs=[out])
    return response.as_numpy("output")


# --- gRPC client (lower overhead for high QPS) ---
def triton_grpc_infer(server_url: str, model_name: str, image: np.ndarray) -> np.ndarray:
    client = grpcclient.InferenceServerClient(url=server_url)

    inp = grpcclient.InferInput("input", image.shape, datatype="FP32")
    inp.set_data_from_numpy(image)

    out = grpcclient.InferRequestedOutput("output")
    result = client.infer(model_name=model_name, inputs=[inp], outputs=[out])
    return result.as_numpy("output")


# --- Async streaming client for high-throughput pipelines ---
import tritonclient.grpc.aio as grpc_aio
import asyncio

async def triton_async_batch(server_url: str, model_name: str, batch: list[np.ndarray]):
    async with grpc_aio.InferenceServerClient(url=server_url) as client:
        tasks = []
        for img in batch:
            inp = grpc_aio.InferInput("input", img.shape, "FP32")
            inp.set_data_from_numpy(img)
            out = grpc_aio.InferRequestedOutput("output")
            tasks.append(client.infer(model_name=model_name, inputs=[inp], outputs=[out]))
        results = await asyncio.gather(*tasks)
    return [r.as_numpy("output") for r in results]


# Example usage
if __name__ == "__main__":
    img = np.random.randn(1, 3, 224, 224).astype(np.float32)
    logits = triton_http_infer("localhost:8000", "resnet50", img)
    print(f"Top-1 class: {logits.argmax()}, confidence: {logits.max():.4f}")

Triton ensembles wire multiple models together in a DAG without any round-trip to the client. This is critical for pre-processing + inference + post-processing pipelines.

      output_map { key: "ATTENTION_MASK" value: "attn_mask" }
    },
    # Step 2: ONNX BERT inference
    {
      model_name: "bert_inference"
      model_version: -1
      input_map  { key: "input_ids"      value: "token_ids" }

      output_map { key: "last_hidden_state" value: "EMBEDDINGS" }
    }
  ]
}
Tip — Concurrent model execution: Set instance_group count to match the number of GPU SMs you want to dedicate per model. For small models on A100/H100, running 4 instances on one GPU (MIG or time-sliced) can triple throughput over a single instance while staying under your latency budget.

3. TorchServe

TorchServe is PyTorch's official model serving library — simpler than Triton, no YAML protobufs, pure Python handlers. It's ideal for teams that are all-in on PyTorch and want a straightforward path from torch.save to a REST API.

Creating Model Archives (.mar files)

# Install TorchServe
pip install torchserve torch-model-archiver torch-workflow-archiver

# Export a traced model
python -c "
import torch
from torchvision.models import resnet50, ResNet50_Weights
m = resnet50(weights=ResNet50_Weights.DEFAULT).eval()
traced = torch.jit.trace(m, torch.randn(1, 3, 224, 224))
torch.jit.save(traced, 'resnet50_traced.pt')
"

# Build the .mar archive
torch-model-archiver \
  --model-name resnet50 \
  --version 1.0 \
  --serialized-file resnet50_traced.pt \
  --handler image_classifier \
  --extra-files index_to_name.json \
  --export-path model_store

# Start TorchServe
mkdir -p model_store logs
torchserve \
  --start \
  --ncs \
  --model-store model_store \
  --models resnet50=resnet50.mar \
  --ts-config config.properties

Custom Handler for TorchServe

"""custom_handler.py — production TorchServe handler with pre/post-processing."""
import io
import json
import logging
import os
from typing import Any

import torch
import torchvision.transforms as T
from PIL import Image
from ts.torch_handler.base_handler import BaseHandler

logger = logging.getLogger(__name__)


class ImageClassifierHandler(BaseHandler):
    """
    Custom handler: accepts raw JPEG bytes, returns top-5 class probabilities.
    """

    TRANSFORM = T.Compose([
        T.Resize(256),
        T.CenterCrop(224),
        T.ToTensor(),
        T.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]),
    ])

    def initialize(self, context):
        """Load model and class index on worker startup."""
        super().initialize(context)  # sets self.model, self.device

        # Load label map
        props = context.system_properties
        model_dir = props.get("model_dir")
        with open(os.path.join(model_dir, "index_to_name.json")) as f:
            self.label_map: dict[str, str] = json.load(f)

        self.model.eval()
        logger.info("ImageClassifierHandler initialized on %s", self.device)

    def preprocess(self, data: list[dict]) -> torch.Tensor:
        """Convert raw request bytes to a batched float32 tensor."""
        tensors = []
        for item in data:
            body = item.get("body") or item.get("data")
            if isinstance(body, (bytes, bytearray)):
                image = Image.open(io.BytesIO(body)).convert("RGB")
            else:
                raise ValueError("Expected raw image bytes")
            tensors.append(self.TRANSFORM(image))
        return torch.stack(tensors).to(self.device)

    def inference(self, inputs: torch.Tensor) -> torch.Tensor:
        """Run forward pass without gradient computation."""
        with torch.no_grad():
            return self.model(inputs)

    def postprocess(self, logits: torch.Tensor) -> list[dict[str, Any]]:
        """Return top-5 class names and probabilities per sample."""
        probs = torch.softmax(logits, dim=-1)
        top5_probs, top5_idxs = probs.topk(5, dim=-1)

        results = []
        for sample_probs, sample_idxs in zip(top5_probs, top5_idxs):
            results.append([
                {
                    "class": self.label_map.get(str(idx.item()), str(idx.item())),
                    "probability": round(p.item(), 6),
                }
                for p, idx in zip(sample_probs, sample_idxs)
            ])
        return results

4. ONNX and Model Optimization

ONNX (Open Neural Network Exchange) is the common IR (intermediate representation) that lets you train in PyTorch, export to ONNX, and run on any runtime — CPU, GPU, edge SoC. Combined with TensorRT, it is the highest-performance path on NVIDIA hardware.

Exporting PyTorch Model to ONNX

"""export_onnx.py — export, verify, and optimize a PyTorch model to ONNX."""
import torch
import onnx
import onnxruntime as ort
import numpy as np
from torchvision.models import resnet50, ResNet50_Weights

# 1. Load and prepare model
model = resnet50(weights=ResNet50_Weights.DEFAULT).eval()
dummy_input = torch.randn(1, 3, 224, 224)

# 2. Export with dynamic axes so batch size is flexible at runtime
torch.onnx.export(
    model,
    dummy_input,
    "resnet50.onnx",
    export_params=True,
    opset_version=17,              # use latest stable opset
    do_constant_folding=True,      # fold constants for speedup
    input_names=["input"],
    output_names=["output"],
    dynamic_axes={
        "input":  {0: "batch_size"},
        "output": {0: "batch_size"},
    },
    verbose=False,
)

# 3. Verify the exported graph
model_onnx = onnx.load("resnet50.onnx")
onnx.checker.check_model(model_onnx)
print(f"ONNX model opset: {model_onnx.opset_import[0].version}")

# 4. Optional: simplify with onnx-simplifier (pip install onnxsim)
try:
    from onnxsim import simplify
    model_simplified, ok = simplify(model_onnx)
    if ok:
        onnx.save(model_simplified, "resnet50_simplified.onnx")
        print("Simplified ONNX model saved")
except ImportError:
    pass

# 5. Quick correctness check: compare PyTorch vs ONNX Runtime outputs
sess = ort.InferenceSession("resnet50.onnx", providers=["CUDAExecutionProvider", "CPUExecutionProvider"])
x_np = dummy_input.numpy()
ort_output = sess.run(None, {"input": x_np})[0]

with torch.no_grad():
    torch_output = model(dummy_input).numpy()

np.testing.assert_allclose(torch_output, ort_output, rtol=1e-3, atol=1e-5)
print("Outputs match between PyTorch and ONNX Runtime")

ONNX Runtime Inference Server

"""onnx_server.py — production-grade ONNX Runtime inference wrapper."""
import asyncio
import time
from contextlib import asynccontextmanager
from typing import Any

import numpy as np
import onnxruntime as ort
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

# ---- ORT session singleton with optimal session options ----
class ONNXInferenceEngine:
    def __init__(self, model_path: str, device: str = "cuda"):
        opts = ort.SessionOptions()
        opts.graph_optimization_level = ort.GraphOptimizationLevel.ORT_ENABLE_ALL
        opts.intra_op_num_threads = 4
        opts.inter_op_num_threads = 2
        opts.enable_mem_pattern = True
        opts.enable_cpu_mem_arena = True

        providers = (
            [("CUDAExecutionProvider", {"device_id": 0, "arena_extend_strategy": "kSameAsRequested"}),
             "CPUExecutionProvider"]
            if device == "cuda"
            else ["CPUExecutionProvider"]
        )

        self.session = ort.InferenceSession(model_path, sess_options=opts, providers=providers)
        self.input_names  = [inp.name for inp in self.session.get_inputs()]
        self.output_names = [out.name for out in self.session.get_outputs()]
        print(f"Loaded {model_path} | providers: {self.session.get_providers()}")

    def predict(self, inputs: dict[str, np.ndarray]) -> dict[str, np.ndarray]:
        t0 = time.perf_counter()
        outputs = self.session.run(self.output_names, inputs)
        latency_ms = (time.perf_counter() - t0) * 1000
        return {
            "outputs": dict(zip(self.output_names, outputs)),
            "latency_ms": round(latency_ms, 3),
        }


# ---- FastAPI app wiring (see Section 5 for full FastAPI details) ----
engine: ONNXInferenceEngine | None = None

@asynccontextmanager
async def lifespan(app: FastAPI):
    global engine
    engine = ONNXInferenceEngine("resnet50_simplified.onnx", device="cuda")
    yield
    engine = None

app = FastAPI(title="ONNX Inference Server", lifespan=lifespan)

class InferenceRequest(BaseModel):
    data: list[list[list[list[float]]]]   # [N, C, H, W]

@app.post("/predict")
async def predict(req: InferenceRequest):
    if engine is None:
        raise HTTPException(503, "Engine not ready")
    x = np.array(req.data, dtype=np.float32)
    result = engine.predict({"input": x})
    logits = result["outputs"]["output"]
    return {
        "predictions": logits.argmax(axis=-1).tolist(),
        "latency_ms": result["latency_ms"],
    }

TensorRT Engine Creation from ONNX

"""build_tensorrt.py — build a TensorRT FP16 engine from an ONNX model."""
import tensorrt as trt
import numpy as np

TRT_LOGGER = trt.Logger(trt.Logger.WARNING)


def build_engine(
    onnx_path: str,
    engine_path: str,
    fp16: bool = True,
    max_batch: int = 32,
    workspace_gb: int = 4,
) -> None:
    builder = trt.Builder(TRT_LOGGER)
    network_flags = 1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH)
    network = builder.create_network(network_flags)
    parser  = trt.OnnxParser(network, TRT_LOGGER)

    with open(onnx_path, "rb") as f:
        if not parser.parse(f.read()):
            for i in range(parser.num_errors):
                print(f"TRT ONNX parse error: {parser.get_error(i)}")
            raise RuntimeError("Failed to parse ONNX")

    config = builder.create_builder_config()
    config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, workspace_gb * (1 << 30))

    if fp16 and builder.platform_has_fast_fp16:
        config.set_flag(trt.BuilderFlag.FP16)
        print("FP16 mode enabled")

    # Dynamic shapes profile
    profile = builder.create_optimization_profile()
    profile.set_shape(
        "input",
        min=(1,  3, 224, 224),
        opt=(16, 3, 224, 224),
        max=(max_batch, 3, 224, 224),
    )
    config.add_optimization_profile(profile)

    print("Building TensorRT engine (this may take minutes) ...")
    serialized = builder.build_serialized_network(network, config)
    if serialized is None:
        raise RuntimeError("TensorRT engine build failed")

    with open(engine_path, "wb") as f:
        f.write(serialized)
    print(f"Engine saved to {engine_path}")


def load_and_infer(engine_path: str, x: np.ndarray) -> np.ndarray:
    """Load a serialized TRT engine and run inference."""
    runtime = trt.Runtime(TRT_LOGGER)
    with open(engine_path, "rb") as f:
        engine = runtime.deserialize_cuda_engine(f.read())

    import cuda
    context = engine.create_execution_context()
    context.set_input_shape("input", x.shape)

    # Allocate CUDA memory and run
    import pycuda.driver as cuda_drv
    import pycuda.autoinit  # noqa: F401

    d_input  = cuda_drv.mem_alloc(x.nbytes)
    output_shape = (x.shape[0], 1000)
    output = np.empty(output_shape, dtype=np.float32)
    d_output = cuda_drv.mem_alloc(output.nbytes)

    cuda_drv.memcpy_htod(d_input, x)
    context.execute_v2([int(d_input), int(d_output)])
    cuda_drv.memcpy_dtoh(output, d_output)
    return output

5. FastAPI for ML APIs

FastAPI is the de-facto standard for writing ML microservices in Python. Its async-first design fits the GPU-bound concurrency model perfectly: the event loop dispatches requests while the GPU is computing. Pydantic v2 gives you zero-cost request validation.

Complete FastAPI ML Service

"""ml_service.py — production-quality FastAPI ML service with metrics, health, async inference."""

import logging

from typing import Any

import numpy as np

from starlette.responses import Response

# ---- Logging ----

# ---- Prometheus metrics ----

REQUEST_LATENCY = Histogram("ml_latency_seconds", "Inference latency",           ["model"],
                             buckets=[.005, .01, .025, .05, .1, .25, .5, 1, 2.5, 5])

# ---- Request / Response schemas ----
class PredictRequest(BaseModel):
    instances: list[list[float]] = Field(..., min_length=1, max_length=256,
                                          description="List of feature vectors")
    model_version: str = Field("latest", description="Model version tag")

class PredictionResult(BaseModel):
    predictions: list[int]
    probabilities: list[list[float]]
    model_version: str
    latency_ms: float

class HealthResponse(BaseModel):
    status: str
    model_loaded: bool
    device: str
    uptime_seconds: float

# ---- Model registry ----
class ModelRegistry:
    def __init__(self):
        self._models: dict[str, Any]  = {}
        self._start_time = time.time()

    def load(self, name: str, model: Any, device: str = "cpu"):
        model = model.to(device).eval()
        self._models[name] = {"model": model, "device": device, "loaded_at": time.time()}
        logger.info("Model '%s' loaded on %s", name, device)

    def get(self, name: str = "latest"):
        if name == "latest":
            name = max(self._models.keys())
        if name not in self._models:
            raise KeyError(f"Model '{name}' not found")
        return self._models[name]

    @property
    def uptime(self) -> float:
        return time.time() - self._start_time

registry = ModelRegistry()

# ---- Application lifecycle ----
@asynccontextmanager
async def lifespan(app: FastAPI):
    # Startup: load model
    device = "cuda" if torch.cuda.is_available() else "cpu"
    logger.info("Starting ML service on device: %s", device)

    from torchvision.models import resnet18, ResNet18_Weights
    model = resnet18(weights=ResNet18_Weights.DEFAULT)
    registry.load("v1.0", model, device=device)
    registry.load("latest", model, device=device)   # alias

    # Background task: periodically poll GPU utilization
    async def poll_gpu():
        while True:
            try:
                import pynvml
                pynvml.nvmlInit()
                h = pynvml.nvmlDeviceGetHandleByIndex(0)
                util = pynvml.nvmlDeviceGetUtilizationRates(h)
                GPU_UTIL.labels(device="gpu:0").set(util.gpu)
            except Exception:
                pass
            await asyncio.sleep(5)

    task = asyncio.create_task(poll_gpu())
    yield
    task.cancel()

@app.get("/health", response_model=HealthResponse)

@app.post("/v1/predict", response_model=PredictionResult)
async def predict(req: PredictRequest, request: Request):
    model_name = req.model_version
    QUEUE_DEPTH.labels(model=model_name).inc()
    t0 = time.perf_counter()
    try:
        entry = registry.get(model_name)
        model: torch.nn.Module = entry["model"]
        device: str = entry["device"]

        # Prepare input — run CPU tensor ops in a thread pool to avoid blocking the loop
        x = await asyncio.get_event_loop().run_in_executor(
            None,
            lambda: torch.tensor(req.instances, dtype=torch.float32).to(device)
        )

        # GPU inference
        with torch.inference_mode():
            logits = await asyncio.get_event_loop().run_in_executor(None, lambda: model(x))
            probs  = F.softmax(logits, dim=-1)
            preds  = probs.argmax(dim=-1)

        latency_ms = (time.perf_counter() - t0) * 1000
        REQUEST_COUNT.labels(model=model_name, status="ok").inc()
        REQUEST_LATENCY.labels(model=model_name).observe(time.perf_counter() - t0)

        return PredictionResult(
            predictions=preds.cpu().tolist(),
            probabilities=probs.cpu().tolist(),
            model_version=model_name,
            latency_ms=round(latency_ms, 3),
        )
    except KeyError as e:
        REQUEST_COUNT.labels(model=model_name, status="not_found").inc()
        raise HTTPException(status_code=404, detail=str(e))
    except Exception as e:
        REQUEST_COUNT.labels(model=model_name, status="error").inc()
        logger.exception("Inference failed: %s", e)
        raise HTTPException(status_code=500, detail="Inference failed")
    finally:
        QUEUE_DEPTH.labels(model=model_name).dec()

@app.get("/metrics")
async def metrics():
    """Prometheus scrape endpoint."""
    return Response(generate_latest(), media_type=CONTENT_TYPE_LATEST)

FastAPI with Background Inference and Callback

"""async_inference.py — fire-and-forget inference with webhook callback."""
import asyncio
import uuid
from enum import Enum

import httpx
from fastapi import BackgroundTasks, FastAPI
from pydantic import BaseModel, HttpUrl

app = FastAPI()
JOB_STORE: dict[str, dict] = {}   # in production use Redis

class JobStatus(str, Enum):
    PENDING   = "pending"
    RUNNING   = "running"
    COMPLETED = "completed"
    FAILED    = "failed"

class AsyncRequest(BaseModel):
    instances: list[list[float]]
    callback_url: HttpUrl | None = None   # optional webhook

class JobResponse(BaseModel):
    job_id: str
    status: JobStatus
    result: dict | None = None

async def _run_inference(job_id: str, instances: list, callback_url: str | None):
    JOB_STORE[job_id]["status"] = JobStatus.RUNNING
    try:
        # Simulate heavy GPU work
        await asyncio.sleep(0.5)
        result = {"predictions": [0] * len(instances)}
        JOB_STORE[job_id].update({"status": JobStatus.COMPLETED, "result": result})

        # Optionally notify caller
        if callback_url:
            async with httpx.AsyncClient(timeout=10) as client:
                await client.post(callback_url, json={"job_id": job_id, **result})
    except Exception as exc:
        JOB_STORE[job_id].update({"status": JobStatus.FAILED, "error": str(exc)})

@app.post("/v1/predict/async", response_model=JobResponse, status_code=202)
async def predict_async(req: AsyncRequest, background_tasks: BackgroundTasks):
    job_id = str(uuid.uuid4())
    JOB_STORE[job_id] = {"status": JobStatus.PENDING, "result": None}
    background_tasks.add_task(_run_inference, job_id, req.instances, str(req.callback_url) if req.callback_url else None)
    return JobResponse(job_id=job_id, status=JobStatus.PENDING)

@app.get("/v1/jobs/{job_id}", response_model=JobResponse)
async def get_job(job_id: str):
    if job_id not in JOB_STORE:
        from fastapi import HTTPException
        raise HTTPException(404, "Job not found")
    j = JOB_STORE[job_id]
    return JobResponse(job_id=job_id, status=j["status"], result=j.get("result"))
Request batching with asyncio: For throughput-critical services, accumulate requests in an asyncio.Queue and flush on a timer (e.g., every 10 ms) or when the queue reaches the max batch size. This implements dynamic batching in pure Python — useful when you can't use Triton's built-in dynamic batcher.

BentoML Runner with Adaptive Batching

"""runner_batching.py — BentoML runner with adaptive batch config."""
import bentoml
from bentoml.io import JSON, NumpyNdarray
from pydantic import BaseModel
import numpy as np

class ClassifyRequest(BaseModel):
    image_b64: str
    top_k: int = 5

# Custom runner configuration
runner = bentoml.pytorch.get("resnet50:latest").to_runner(
    name="resnet_runner",
    max_batch_size=64,           # maximum batch size for adaptive batching
    max_latency_ms=100,          # flush batch at this latency even if not full
)

svc = bentoml.Service("classifier_svc", runners=[runner])

@svc.api(input=JSON(pydantic_model=ClassifyRequest), output=JSON())
async def predict(req: ClassifyRequest) -> dict:
    import base64, io
    from PIL import Image
    import torchvision.transforms as T

    img_bytes = base64.b64decode(req.image_b64)
    img = Image.open(io.BytesIO(img_bytes)).convert("RGB")

    transform = T.Compose([T.Resize(256), T.CenterCrop(224), T.ToTensor(),
                            T.Normalize([0.485, 0.456, 0.406], [0.229, 0.224, 0.225])])
    tensor = transform(img).unsqueeze(0).numpy()

    # Runner handles batching automatically across concurrent requests
    logits = await runner.async_run(tensor)
    probs = np.exp(logits) / np.exp(logits).sum()
    top_k_idx = probs.argsort()[-req.top_k:][::-1]
    return {"top_k_classes": top_k_idx.tolist(), "probabilities": probs[top_k_idx].tolist()}

"""spark_batch_inference.py — broadcast model weights across Spark workers."""
from pyspark.sql import SparkSession
from pyspark.sql.functions import pandas_udf
from pyspark.sql.types import ArrayType, FloatType
import pandas as pd
import numpy as np
import torch
import io

spark = SparkSession.builder \
    .appName("BatchInference") \
    .config("spark.sql.execution.arrow.pyspark.enabled", "true") \
    .config("spark.executor.memory", "16g") \
    .getOrCreate()

# Serialize model to bytes and broadcast to all workers
import torchvision.models as models
model = models.resnet50(pretrained=True).eval()
buf = io.BytesIO()
torch.save(model.state_dict(), buf)
model_broadcast = spark.sparkContext.broadcast(buf.getvalue())

@pandas_udf(returnType=ArrayType(FloatType()))
def predict_udf(pixel_series: pd.Series) -> pd.Series:
    """Runs on each Spark partition — loads model once per JVM process."""
    import torch, io
    from torchvision.models import resnet50

    # Load model from broadcast — only once per executor
    if not hasattr(predict_udf, "_model"):
        m = resnet50()
        state = torch.load(io.BytesIO(model_broadcast.value), map_location="cpu")
        m.load_state_dict(state)
        m.eval()
        predict_udf._model = m

    results = []
    for pixel_bytes in pixel_series:
        x = torch.frombuffer(pixel_bytes, dtype=torch.float32).reshape(1, 3, 224, 224)
        with torch.no_grad():
            logits = predict_udf._model(x)
        results.append(logits.squeeze().tolist())
    return pd.Series(results)

# Apply to a DataFrame with an 'image_pixels' binary column
df = spark.read.parquet("s3a://data-lake/images/")
predictions_df = df.withColumn("logits", predict_udf("image_pixels"))
predictions_df.write.mode("overwrite").parquet("s3a://data-lake/predictions/")

"""sqs_worker.py — async inference worker: SQS → model → S3 result."""
import json
import os
import time
import uuid

import boto3
import numpy as np

sqs     = boto3.client("sqs", region_name="us-east-1")
s3      = boto3.client("s3")
QUEUE   = os.environ["INFERENCE_QUEUE_URL"]
BUCKET  = os.environ["RESULTS_BUCKET"]

def load_model():
    """Load model once at worker startup."""
    import onnxruntime as ort
    sess = ort.InferenceSession("model.onnx", providers=["CUDAExecutionProvider"])
    return sess

def process_message(session, message: dict) -> dict:
    body   = json.loads(message["Body"])
    job_id = body["job_id"]
    s3_key = body["input_s3_key"]

    # Download input from S3
    obj = s3.get_object(Bucket=BUCKET, Key=s3_key)
    x   = np.frombuffer(obj["Body"].read(), dtype=np.float32).reshape(body["shape"])

    # Infer
    t0     = time.perf_counter()
    output = session.run(None, {"input": x})[0]
    ms     = (time.perf_counter() - t0) * 1000

    # Upload result to S3
    result_key = f"results/{job_id}.npy"
    s3.put_object(Bucket=BUCKET, Key=result_key, Body=output.tobytes())

    return {"job_id": job_id, "result_key": result_key, "latency_ms": round(ms, 2)}

def main():
    session = load_model()
    print("Worker ready, polling SQS ...")
    while True:
        resp = sqs.receive_message(
            QueueUrl=QUEUE,
            MaxNumberOfMessages=10,
            WaitTimeSeconds=20,       # long polling
        )
        for msg in resp.get("Messages", []):
            try:
                result = process_message(session, msg)
                print(f"Processed {result['job_id']} in {result['latency_ms']} ms")
                sqs.delete_message(QueueUrl=QUEUE, ReceiptHandle=msg["ReceiptHandle"])
            except Exception as e:
                print(f"Failed to process message: {e}")
                # Leave in queue for retry / DLQ

if __name__ == "__main__":
    main()

Multi-Model Endpoints (Cost Optimization)

On SageMaker, a Multi-Model Endpoint (MME) deploys thousands of models behind one endpoint. Models are loaded on-demand and cached in GPU memory. A LRU policy evicts infrequently accessed models. This is 90%+ cheaper than one endpoint per model for a long tail of low-traffic models.

Model Caching Strategies

  • Response cache (Redis): Cache identical input → output pairs. Effective when input space is small (e.g., trending queries).
  • Feature cache: Cache expensive feature lookups (embeddings, entity features) by entity ID.
  • Model weight cache: Pin model weights in GPU VRAM; use LRU for MME eviction policy.
  • KV cache (LLMs): Cache key/value attention states for prefix-shared prompts. Critical for serving LLMs efficiently.

Warm-up to Avoid Cold Start

First-request latency can be 10–100× higher than steady-state due to CUDA context initialization, JIT compilation, and memory allocation. Mitigate with:

  • Triton model_warmup block in config.pbtxt (shown in Section 2)
  • Kubernetes readinessProbe that fires synthetic requests before routing traffic
  • Pre-warming Lambda functions by scheduling keep-alive pings
  • TorchScript / TRT engines eliminate JIT compilation on first request

Blue/Green Model Deployments

Blue/green is the safest model rollout strategy. Key implementation:

  1. Deploy new model version to green cluster (zero traffic)
  2. Run shadow traffic: copy production requests to green and compare outputs
  3. Shift 5% → 10% → 25% → 50% → 100% traffic using weighted routing
  4. Monitor accuracy metrics, latency P99, error rates at each step
  5. Automated rollback: if error rate spikes >1% in 5-minute window, route 100% back to blue
Rollback readiness requirement: Never decommission the blue cluster until the green cluster has served 72+ hours of production traffic without regressions. Store previous model artifacts in S3 with a minimum 30-day retention policy. SageMaker model registry Approved vs PendingManualApproval states enforce this gate.

Summary & Key Takeaways

Performance Engineering

  • Always profile the latency/throughput Pareto curve before choosing batch size
  • TensorRT FP16 is the best first optimization on NVIDIA GPUs — 3–5× speedup with negligible accuracy loss
  • Dynamic batching (Triton built-in) improves GPU utilization without client changes
  • Warm-up requests eliminate cold-start latency spikes in production
  • gRPC outperforms REST for internal high-QPS services by 10–20%

Framework Selection

  • Triton: When you need maximum GPU performance, multi-backend, or complex model pipelines
  • TorchServe: Pure-PyTorch shops wanting a simple REST API with managed lifecycle
  • FastAPI + ONNX Runtime: Custom logic, rapid prototyping, non-standard preprocessing
  • BentoML: Data-science-friendly serving with automatic adaptive batching
  • Seldon / KServe: Enterprise Kubernetes, A/B testing, inference graphs, explainability

Reliability Patterns

  • Blue/green + shadow traffic is the only safe model rollout strategy at scale
  • Automated rollback triggered by error rate / P99 thresholds is non-negotiable
  • Multi-model endpoints (SageMaker MME, KServe ModelMesh) cut per-model costs by 90%+
  • Response caching removes GPU load for repeated identical requests
  • SLA targets: P99 <100 ms for online, measure P99.9 for safety-critical

Optimization Hierarchy

  • Step 1: Profile — find the bottleneck (CPU pre-processing? memory bandwidth? compute?)
  • Step 2: TorchScript / trace → ONNX to remove Python overhead
  • Step 3: TensorRT FP16 or ONNX Runtime CUDA EP
  • Step 4: INT8 quantization with calibration data
  • Step 5: Pruning + knowledge distillation for 5–10× end-to-end speedup
  • Step 6: Architectural changes (smaller model, MobileNet, DistilBERT)
