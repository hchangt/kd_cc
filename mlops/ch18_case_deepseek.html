1 DeepSeek Overview

DeepSeek AI, a research lab founded in 2023 under High-Flyer Capital Management, stunned the ML community in early 2025 by demonstrating that frontier-class LLMs could be trained at a fraction of Western lab costs. Their publication strategy — open weights plus detailed technical reports — provided an unprecedented look into the engineering decisions behind cost-efficient pre-training at scale.

The $5.5M Headline

DeepSeek-V3 required approximately 2.788M H800 GPU-hours for its 14.8T token pre-training run. At a spot price of roughly $2/GPU-hour, the compute cost was approximately $5.576M — an order of magnitude cheaper than estimated GPT-4 training costs [V3, §4.3]. This figure excludes exploratory experiments, ablations, and staff costs, but the raw compute efficiency is real and reproducible.

2 DeepSeekMoE Architecture [V2]

MoE Fundamentals

A Mixture-of-Experts layer replaces a standard dense FFN with N expert FFNs, activating only a top-K subset per token via a learned router. The router assigns each token a probability distribution over experts; only the top-K highest-scoring experts compute outputs, which are weighted-summed. The key benefit: total parameters scale as N×E (where E is expert size) but FLOPs per forward pass scale as K×E — enabling a large-capacity model at inference cost equivalent to a much smaller dense model.

Load balancing is the central MoE challenge. Without it, a few expert slots become overloaded ("expert collapse") while others are underutilized. DeepSeek-V2 addresses this with an auxiliary load-balancing loss plus a device-level balancing constraint [V2, §2.1].

Fine-Grained MoE with Shared Experts

DeepSeek's key architectural innovation over standard MoE (e.g., GShard, Switch Transformer) is two-fold [V2, §2.1]:

  • Fine-grained experts: Each expert is smaller (1/m of standard size), and the total activated expert count is K×m. This provides finer-grained specialization with the same compute budget — more routing options reduce "knowledge redundancy" where multiple experts learn the same representations.
  • Shared experts (always-active): K_s experts are activated for every token regardless of routing. These capture universal knowledge (syntax, common facts) that would otherwise be redundantly replicated across many routed experts. V2 uses K_s=2 shared experts with 160 routed experts, selecting top-6 per token.

Why Shared Experts Matter

Without shared experts, knowledge common to all tokens (stop words, basic syntax) must be replicated across many routed experts, wasting capacity. Shared experts decouple "universal" from "specialized" knowledge, improving parameter utilization efficiency by an estimated 8–12% in ablations [V2, Table 4].

MLA: Multi-head Latent Attention

Standard Multi-Head Attention (MHA) requires caching K and V tensors for all previous tokens at inference. For a model with n_h heads of dimension d_h, the KV cache per token is 2 × n_h × d_h × num_layers bytes — a dominant memory cost at long context. MLA compresses this by projecting into a low-rank latent space [V2, §2.2]:

MLA KV Compression (from [V2, Eq. 3–7]):

Down-projection: c_KV = W_DKV · h_t     (c_KV ∈ Rd_c, d_c << n_h·d_h)

Up-projection:  K = W_UK · c_KV     V = W_UV · c_KV

Cache only: c_KV of size d_c = 512 (vs. n_h·d_h = 128×128 = 16,384 in MHA)

KV cache reduction: ~32× vs. MHA at equivalent model size

For queries, MLA also uses a decoupled RoPE formulation to preserve positional encoding while keeping queries in compressed form during prefill [V2, §2.2]. Only the compressed latent c_KV is stored in the KV cache — the full K/V tensors are reconstructed on the fly during decoding.

MLA Attention: Simplified Implementation

Python — MLA attention (simplified, from [V2])
import torch
import torch.nn as nn
import torch.nn.functional as F

class MultiHeadLatentAttention(nn.Module):
    """
    Simplified MLA as described in DeepSeek-V2 [arXiv:2405.04434, §2.2].
    Key innovation: compress KV into low-rank latent c_KV (d_c dims)
    instead of caching full K/V (n_h * d_h dims per token).
    """
    def __init__(self, d_model=5120, n_heads=128, d_head=128,
                 d_c=512, d_c_q=1536):
        super().__init__()
        self.n_heads = n_heads
        self.d_head = d_head
        self.d_c = d_c          # KV compression dim (512 << 16384)
        self.d_c_q = d_c_q      # Q compression dim

        # KV down-projection: h_t -> c_KV  (the only thing cached)
        self.W_DKV = nn.Linear(d_model, d_c, bias=False)
        # KV up-projections: c_KV -> K, V
        self.W_UK = nn.Linear(d_c, n_heads * d_head, bias=False)
        self.W_UV = nn.Linear(d_c, n_heads * d_head, bias=False)

        # Query: also compressed to reduce activation memory
        self.W_DQ = nn.Linear(d_model, d_c_q, bias=False)
        self.W_UQ = nn.Linear(d_c_q, n_heads * d_head, bias=False)

        self.W_O = nn.Linear(n_heads * d_head, d_model, bias=False)
        self.scale = d_head ** -0.5

    def forward(self, x, kv_cache=None):
        """
        x: (batch, seq_len, d_model)
        kv_cache: list of cached c_KV tensors from prior tokens
        Returns: output tensor + updated c_KV for caching
        """
        B, T, _ = x.shape

        # --- Compress KV into latent (THIS is what gets cached) ---
        c_KV = self.W_DKV(x)                        # (B, T, d_c=512)

        # Append to cache if provided (autoregressive decode)
        if kv_cache is not None:
            c_KV_full = torch.cat([kv_cache, c_KV], dim=1)  # (B, T_total, d_c)
        else:
            c_KV_full = c_KV

        # Reconstruct K, V from compressed latent
        K = self.W_UK(c_KV_full)                    # (B, T_total, n_h * d_h)
        V = self.W_UV(c_KV_full)                    # (B, T_total, n_h * d_h)

        # Compress then reconstruct Q
        c_Q = self.W_DQ(x)
        Q = self.W_UQ(c_Q)                          # (B, T, n_h * d_h)

        # Reshape for multi-head attention
        def split_heads(t, T_len):
            return t.view(B, T_len, self.n_heads, self.d_head).transpose(1, 2)

        T_full = c_KV_full.shape[1]
        Q = split_heads(Q, T)
        K = split_heads(K, T_full)
        V = split_heads(V, T_full)

        # Scaled dot-product attention
        attn = torch.matmul(Q, K.transpose(-2, -1)) * self.scale
        attn = F.softmax(attn, dim=-1)
        out = torch.matmul(attn, V)

        # Merge heads and project
        out = out.transpose(1, 2).reshape(B, T, -1)
        return self.W_O(out), c_KV   # return c_KV for caching

3 DeepSeek-V3 Training Innovations [V3]

DeepSeek-V3 scaled to 671B total parameters trained on 14.8T tokens — yet introduced three key algorithmic innovations that dramatically improved hardware utilization and reduced cost vs. naive scaling [V3, §3].

DualPipe Pipeline Parallelism

Standard pipeline parallelism (GPipe, 1F1B) suffers from "pipeline bubbles" — GPU idle time while waiting for activations from prior stages. With a large number of pipeline stages (V3 uses 16 pipeline stages), bubble fraction grows to ~6% of total compute with 1F1B [V3, §3.2].

DualPipe addresses this by simultaneously feeding two micro-batches through the pipeline in opposite directions. The key insight: MoE layers have a natural computation-communication overlap window because expert dispatch (all-to-all) can be overlapped with attention computation in the opposite direction micro-batch. This reduces bubble fraction to near zero [V3, §3.2].

FP8 Mixed-Precision Training

DeepSeek-V3 pioneered FP8 training at this scale, reducing memory and compute significantly. The key challenges — and their solutions [V3, §3.3]:

  • Quantization granularity: Tile-wise quantization (128×128 tiles for GEMM operands) rather than per-tensor, preventing outlier activations from dominating scale factors.
  • Accumulation precision: FP8 GEMM accumulates into FP32 rather than FP16 to prevent underflow in gradient accumulation.
  • High-precision master weights: Optimizer states (Adam m/v) and master weights remain in BF16/FP32; only forward/backward GEMMs use FP8.
  • Online quantization: Scale factors computed per-tile per-step on the fly — no static calibration needed for training.

Multi-Token Prediction (MTP)

Standard next-token prediction trains the model to predict one future token per position. MTP adds auxiliary prediction heads that predict tokens at offsets 2, 3, ..., D simultaneously from the same hidden state [V3, §2.3]. This serves two purposes:

  • Richer training signal: Each forward pass provides D times more gradient signal, improving data efficiency — particularly important for code and structured outputs where future tokens are highly predictable.
  • Speculative decoding at inference: The auxiliary heads can propose candidate tokens that the main model verifies, achieving inference speedups of 1.8× with D=1 additional head [V3, §4.4].
Python — Multi-Token Prediction head (simplified, from [V3, §2.3])
import torch
import torch.nn as nn

class MultiTokenPredictionHead(nn.Module):
    """
    MTP auxiliary training objective from DeepSeek-V3 [arXiv:2412.19437, §2.3].
    Adds D extra prediction heads at offsets [1..D] from each position.
    During inference, head[0] provides speculative draft tokens.
    """
    def __init__(self, d_model: int, vocab_size: int, depth: int = 1):
        super().__init__()
        self.depth = depth  # D=1 in V3 (one additional head)

        # Each depth level has its own projection + RMSNorm
        self.norms = nn.ModuleList([nn.RMSNorm(d_model) for _ in range(depth)])
        # Transformer sub-block to integrate causal context
        self.transformers = nn.ModuleList([
            nn.TransformerEncoderLayer(d_model, nhead=8, dim_feedforward=d_model*4,
                                       batch_first=True, norm_first=True)
            for _ in range(depth)
        ])
        # Shared embedding matrix (tied to main model vocab embedding)
        self.lm_heads = nn.ModuleList([
            nn.Linear(d_model, vocab_size, bias=False) for _ in range(depth)
        ])

    def forward(self, hidden_states: torch.Tensor,
                target_ids: torch.Tensor) -> dict:
        """
        hidden_states: (B, T, d_model) from main model's last layer
        target_ids:    (B, T) ground-truth token IDs
        Returns dict with auxiliary losses for each depth.
        """
        losses = {}
        h = hidden_states

        for d in range(self.depth):
            # Normalize and apply transformer sub-block
            h = self.norms[d](h)
            h = self.transformers[d](h)

            # Predict token at offset (d+2) from each position
            logits = self.lm_heads[d](h)         # (B, T, vocab_size)

            # Shift targets: position i predicts target[i + d + 2]
            shift = d + 2
            if shift < target_ids.shape[1]:
                pred_logits = logits[:, :-shift, :].contiguous()
                pred_targets = target_ids[:, shift:].contiguous()
                loss = nn.functional.cross_entropy(
                    pred_logits.view(-1, pred_logits.size(-1)),
                    pred_targets.view(-1),
                    ignore_index=-100
                )
                losses[f"mtp_depth_{d+1}"] = loss

        return losses

def total_loss(main_loss, mtp_losses, lambda_mtp=0.3):
    """V3 uses λ=0.3 for MTP auxiliary weight [V3, §2.3]."""
    aux = sum(mtp_losses.values()) / max(len(mtp_losses), 1)
    return main_loss + lambda_mtp * aux

4 Training Infrastructure

H800 GPU Cluster

DeepSeek used NVIDIA H800 GPUs rather than H100s due to US export restrictions. The H800 has identical compute specs to H100 SXM5 (3,958 TFLOPS FP8 dense) but with NVLink bandwidth reduced from 900 GB/s to 400 GB/s [V3, §3.1]. This bandwidth reduction makes intra-node all-to-all communication significantly more expensive — a critical constraint for MoE expert dispatch.

The cluster topology is 8 H800 per node with NVLink intra-node, connected by 3.2 Tbps InfiniBand inter-node. MoE expert parallelism (EP=64, each expert group on 8 nodes) requires inter-node all-to-all at each MoE layer, making IB bandwidth the primary bottleneck [V3, §3.1].

Export Restriction Engineering

The H800's reduced NVLink bandwidth forced DeepSeek to innovate aggressively on communication scheduling. Their solution — limiting each token to dispatch to experts on at most M=4 nodes — reduces all-to-all traffic by restricting the routing fanout. Combined with IB/NVLink overlap in DualPipe, they recovered most of the lost bandwidth [V3, §3.1].

MoE All-to-All Communication

Each MoE layer requires two all-to-all communication phases: dispatch (send tokens to their selected experts on remote GPUs) and combine (receive computed results back). With 256 experts across 64 expert parallel ranks, each device must exchange data with up to 63 other devices per MoE layer.

Python — NCCL all-to-all for MoE expert dispatch (V3-style)
import torch
import torch.distributed as dist

def moe_all_to_all_dispatch(tokens: torch.Tensor,
                             expert_ids: torch.Tensor,
                             ep_group: dist.ProcessGroup,
                             max_nodes: int = 4) -> tuple:
    """
    MoE expert dispatch using all-to-all as described in [V3, §3.1].

    Key optimization: limit each token to experts on at most `max_nodes` nodes
    to bound inter-node traffic (node-constrained routing).

    Args:
        tokens:     (local_tokens, d_model) — tokens on this rank
        expert_ids: (local_tokens, top_k)   — selected expert global IDs
        ep_group:   expert parallel process group (EP=64 in V3)
        max_nodes:  max distinct nodes a token can dispatch to (M=4 in V3)

    Returns:
        recv_tokens:    tokens dispatched to this rank's experts
        routing_info:   metadata needed for combine step
    """
    world_size = dist.get_world_size(ep_group)
    rank = dist.get_rank(ep_group)
    local_tokens, d_model = tokens.shape
    top_k = expert_ids.shape[1]

    # Count how many tokens each rank sends to each other rank
    # expert_id -> rank mapping (each rank owns world_size//EP experts)
    experts_per_rank = 256 // world_size  # 4 in V3 (256 experts / 64 ranks)
    dest_ranks = expert_ids // experts_per_rank  # (local_tokens, top_k)

    # Build send count tensor for all-to-all metadata
    send_counts = torch.zeros(world_size, dtype=torch.long, device=tokens.device)
    for r in range(world_size):
        send_counts[r] = (dest_ranks == r).sum()

    # Exchange send counts so each rank knows how many to receive
    recv_counts = torch.zeros_like(send_counts)
    dist.all_to_all_single(recv_counts, send_counts, group=ep_group)

    # Sort tokens by destination rank for contiguous all-to-all send buffer
    flat_dest = dest_ranks.view(-1)  # (local_tokens * top_k,)
    sort_idx = torch.argsort(flat_dest)
    token_idx = sort_idx // top_k
    sorted_tokens = tokens[token_idx]         # (local_tokens*top_k, d_model)

    # All-to-all: exchange token data
    recv_total = recv_counts.sum().item()
    recv_buffer = torch.empty(recv_total, d_model, device=tokens.device,
                              dtype=tokens.dtype)

    send_splits = send_counts.tolist()
    recv_splits = recv_counts.tolist()

    # This is the core all-to-all — overlapped with attention in DualPipe
    dist.all_to_all(
        list(recv_buffer.split(recv_splits)),
        list(sorted_tokens.split(send_splits)),
        group=ep_group
    )

    routing_info = {"sort_idx": sort_idx, "send_counts": send_counts,
                    "recv_counts": recv_counts, "original_shape": tokens.shape}
    return recv_buffer, routing_info


def moe_all_to_all_combine(expert_outputs: torch.Tensor,
                            routing_info: dict,
                            gates: torch.Tensor,
                            ep_group: dist.ProcessGroup) -> torch.Tensor:
    """Reverse all-to-all to return expert outputs to originating ranks."""
    send_counts = routing_info["recv_counts"]  # now we send back what we received
    recv_counts = routing_info["send_counts"]
    sort_idx = routing_info["sort_idx"]
    B, d = routing_info["original_shape"]

    recv_total = recv_counts.sum().item()
    recv_buffer = torch.empty(recv_total, expert_outputs.shape[-1],
                              device=expert_outputs.device,
                              dtype=expert_outputs.dtype)
    dist.all_to_all(
        list(recv_buffer.split(recv_counts.tolist())),
        list(expert_outputs.split(send_counts.tolist())),
        group=ep_group
    )

    # Unsort and apply gating weights
    out = torch.zeros(B, expert_outputs.shape[-1], device=expert_outputs.device,
                      dtype=expert_outputs.dtype)
    unsort_idx = torch.argsort(sort_idx)
    out.scatter_add_(0, (unsort_idx // gates.shape[1]).unsqueeze(-1).expand_as(recv_buffer),
                     recv_buffer * gates.view(-1, 1)[unsort_idx])
    return out

Training Stability Choices

Training 671B parameters on 14.8T tokens requires careful stability engineering. DeepSeek-V3's key choices [V3, §4.1-4.2]:

  • No dropout: Consistent with findings that large models trained on diverse data do not benefit from dropout.
  • Gradient clipping at 1.0 with warmup learning rate schedule (2000 steps, cosine decay to 10% of peak).
  • Auxiliary loss weight tuning: Load balancing loss coefficient α=0.001, carefully tuned to prevent expert collapse without degrading task loss.
  • Loss spike recovery: One documented instability at ~4T tokens required rollback and restart with reduced LR; full training had zero data corruption events [V3, §4.2].

Tokenizer Design

DeepSeek uses a custom BPE tokenizer trained on a representative corpus sample [V2, §3.1]:

  • Vocabulary size: 102,400 tokens — larger than LLaMA-2 (32K) to improve Chinese/code coverage.
  • Byte-level fallback: All bytes representable, ensuring no OOV tokens for any UTF-8 input.
  • Pre-tokenization: Digits split individually (each digit = separate token) for improved arithmetic generalization — a technique also used in GPT-4 and LLaMA-3.
  • No whitespace merging across sentences for Chinese text (no natural word boundaries).
Python — Data quality filter (simplified pipeline stage)
import re
import hashlib
from dataclasses import dataclass
from typing import Optional

@dataclass
class DocumentFilter:
    """
    Heuristic quality filter approximating DeepSeek's pipeline [V3, §2.4].
    Applied per-document before MinHash deduplication.
    """
    min_chars: int = 200
    max_chars: int = 100_000
    min_mean_word_len: float = 3.0
    max_mean_word_len: float = 10.0
    max_symbol_ratio: float = 0.1    # fraction of non-alphanumeric chars
    max_repeated_line_ratio: float = 0.3

    # PII patterns
    _EMAIL_RE = re.compile(r'\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}\b')
    _PHONE_RE = re.compile(r'\b\d{3}[-.\s]?\d{3}[-.\s]?\d{4}\b')

    def filter(self, text: str) -> Optional[str]:
        """Returns cleaned text if document passes filters, else None."""
        if not (self.min_chars <= len(text) <= self.max_chars):
            return None

        words = text.split()
        if not words:
            return None

        mean_word_len = sum(len(w) for w in words) / len(words)
        if not (self.min_mean_word_len <= mean_word_len <= self.max_mean_word_len):
            return None

        symbol_ratio = sum(1 for c in text if not c.isalnum() and not c.isspace()) / len(text)
        if symbol_ratio > self.max_symbol_ratio:
            return None

        lines = text.splitlines()
        if len(lines) > 10:
            unique_lines = len(set(lines))
            if 1 - unique_lines / len(lines) > self.max_repeated_line_ratio:
                return None  # boilerplate / repeated content

        # PII removal (replace, not discard)
        text = self._EMAIL_RE.sub('[EMAIL]', text)
        text = self._PHONE_RE.sub('[PHONE]', text)

        return text

    @staticmethod
    def minhash_signature(text: str, num_hashes: int = 128) -> list[int]:
        """
        Simplified MinHash for fuzzy dedup (13-gram shingles).
        Real implementation uses datasketch or custom C++ for scale.
        """
        shingles = set()
        tokens = text.lower().split()
        for i in range(len(tokens) - 12):
            shingle = ' '.join(tokens[i:i+13])
            shingles.add(shingle.encode())

        signature = []
        for seed in range(num_hashes):
            min_hash = float('inf')
            for s in shingles:
                h = int(hashlib.md5(s + seed.to_bytes(4, 'little')).hexdigest(), 16)
                min_hash = min(min_hash, h)
            signature.append(min_hash)
        return signature

Key Takeaways

MoE + Shared Experts

Fine-grained MoE with always-active shared experts separates universal from specialized knowledge, dramatically improving parameter efficiency over standard sparse MoE. V2's 236B parameters at 21B active cost = 3× a dense 7B model's FLOPs for 33× the capacity.

MLA: 32× KV Cache Reduction

Multi-head Latent Attention compresses KV cache into 512-dim latents vs. 16,384-dim full K/V, enabling long-context inference on commodity hardware without quantization tricks.

DualPipe + FP8 = <1% Bubble

Bidirectional pipeline with computation-communication overlap effectively eliminates pipeline bubbles. Combined with FP8 training (2× memory, 2× compute over BF16), MFU reaches ~38.6% on H800 clusters.

Multi-Token Prediction: Free Speedup

MTP auxiliary heads add <5% training compute overhead but provide 1.8× inference speedup via built-in speculative decoding — a rare case where a training regularizer directly translates to deployment efficiency.

Constraint-Driven Innovation

H800 export restrictions (halved NVLink bandwidth) forced node-constrained routing (max M=4 nodes per token) and aggressive IB/NVLink overlap — solutions that would benefit any large MoE deployment, not just export-restricted setups.

Data Quality Over Quantity

14.8T tokens with aggressive MinHash deduplication and heuristic + ML quality filtering outperforms naively larger corpora. Per-digit tokenization and 100K vocab provide meaningful code and math improvements at negligible cost.
