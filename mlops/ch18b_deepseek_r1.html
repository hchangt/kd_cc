1. DeepSeek-R1 — Reasoning with RL

Source: DeepSeek-R1 paper, arXiv:2501.12948

The Reasoning Model Paradigm

DeepSeek-R1 introduced a new training paradigm: rather than teaching reasoning through supervised imitation of chain-of-thought examples, the model is trained via reinforcement learning to discover reasoning strategies. The key insight is that reasoning capability can emerge spontaneously when the model is rewarded for correct answers, without explicit reasoning supervision. This mirrors how humans develop reasoning — through trial, error, and feedback — rather than mimicry.

The paper distinguishes two key models: DeepSeek-R1-Zero, trained purely with RL on DeepSeek-V3-Base with no SFT cold-start, and DeepSeek-R1, which uses a carefully designed pipeline combining cold-start SFT data, RL, and rejection sampling to reach production quality.

GRPO: Group Relative Policy Optimization

Standard PPO requires a separate critic (value) network. For LLMs this doubles memory and compute cost. DeepSeek-R1 uses GRPO (Group Relative Policy Optimization), introduced in DeepSeek-Math (2024), which eliminates the critic by estimating the baseline from a group of sampled outputs for the same prompt.

For a prompt q, GRPO samples a group of G outputs {o1...oG} and computes relative rewards. The policy gradient objective is:

J_GRPO(θ) = E[Σ_i (r_i − mean(r)) / std(r) · log π_θ(o_i | q)] − β · KL[π_θ || π_ref]

Where r_i is the reward for output i, the mean and std are computed over the group, and the KL term keeps the policy close to a frozen reference model. No critic network needed — the group average serves as the baseline.

Cold Start Problem and Solution

DeepSeek-R1-Zero (pure RL from base) achieves strong benchmark scores but produces outputs that are hard to read — mixed languages, no clear structure, occasionally incoherent reasoning chains. This is the cold-start problem: RL on a base model without any format guidance produces capable but undeployable models.

Solution: Stage 1 uses a small set (~thousands) of curated long-CoT examples with explicit <think>...</think> tags to teach format before RL begins. This cold-start SFT dramatically improves readability and RL convergence speed without sacrificing the emergent reasoning properties.

Thinking Tokens and Chain-of-Thought Emergence

A striking result from DeepSeek-R1-Zero: when trained purely with RL and accuracy rewards, the model spontaneously develops behaviors including self-verification ("Wait, let me reconsider..."), backtracking, and extended exploration — without ever being shown examples of these patterns. The model also learns to allocate more thinking tokens to harder problems. Average thinking length scales with problem difficulty, mirroring human behavior.

The paper calls this an "aha moment" in training — a phase transition where the model shifts from short, direct answers to long deliberative reasoning. This emergence happens because the reward model only checks the final answer, so extended reasoning is instrumentally rewarded.

GRPO Loss Implementation

import torch
import torch.nn.functional as F

def grpo_loss(
    log_probs_new: torch.Tensor,   # [G, seq_len] current policy log probs
    log_probs_old: torch.Tensor,   # [G, seq_len] reference policy log probs
    rewards: torch.Tensor,         # [G] scalar reward per output
    kl_coeff: float = 0.04,
    clip_eps: float = 0.2,
) -> torch.Tensor:
    """
    Group Relative Policy Optimization loss.
    From DeepSeek-R1 paper (arXiv:2501.12948), Section 3.1.

    Args:
        log_probs_new: log probabilities under current policy π_θ
        log_probs_old: log probabilities under reference policy π_ref
        rewards: scalar reward for each of G sampled outputs
        kl_coeff: β in the paper, KL penalty coefficient
        clip_eps: PPO-style probability ratio clip range
    """
    G = rewards.shape[0]

    # Normalize rewards within the group (group-relative baseline)
    reward_mean = rewards.mean()
    reward_std  = rewards.std() + 1e-8
    advantages  = (rewards - reward_mean) / reward_std  # [G]

    # Token-level probability ratio (PPO-style clipping)
    ratio = (log_probs_new - log_probs_old).exp()       # [G, seq_len]
    adv   = advantages.unsqueeze(1).expand_as(ratio)    # [G, seq_len]

    surr1 = ratio * adv
    surr2 = ratio.clamp(1 - clip_eps, 1 + clip_eps) * adv
    policy_loss = -torch.min(surr1, surr2).mean()

    # KL divergence penalty (keep policy near reference)
    # Approximated as: r - 1 - log(r) per token
    r = ratio.detach()
    kl_approx = (r - 1 - r.log()).mean()

    return policy_loss + kl_coeff * kl_approx


# Reward functions used in R1 (rule-based, no reward model needed)
def accuracy_reward(prediction: str, ground_truth: str) -> float:
    """Binary reward: 1.0 if final answer matches, 0.0 otherwise."""
    # Extract answer from ... tags
    import re
    match = re.search(r'<answer>(.*?)</answer>', prediction, re.DOTALL)
    if not match:
        return 0.0
    pred_answer = match.group(1).strip()
    return 1.0 if pred_answer == ground_truth.strip() else 0.0


def format_reward(prediction: str) -> float:
    """Reward proper use of <think> and <answer> tags."""
    import re
    has_think  = bool(re.search(r'<think>.*?</think>', prediction, re.DOTALL))
    has_answer = bool(re.search(r'<answer>.*?</answer>', prediction, re.DOTALL))
    return 0.5 * int(has_think) + 0.5 * int(has_answer)

2. Distillation from R1

Source: DeepSeek-R1 paper, Section 4

DeepSeek-R1 serves as a teacher to distill reasoning capability into much smaller models (1.5B–70B parameters). The distillation strategy is straightforward: use R1 to generate long-CoT training data via rejection sampling, then fine-tune open-source base models (Qwen2.5, Llama-3) on this data. No RL required for the student models — the teacher's reasoning traces are sufficient.

Key finding from the paper: Distilled small models significantly outperform models trained with RL directly from the same small base. RL is expensive and unstable at small scale; distillation from a large reasoning teacher is far more sample-efficient.

Distillation Training Setup

from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from trl import SFTTrainer
from datasets import load_dataset

# Distillation: fine-tune small model on R1-generated reasoning traces
# No RL needed — supervised fine-tuning on teacher outputs is sufficient.

def prepare_distillation_dataset(teacher_outputs_path: str):
    """
    Load rejection-sampled outputs from DeepSeek-R1 teacher.
    Format: {"prompt": "...", "response": "<think>...</think><answer>...</answer>"}
    Only keep samples where the final answer is verifiably correct.
    """
    dataset = load_dataset("json", data_files=teacher_outputs_path)
    # Filter: keep only correct solutions (rejection sampling)
    dataset = dataset.filter(lambda x: x["is_correct"] == True)
    return dataset["train"]


def train_distilled_model(
    student_model_id: str = "Qwen/Qwen2.5-7B",
    distill_data_path: str = "./r1_reasoning_traces.jsonl",
    output_dir: str = "./r1-distill-qwen-7b",
):
    model = AutoModelForCausalLM.from_pretrained(
        student_model_id, torch_dtype="bfloat16", device_map="auto"
    )
    tokenizer = AutoTokenizer.from_pretrained(student_model_id)

    dataset = prepare_distillation_dataset(distill_data_path)

    training_args = TrainingArguments(
        output_dir=output_dir,
        num_train_epochs=3,
        per_device_train_batch_size=2,
        gradient_accumulation_steps=8,       # effective batch = 16
        learning_rate=1e-5,                  # lower LR preserves base capabilities
        lr_scheduler_type="cosine",
        warmup_ratio=0.05,
        bf16=True,
        logging_steps=50,
        save_strategy="epoch",
        # Long sequences needed for chain-of-thought
        max_seq_length=16384,
    )

    trainer = SFTTrainer(
        model=model,
        tokenizer=tokenizer,
        train_dataset=dataset,
        dataset_text_field="text",           # pre-formatted prompt+response
        args=training_args,
    )
    trainer.train()
    trainer.save_model(output_dir)
When distilled models beat same-size RL models: At <14B parameters, training with RL directly is unstable — reward hacking, mode collapse, and slow convergence dominate. Distillation from R1 consistently produces better benchmarks scores at 7B and 14B than running GRPO on the same base. The paper recommends RL only for models >32B.

3. Cost Analysis

Source: DeepSeek-V3 Technical Report, arXiv:2412.19437, Section 2.5

Caveat: The $5.5M figure covers only pre-training GPU costs at prevailing cloud rental rates. It excludes: engineering salaries, prior research (V1/V2), evaluation infrastructure, post-training (SFT/RLHF for V3), and hardware amortization for owned clusters. H800 vs H100 Performance Delta

The US export controls (October 2022, October 2023) restrict H100 sales to China; DeepSeek trained on H800 GPUs, which have NVLink bandwidth reduced from 900 GB/s to 400 GB/s and reduced FP8 throughput. For dense Transformer models this is a ~15–20% throughput penalty for comparable parameter counts. For MoE models, the penalty was more severe because all-to-all expert routing is communication-bound.

This constraint directly motivated DualPipe (covered in Ch18A) and the aggressive use of FP8 training — both specifically designed to work around reduced NVLink bandwidth. The hardware constraint became an algorithmic forcing function.

4. Inference Efficiency

Source: DeepSeek-V3 Technical Report, arXiv:2412.19437, Section 3

Prefill/Decode Separation for MoE

DeepSeek-V3's inference architecture separates prefill (processing the input prompt) and decode (generating tokens autoregressively) onto different node pools. Prefill is compute-bound and benefits from large batches; decode is memory-bandwidth-bound and benefits from high GPU memory. Separating these workloads allows each pool to be optimized independently — a key production engineering insight.

Expert Routing at Inference

DeepSeek-V3 uses top-K=8 expert selection from 256 routed experts (plus 1 shared expert per layer). At inference, expert activations can be precomputed and cached across requests. The paper reports that expert load is naturally balanced without auxiliary loss — the token-choice routing with sigmoid gating (replacing softmax) converges to more uniform expert utilization during training, reducing inference-time load imbalance.

Quantization

FP8 quantization (used during training) translates directly to inference. The paper uses a block-wise FP8 scheme with separate scaling factors per 128-token block, preserving accuracy within 0.1% on most benchmarks while halving memory footprint and doubling throughput versus BF16. At inference, GPTQ W4A16 (4-bit weights, 16-bit activations) is commonly used for further compression.

5. Lessons for MLOps Engineers

Synthesized from DeepSeek-V3 and R1 papers

L1

Architecture Innovation Can Beat Raw Compute

MLA (Multi-head Latent Attention) reduces KV cache memory by 93% vs standard MHA. MoE activates only 37B of 671B parameters per token. These are algorithmic wins that compound — a smaller memory footprint means larger batches, faster iteration, and lower cost, regardless of hardware budget. The V3 training efficiency gap vs GPT-4 estimates is primarily architectural, not just hardware pricing.

L2

Hardware Constraints Drive Algorithmic Creativity

Restricted to H800 GPUs (reduced NVLink bandwidth), DeepSeek invented DualPipe and optimized all-to-all communication to hide latency behind computation. Constraint-driven engineering produced techniques that benefit the entire field. When your team faces GPU limits, treat them as design constraints — not blockers.

L3

MoE Is Now Viable for Production

Prior MoE models (GShard, Switch Transformer) had training instability and load balancing issues. DeepSeek-V3 demonstrates that with auxiliary-loss-free load balancing and modern frameworks, MoE trains stably and serves efficiently. If you're planning a custom model at 7B+ parameters, MoE should be the default consideration — not an advanced option.

L4

RL for Reasoning Is a New Paradigm (Not Just RLHF)

RLHF aligns tone and safety. GRPO in R1 teaches how to think. The key differences: reward is rule-based (answer correctness), no reward model needed, and the emergent behaviors (self-verification, backtracking) were not explicitly programmed. For domains with verifiable correctness — math, code, science QA, structured data extraction — this approach is directly applicable to your team's models.

L5

Open Weights Enable Rapid Ecosystem Growth

Within two weeks of R1 release, the community had: GGUF quantizations for local inference, Ollama integration, fine-tuned variants for specific domains, and GRPO training frameworks (TRL, LlamaFactory). MIT license means commercial use is permitted. Open weights with open methodology (the technical report) allows the field to build on, verify, and extend the work — something closed APIs cannot provide.

6. Applying DeepSeek Insights to Your Team

Practical adoption paths for teams without frontier-scale resources

MoE at Smaller Scale with Mixtral 8x7B

You don't need 671B parameters to benefit from MoE. Mixtral 8x7B (56B parameters, 13B active) is the most accessible entry point. It outperforms Llama 2 70B on most benchmarks while being faster at inference due to sparse activation. Running it with vLLM provides a production-ready DeepSeek-inspired MoE deployment.

from vllm import LLM, SamplingParams
import os

# Mixtral 8x7B — MoE deployment inspired by DeepSeek patterns
# Demonstrates sparse expert routing at accessible scale
# Requires: ~90GB GPU RAM (2x A100-80GB or 4x A40-48GB)

def deploy_mixtral_moe(
    tensor_parallel_size: int = 2,
    max_model_len: int = 32768,
):
    """
    Deploy Mixtral 8x7B as a DeepSeek-inspired MoE serving stack.
    Applies: prefill/decode batching, FP8-equivalent (AWQ), expert parallelism.
    """
    llm = LLM(
        model="mistralai/Mixtral-8x7B-Instruct-v0.1",
        tensor_parallel_size=tensor_parallel_size,
        max_model_len=max_model_len,
        # AWQ 4-bit quantization — reduces to ~25GB, fits 2x A100-40GB
        quantization="awq",
        gpu_memory_utilization=0.90,
        # Chunked prefill handles long prompts efficiently
        enable_chunked_prefill=True,
        max_num_batched_tokens=4096,
        # Swap KV blocks to CPU for larger effective context
        swap_space=4,  # GB
    )
    return llm


def run_domain_reasoning(llm: LLM, prompt: str, domain: str = "medical") -> str:
    """
    Apply R1-style reasoning prompt for domain-specific tasks.
    Works with any instruction-tuned model, not just R1.
    """
    system_prompt = (
        f"You are an expert {domain} reasoning assistant. "
        "Think step by step before giving your final answer. "
        "Use <think> tags for your reasoning process."
    )
    full_prompt = f"[INST] {system_prompt}\n\n{prompt} [/INST]"

    params = SamplingParams(
        temperature=0.6,
        top_p=0.9,
        max_tokens=4096,
    )
    outputs = llm.generate([full_prompt], params)
    return outputs[0].outputs[0].text


# GRPO fine-tuning for domain reasoning (using TRL)
# Apply this after deploying Mixtral to add reasoning capability
def setup_grpo_domain_training(
    base_model: str = "mistralai/Mixtral-8x7B-v0.1",
    domain_reward_fn=None,
):
    """
    Apply GRPO to add domain reasoning to any base model.
    domain_reward_fn: callable(response, ground_truth) -> float
    Example domains: clinical coding (ICD-10 accuracy), SQL generation,
    legal document analysis, molecule property prediction.
    """
    from trl import GRPOConfig, GRPOTrainer

    config = GRPOConfig(
        model_name=base_model,
        learning_rate=5e-7,
        num_train_epochs=1,
        per_device_train_batch_size=1,
        gradient_accumulation_steps=16,
        num_generations=8,       # G in GRPO: sample 8 outputs per prompt
        max_new_tokens=2048,
        temperature=0.9,         # high temperature during training for exploration
        kl_coeff=0.04,           # β: KL penalty (from R1 paper)
        bf16=True,
        output_dir="./grpo-domain-model",
    )
    # Pass domain_reward_fn as reward_funcs to GRPOTrainer
    return config

7. The Broader Impact

Context and future directions

Open Source LLM Ecosystem Acceleration

DeepSeek-R1's release (January 2025) demonstrated that open-weight reasoning models can match closed frontier models. Within 30 days: llama.cpp added R1-GGUF support, Ollama shipped R1 integration, HuggingFace saw record downloads, and multiple companies announced R1-distilled domain models. The MIT license removes legal barriers that prevented enterprise adoption of earlier open models.

The broader pattern: when a Chinese AI lab publishes a technical report with sufficient detail to reproduce results, the open-source community can iterate in days. DeepSeek-R1 proved that GRPO works; within weeks, TRL and LlamaFactory added GRPO support, and dozens of domain-specific reasoning models appeared. This ecosystem flywheel accelerates faster with each frontier open-weight release.

Chinese AI Lab Contributions to Global Research

DeepSeek, Zhipu, Qwen (Alibaba), and Kimi (Moonshot AI) have published some of the highest-impact LLM papers of 2024-2025. These labs operate under different hardware and resource constraints than US labs, which produces genuinely different algorithmic approaches. The export control-driven hardware gap has inadvertently produced algorithmic diversity that benefits the global research community.

Future Directions

  • Smaller reasoning models: R1-1.5B already shows strong math performance. 500M reasoning-capable models for edge deployment are plausible.
  • Multimodal RL: Extending GRPO to vision-language tasks with verifiable rewards (e.g., geometry problems with diagrams).
  • Process reward models: Current R1 uses outcome rewards only. Process-level rewards (verify each reasoning step) may further improve accuracy and reduce reward hacking.
  • Test-time compute scaling: R1 demonstrated that more thinking tokens improve accuracy. Adaptive compute allocation — spending more tokens on hard problems — is an active research direction.
  • MoE at sub-7B scale: Applying MoE architecture to 1B-3B models for edge/mobile deployment with negligible active parameter cost.

  • Cold-start SFT is required before RL for format stability
  • Distillation outperforms direct RL at <14B — use the right tool
  • $5.5M training cost vs ~$100M GPT-4 est. — algorithmic efficiency wins

Inference & Cost

  • Prefill/decode separation is essential for MoE serving
  • R1 API: $0.55/$2.19 per M tokens — 7-30x cheaper than closed models
  • Self-hosted R1 on 8xH100: ~$5.60/M output tokens
  • Thinking tokens are expensive — budget them by task complexity

For Your Team

  • Use Mixtral 8x7B as your MoE entry point today
  • Apply GRPO for any domain with verifiable correct answers
  • Distill from R1 for domain tasks — don't train reasoning from scratch
  • Hardware constraints are design inputs — treat them as such
  • Open weights + MIT license = production-legal frontier capabilities
