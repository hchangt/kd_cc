1. CI/CD for ML — Overview

Why CI/CD for ML Differs from Software CI/CD

Traditional software CI/CD validates code correctness through unit and integration tests. ML systems have an additional dimension: data and model quality. A pipeline can pass all code tests yet produce a statistically degraded model if training data drifts. This creates three categories of change that each demand their own validation gate:

Code Changes

Feature engineering, model architecture, training logic — validated by unit/integration tests and linting.

Data Changes

Schema changes, distribution shifts, new data sources — validated by data contracts and statistical tests.

Model Changes

Hyperparameter updates, architecture changes — validated by evaluation metrics and behavioral tests against champion model.

Key Insight: In software CI/CD, a green build means the code is correct. In ML CI/CD, a green build means the code is correct and the resulting model meets quality thresholds on current data. These are entirely separate concerns.

The Three ML Pipelines

Google's ML engineering team established a useful taxonomy with three distinct automated pipelines, each triggered independently:

PipelineTriggerValidatesOutput
Data PipelineNew raw data arrives / scheduleSchema, statistics, completenessValidated feature set / dataset version
Training PipelineData change, code PR, scheduleModel metrics vs baselineCandidate model artifact + metadata
Deployment PipelineCandidate model passes quality gateServing performance, A/B testLive production endpoint

Continuous Training vs Continuous Delivery

Continuous Training (CT) means automatically retraining models on a schedule or when data changes, producing new candidate artifacts. Continuous Delivery (CD) means automatically deploying those candidates once they pass quality gates. Many teams implement CT without CD — they retrain automatically but require human approval before deployment. Full CT+CD is the gold standard but requires extremely mature quality gates.

2. Kubeflow Pipelines (KFP)

KFP v2 SDK Architecture

Kubeflow Pipelines v2 represents a major redesign over v1. Pipelines are compiled to an IR YAML (Intermediate Representation) based on the ML Metadata spec and executed by the KFP backend on Kubernetes. The v2 SDK introduces first-class artifact typing, eliminating the string-passing anti-pattern of v1.

Components vs Pipelines

A component is the atomic unit: a Python function decorated with @component that runs in its own container. A pipeline wires components together, passing artifacts as typed inputs and outputs. Components can be reused across pipelines and versioned independently.

Code: KFP Component Definition

from kfp import dsl
from kfp.dsl import Dataset, Model, Metrics, Input, Output

# ── Component 1: data ingestion ──────────────────────────────────────────────
@dsl.component(
    base_image="python:3.11-slim",
    packages_to_install=["pandas==2.1.4", "scikit-learn==1.4.0", "pyarrow==14.0.1"],
)
def ingest_data(
    dataset_uri: str,
    output_dataset: Output[Dataset],
    test_size: float = 0.2,
    random_state: int = 42,
) -> None:
    """Download raw data, split train/test, persist as parquet."""
    import pandas as pd
    from sklearn.model_selection import train_test_split
    import json, pathlib

    df = pd.read_parquet(dataset_uri)
    train, test = train_test_split(df, test_size=test_size, random_state=random_state)

    pathlib.Path(output_dataset.path).mkdir(parents=True, exist_ok=True)
    train.to_parquet(f"{output_dataset.path}/train.parquet", index=False)
    test.to_parquet(f"{output_dataset.path}/test.parquet",  index=False)

    output_dataset.metadata["n_train"] = len(train)
    output_dataset.metadata["n_test"]  = len(test)
    output_dataset.metadata["features"] = json.dumps(list(df.columns))


# ── Component 2: feature engineering ────────────────────────────────────────
@dsl.component(
    base_image="python:3.11-slim",
    packages_to_install=["pandas==2.1.4", "scikit-learn==1.4.0", "pyarrow==14.0.1"],
)
def build_features(
    raw_dataset: Input[Dataset],
    feature_dataset: Output[Dataset],
    target_col: str = "label",
) -> None:
    import pandas as pd
    from sklearn.preprocessing import StandardScaler
    import pickle, pathlib

    train = pd.read_parquet(f"{raw_dataset.path}/train.parquet")
    test  = pd.read_parquet(f"{raw_dataset.path}/test.parquet")

    numeric_cols = train.select_dtypes("number").columns.drop(target_col, errors="ignore")
    scaler = StandardScaler()
    train[numeric_cols] = scaler.fit_transform(train[numeric_cols])
    test[numeric_cols]  = scaler.transform(test[numeric_cols])

    pathlib.Path(feature_dataset.path).mkdir(parents=True, exist_ok=True)
    train.to_parquet(f"{feature_dataset.path}/train.parquet", index=False)
    test.to_parquet(f"{feature_dataset.path}/test.parquet",  index=False)

    # Save scaler as part of the artifact
    with open(f"{feature_dataset.path}/scaler.pkl", "wb") as f:
        pickle.dump(scaler, f)

Code: Training + Evaluation Components

@dsl.component(
    base_image="python:3.11-slim",
    packages_to_install=["pandas==2.1.4", "scikit-learn==1.4.0",
                         "xgboost==2.0.3", "pyarrow==14.0.1"],
)
def train_model(
    feature_dataset: Input[Dataset],
    model_artifact: Output[Model],
    n_estimators: int = 300,
    max_depth: int = 6,
    learning_rate: float = 0.05,
    target_col: str = "label",
) -> None:
    import pandas as pd, xgboost as xgb, pickle, pathlib, json

    train = pd.read_parquet(f"{feature_dataset.path}/train.parquet")
    X = train.drop(columns=[target_col])
    y = train[target_col]

    clf = xgb.XGBClassifier(
        n_estimators=n_estimators,
        max_depth=max_depth,
        learning_rate=learning_rate,
        use_label_encoder=False,
        eval_metric="logloss",
        random_state=42,
    )
    clf.fit(X, y, eval_set=[(X, y)], verbose=False)

    pathlib.Path(model_artifact.path).mkdir(parents=True, exist_ok=True)
    with open(f"{model_artifact.path}/model.pkl", "wb") as f:
        pickle.dump(clf, f)

    model_artifact.metadata["framework"]   = "xgboost"
    model_artifact.metadata["version"]     = xgb.__version__
    model_artifact.metadata["hyperparams"] = json.dumps(
        {"n_estimators": n_estimators, "max_depth": max_depth, "lr": learning_rate}
    )


@dsl.component(
    base_image="python:3.11-slim",
    packages_to_install=["pandas==2.1.4", "scikit-learn==1.4.0",
                         "xgboost==2.0.3", "pyarrow==14.0.1"],
)
def evaluate_model(
    feature_dataset: Input[Dataset],
    model_artifact: Input[Model],
    metrics: Output[Metrics],
    target_col: str = "label",
    min_accuracy: float = 0.85,
) -> bool:
    import pandas as pd, pickle
    from sklearn.metrics import accuracy_score, roc_auc_score, f1_score

    test = pd.read_parquet(f"{feature_dataset.path}/test.parquet")
    X    = test.drop(columns=[target_col])
    y    = test[target_col]

    with open(f"{model_artifact.path}/model.pkl", "rb") as f:
        clf = pickle.load(f)

    preds      = clf.predict(X)
    pred_proba = clf.predict_proba(X)[:, 1]

    accuracy = accuracy_score(y, preds)
    auc      = roc_auc_score(y, pred_proba)
    f1       = f1_score(y, preds)

    metrics.log_metric("accuracy", round(accuracy, 4))
    metrics.log_metric("roc_auc",  round(auc, 4))
    metrics.log_metric("f1_score", round(f1, 4))

    print(f"Accuracy: {accuracy:.4f}  AUC: {auc:.4f}  F1: {f1:.4f}")

    if accuracy < min_accuracy:
        raise ValueError(f"Model accuracy {accuracy:.4f} below threshold {min_accuracy}")

    return accuracy >= min_accuracy

Code: Complete KFP Pipeline Wiring

from kfp import dsl, compiler

@dsl.pipeline(
    name="xgboost-training-pipeline",
    description="End-to-end training pipeline: ingest → features → train → evaluate → push",
)
def ml_training_pipeline(
    dataset_uri: str = "gs://my-bucket/data/raw/dataset.parquet",
    target_col:  str  = "label",
    min_accuracy: float = 0.85,
    n_estimators: int   = 300,
    max_depth:    int   = 6,
    learning_rate: float = 0.05,
) -> None:

    # Step 1 — ingest
    ingest_task = ingest_data(
        dataset_uri=dataset_uri,
    )
    ingest_task.set_caching_options(enable_caching=True)

    # Step 2 — features
    feature_task = build_features(
        raw_dataset=ingest_task.outputs["output_dataset"],
        target_col=target_col,
    )
    feature_task.set_cpu_limit("2").set_memory_limit("4G")

    # Step 3 — train  (GPU node)
    train_task = train_model(
        feature_dataset=feature_task.outputs["feature_dataset"],
        n_estimators=n_estimators,
        max_depth=max_depth,
        learning_rate=learning_rate,
        target_col=target_col,
    )
    train_task.set_cpu_limit("4").set_memory_limit("8G")
    train_task.set_accelerator_type("NVIDIA_TESLA_T4").set_accelerator_limit(1)

    # Step 4 — evaluate
    eval_task = evaluate_model(
        feature_dataset=feature_task.outputs["feature_dataset"],
        model_artifact=train_task.outputs["model_artifact"],
        target_col=target_col,
        min_accuracy=min_accuracy,
    )

    # Step 5 — conditionally push to registry
    with dsl.If(eval_task.output == True, name="quality-gate-passed"):
        push_task = push_to_registry(
            model_artifact=train_task.outputs["model_artifact"],
            metrics=eval_task.outputs["metrics"],
            model_name="xgboost-classifier",
        )


# ── Compile and submit ────────────────────────────────────────────────────────
if __name__ == "__main__":
    # Compile to IR YAML
    compiler.Compiler().compile(
        pipeline_func=ml_training_pipeline,
        package_path="pipeline.yaml",
    )

    # Submit to KFP backend (or Vertex AI)
    import google.cloud.aiplatform as aip

    aip.init(project="my-project", location="us-central1")
    job = aip.PipelineJob(
        display_name="xgboost-training-pipeline",
        template_path="pipeline.yaml",
        parameter_values={
            "dataset_uri":    "gs://my-bucket/data/raw/dataset.parquet",
            "min_accuracy":   0.85,
            "n_estimators":   300,
        },
        enable_caching=True,
    )
    job.run(sync=True)

KFP on Vertex AI (Managed)

Google Cloud's Vertex AI Pipelines is a fully managed KFP backend. You compile the same pipeline YAML and submit via the Vertex AI SDK. Benefits: no Kubernetes to manage, automatic scaling, tight integration with Vertex Model Registry, Vertex Experiments, and Vertex Feature Store.

Best Practice: Enable component-level caching on stable upstream steps (ingestion, feature engineering). KFP caches by hashing inputs; if the same raw data arrives, it skips re-ingestion entirely. This can cut pipeline cost by 40–60% for frequent retraining.

Reusable Component Libraries

Package components as Python packages and publish to your internal PyPI. Teams share components like mlops-components==1.3.0 and reference them in pipelines. This standardizes data loading, evaluation, and push-to-registry steps across all models in the organization.

3. Metaflow (Netflix)

Philosophy: Data Scientist-First

Metaflow was born from Netflix's realization that data scientists should not need to learn Kubernetes, YAML, or distributed systems to run production workflows. A Metaflow flow is just a Python class — you run it locally first, then add a single decorator to burst to AWS Batch or AWS Step Functions without changing the logic.

Steps, Flows, Artifacts

A flow is a DAG of steps. Each step is a method decorated with @step. Artifacts are instance attributes assigned inside steps — Metaflow automatically versions and persists them to S3 (or local). Any downstream step in any future run can resume from a checkpoint or get_metadata on past runs.

Code: Metaflow Training Flow

from metaflow import FlowSpec, step, Parameter, card, current
from metaflow.cards import Markdown, Table

class XGBoostTrainingFlow(FlowSpec):
    """End-to-end XGBoost training flow with evaluation and model registration."""

    data_path   = Parameter("data_path",   default="s3://my-bucket/data/raw/dataset.parquet")
    target_col  = Parameter("target_col",  default="label")
    n_estimators = Parameter("n_estimators", default=300)
    max_depth   = Parameter("max_depth",   default=6)
    lr          = Parameter("lr",          default=0.05)
    min_acc     = Parameter("min_acc",     default=0.85)
    test_size   = Parameter("test_size",   default=0.2)

    @step
    def start(self):
        """Load and validate raw data."""
        import pandas as pd
        self.df = pd.read_parquet(self.data_path)
        print(f"Loaded {len(self.df):,} rows, {self.df.shape[1]} columns")
        assert self.target_col in self.df.columns, f"Missing target: {self.target_col}"
        self.next(self.build_features)

    @step
    def build_features(self):
        """Feature engineering: scale numerics, encode categoricals."""
        import pandas as pd
        from sklearn.model_selection import train_test_split
        from sklearn.preprocessing import StandardScaler

        df = self.df
        X  = df.drop(columns=[self.target_col])
        y  = df[self.target_col]

        X_train, X_test, y_train, y_test = train_test_split(
            X, y, test_size=self.test_size, random_state=42, stratify=y
        )

        scaler = StandardScaler()
        num_cols = X_train.select_dtypes("number").columns
        X_train[num_cols] = scaler.fit_transform(X_train[num_cols])
        X_test[num_cols]  = scaler.transform(X_test[num_cols])

        # Artifacts are auto-persisted by Metaflow
        self.X_train, self.X_test = X_train, X_test
        self.y_train, self.y_test = y_train, y_test
        self.scaler = scaler
        self.next(self.train)

    @step
    def train(self):
        """Train XGBoost classifier."""
        import xgboost as xgb

        self.model = xgb.XGBClassifier(
            n_estimators=self.n_estimators,
            max_depth=self.max_depth,
            learning_rate=self.lr,
            use_label_encoder=False,
            eval_metric="logloss",
            random_state=42,
        )
        self.model.fit(
            self.X_train, self.y_train,
            eval_set=[(self.X_test, self.y_test)],
            verbose=50,
        )
        self.next(self.evaluate)

    @card
    @step
    def evaluate(self):
        """Compute metrics and build evaluation card."""
        from sklearn.metrics import (
            accuracy_score, roc_auc_score, f1_score,
            classification_report, confusion_matrix,
        )
        import pandas as pd

        preds      = self.model.predict(self.X_test)
        pred_proba = self.model.predict_proba(self.X_test)[:, 1]

        self.accuracy = accuracy_score(self.y_test, preds)
        self.auc      = roc_auc_score(self.y_test, pred_proba)
        self.f1       = f1_score(self.y_test, preds)

        print(f"Accuracy={self.accuracy:.4f}  AUC={self.auc:.4f}  F1={self.f1:.4f}")
        print(classification_report(self.y_test, preds))

        self.passed_quality_gate = self.accuracy >= self.min_acc
        self.next(self.register if self.passed_quality_gate else self.end)

    @step
    def register(self):
        """Push model to MLflow model registry."""
        import mlflow, tempfile, pickle, os

        mlflow.set_tracking_uri(os.environ["MLFLOW_TRACKING_URI"])
        mlflow.set_experiment("xgboost-training")

        with mlflow.start_run(run_name=f"metaflow-{current.run_id}") as run:
            mlflow.log_params({
                "n_estimators": self.n_estimators,
                "max_depth":    self.max_depth,
                "lr":           self.lr,
            })
            mlflow.log_metrics({
                "accuracy": self.accuracy,
                "auc":      self.auc,
                "f1":       self.f1,
            })
            with tempfile.TemporaryDirectory() as tmp:
                model_path = os.path.join(tmp, "model.pkl")
                with open(model_path, "wb") as f:
                    pickle.dump(self.model, f)
                mlflow.log_artifact(model_path)

            self.mlflow_run_id = run.info.run_id
        self.next(self.end)

    @step
    def end(self):
        """Summary."""
        status = "PASSED" if self.passed_quality_gate else "FAILED quality gate"
        print(f"Flow complete. Quality gate: {status}")
        if hasattr(self, "mlflow_run_id"):
            print(f"MLflow run: {self.mlflow_run_id}")


if __name__ == "__main__":
    XGBoostTrainingFlow()

class BatchTrainingFlow(FlowSpec):

    def start(self):

4. ZenML

The Stack Concept

ZenML's key insight is the stack: a named collection of infrastructure components that a pipeline targets. Switching from local development to production means changing the active stack, not the pipeline code.

Orchestrator

Local, Airflow, Kubeflow, Vertex AI, AWS Step Functions, Databricks

Artifact Store

Local filesystem, GCS, S3, Azure Blob, MinIO

Model Registry

MLflow, Vertex AI Model Registry, SageMaker, BentoML

Code: ZenML Pipeline Definition

from zenml import pipeline, step, ArtifactConfig
from zenml.integrations.mlflow.flavors.mlflow_experiment_tracker_flavor import MLFlowExperimentTrackerSettings
from typing import Annotated, Tuple
import pandas as pd
import numpy as np

# ── Steps ──────────────────────────────────────────────────────────────────
@step
def load_data(data_path: str) -> Annotated[pd.DataFrame, ArtifactConfig(name="raw_data")]:
    return pd.read_parquet(data_path)


@step
def split_data(
    df: pd.DataFrame, test_size: float = 0.2
) -> Tuple[
    Annotated[pd.DataFrame, "X_train"],
    Annotated[pd.DataFrame, "X_test"],
    Annotated[pd.Series,    "y_train"],
    Annotated[pd.Series,    "y_test"],
]:
    from sklearn.model_selection import train_test_split
    X = df.drop("label", axis=1)
    y = df["label"]
    return train_test_split(X, y, test_size=test_size, random_state=42)


@step(experiment_tracker="mlflow_tracker")
def train_and_evaluate(
    X_train: pd.DataFrame,
    X_test: pd.DataFrame,
    y_train: pd.Series,
    y_test: pd.Series,
) -> Annotated[object, ArtifactConfig(name="trained_model", is_model_artifact=True)]:
    import mlflow
    from sklearn.ensemble import RandomForestClassifier
    from sklearn.metrics import accuracy_score

    mlflow.sklearn.autolog()

    clf = RandomForestClassifier(n_estimators=200, random_state=42)
    clf.fit(X_train, y_train)

    acc = accuracy_score(y_test, clf.predict(X_test))
    mlflow.log_metric("accuracy", acc)
    print(f"Accuracy: {acc:.4f}")

    return clf


# ── Pipeline ───────────────────────────────────────────────────────────────
@pipeline(
    name="rf-training-pipeline",
    settings={"experiment_tracker": MLFlowExperimentTrackerSettings(experiment_name="zenml-rf")},
)
def rf_training_pipeline(data_path: str = "data/dataset.parquet"):
    df = load_data(data_path)
    X_train, X_test, y_train, y_test = split_data(df)
    train_and_evaluate(X_train, X_test, y_train, y_test)


if __name__ == "__main__":
    rf_training_pipeline()

7. Model Quality Gates

What Are Quality Gates?

A quality gate is an automated checkpoint that blocks model promotion if evaluation metrics fall below defined thresholds. The crucial distinction: compare the candidate model against the current production champion, not an absolute threshold. Absolute thresholds go stale as data shifts; champion/challenger comparison adapts automatically.

Metric Categories

CategoryMetricsGate Logic
Predictive qualityAccuracy, AUC-ROC, F1, Precision@KChallenger ≥ Champion − ε (e.g., 1%)
Serving performanceP50/P95/P99 latency, throughputP99 latency ≤ SLO (e.g., 200ms)
Fairness / biasDemographic parity, equalized oddsMax group disparity ≤ threshold
CalibrationECE (Expected Calibration Error), Brier scoreECE ≤ 0.05
Model sizeArtifact size, parameter countSize ≤ max_mb
Data driftPSI, KL divergence on featuresPSI ≤ 0.2 on all features

Code: Python Quality Gate Script

#!/usr/bin/env python3
"""quality_gate.py — Champion/challenger model evaluation gate.

Exit 0: gate PASSED. Exit 1: gate FAILED (blocks CI).
"""
import argparse, json, sys
import mlflow
from mlflow.tracking import MlflowClient
import pandas as pd
from sklearn.metrics import accuracy_score, roc_auc_score, f1_score
import numpy as np


def parse_args():
    p = argparse.ArgumentParser()
    p.add_argument("--challenger-run-id", required=True)
    p.add_argument("--min-accuracy",  type=float, default=0.80)
    p.add_argument("--min-auc",       type=float, default=0.85)
    p.add_argument("--min-f1",        type=float, default=0.75)
    p.add_argument("--max-p99-latency-ms", type=float, default=200.0)
    p.add_argument("--compare-champion", action="store_true")
    p.add_argument("--model-name",    default="production-classifier")
    p.add_argument("--output-report", default="evaluation_report.json")
    p.add_argument("--max-bias-disparity", type=float, default=0.10)
    return p.parse_args()


def get_champion_metrics(client: MlflowClient, model_name: str) -> dict | None:
    """Fetch metrics from the current Production-stage model run."""
    try:
        versions = client.get_latest_versions(model_name, stages=["Production"])
        if not versions:
            print("No champion in Production stage — skipping champion comparison")
            return None
        run = client.get_run(versions[0].run_id)
        return run.data.metrics
    except Exception as e:
        print(f"Warning: could not retrieve champion metrics: {e}")
        return None


def evaluate_challenger(run_id: str, client: MlflowClient) -> dict:
    """Load challenger metrics from MLflow run."""
    run = client.get_run(run_id)
    return run.data.metrics


def check_bias(model, X_test: pd.DataFrame, y_test: pd.Series,
               sensitive_col: str, max_disparity: float) -> tuple[bool, dict]:
    """Demographic parity check across groups in sensitive_col."""
    if sensitive_col not in X_test.columns:
        return True, {}

    groups = X_test[sensitive_col].unique()
    group_accuracies = {}
    for g in groups:
        mask = X_test[sensitive_col] == g
        preds = model.predict(X_test[mask])
        group_accuracies[str(g)] = accuracy_score(y_test[mask], preds)

    disparity = max(group_accuracies.values()) - min(group_accuracies.values())
    passed = disparity <= max_disparity
    return passed, {"group_accuracies": group_accuracies, "disparity": disparity}


def main():
    args = parse_args()
    client = MlflowClient()

    print(f"=== Quality Gate: challenger run {args.challenger_run_id} ===")

    challenger = evaluate_challenger(args.challenger_run_id, client)
    champion   = get_champion_metrics(client, args.model_name) if args.compare_champion else None

    failures = []
    report   = {
        "challenger_run_id": args.challenger_run_id,
        "challenger_metrics": challenger,
        "champion_metrics":   champion,
        "gates": {},
        "passed": False,
    }

    # ── Absolute thresholds ──────────────────────────────────────────────
    def check(name, value, threshold, operator="ge"):
        ok = value >= threshold if operator == "ge" else value <= threshold
        report["gates"][name] = {
            "value": value, "threshold": threshold, "passed": ok
        }
        if not ok:
            failures.append(f"{name}: {value:.4f} {'<' if operator=='ge' else '>'} {threshold}")
        return ok

    check("accuracy", challenger.get("accuracy", 0), args.min_accuracy)
    check("roc_auc",  challenger.get("roc_auc",  0), args.min_auc)
    check("f1_score", challenger.get("f1_score",  0), args.min_f1)
    check("p99_latency_ms",
          challenger.get("p99_latency_ms", 9999),
          args.max_p99_latency_ms, operator="le")

    # ── Champion comparison (challenger must not regress > 1%) ───────────
    if champion:
        for metric in ["accuracy", "roc_auc", "f1_score"]:
            champ_val = champion.get(metric, 0)
            chal_val  = challenger.get(metric, 0)
            tolerance = 0.01  # 1% regression allowed
            name = f"{metric}_vs_champion"
            ok   = chal_val >= champ_val - tolerance
            report["gates"][name] = {
                "challenger": chal_val,
                "champion":   champ_val,
                "delta":      chal_val - champ_val,
                "passed":     ok,
            }
            if not ok:
                failures.append(
                    f"{metric} regression: challenger={chal_val:.4f} "
                    f"champion={champ_val:.4f} (delta={chal_val-champ_val:.4f})"
                )

    report["passed"] = len(failures) == 0
    report["failures"] = failures

    # ── Write report ─────────────────────────────────────────────────────
    with open(args.output_report, "w") as f:
        json.dump(report, f, indent=2)
    print(json.dumps(report, indent=2))

    if failures:
        print(f"\n[GATE FAILED] {len(failures)} check(s) failed:")
        for f in failures:
            print(f"  - {f}")
        sys.exit(1)
    else:
        print("\n[GATE PASSED] All quality checks passed")

        # Transition to Staging in model registry
        versions = client.search_model_versions(f"run_id='{args.challenger_run_id}'")
        if versions:
            client.transition_model_version_stage(
                name=args.model_name,
                version=versions[0].version,
                stage="Staging",
            )
            print(f"Model version {versions[0].version} promoted to Staging")

        sys.exit(0)


if __name__ == "__main__":
    main()

  3. Rollback workflow fetches the previous Production model version from MLflow registry

        # Assumes model was trained without name_hash — adding noise column
        # This test validates the model uses expected feature set only

          provenance: mode=max     # SLSA provenance
          sbom: true               # SBOM attestation

      # Security scan with Trivy — fail on CRITICAL or HIGH
      - name: Run Trivy vulnerability scan
        uses: aquasecurity/trivy-action@master

          image-ref:    ${{ env.ECR_REGISTRY }}/${{ env.IMAGE_NAME }}:sha-${{ github.sha }}
          format:       sarif
          output:       trivy-results.sarif
          severity:     CRITICAL,HIGH
          exit-code:    1           # Fail CI on critical vulns
          ignore-unfixed: true

        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: trivy-results.sarif

      # Generate SBOM with Syft

        uses: anchore/sbom-action@v0

          image: ${{ env.ECR_REGISTRY }}/${{ env.IMAGE_NAME }}:sha-${{ github.sha }}

        uses: actions/upload-artifact@v4
        with:
          name: sbom-${{ github.sha }}
          path: sbom.spdx.json

        run: echo "Image digest ${{ steps.build.outputs.digest }}"

Shadow Mode Deployment

In shadow mode, the new model receives a copy of all production requests but its responses are discarded (not returned to users). This allows offline validation of the new model on real production traffic distributions before any user impact. Istio's mirror policy implements this natively:

# Shadow mode: mirror all traffic to canary (responses discarded)
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: ml-serving-shadow
  namespace: ml-serving
spec:
  hosts: ["ml-serving"]
  http:
  - route:
    - destination:
        host: ml-serving-stable
        port: { number: 80 }
      weight: 100
    mirror:
      host: ml-serving-canary
      port: { number: 80 }
    mirrorPercentage:
      value: 100.0   # Mirror 100% of traffic silently

            --min-auc 0.90 \
            --min-f1 0.80 \
            --max-p99-latency-ms 200 \
            --compare-champion \
            --model-name "${{ env.MODEL_NAME }}" \
            --output-report evaluation_report.json
          EXIT_CODE=$?
          if [ $EXIT_CODE -eq 0 ]; then
            echo "gate_passed=true" >> $GITHUB_OUTPUT
          else
            echo "gate_passed=false" >> $GITHUB_OUTPUT
          fi
          exit $EXIT_CODE

      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: quality-gate-report
          path: evaluation_report.json

      - name: Notify gate result
        if: always()
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            {"channel": "${{ env.SLACK_CHANNEL }}", "text": "Quality gate: ${{ steps.gate.outputs.gate_passed == 'true' && '✅ PASSED' || '❌ FAILED' }}\nRun ID: `${{ needs.train-model.outputs.mlflow_run_id }}`"}
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

  # ══════════════════════════════════════════════════════════════
  # STAGE 6 — BUILD SERVING IMAGE
  # ══════════════════════════════════════════════════════════════
  build-serving-image:
    name: "Build Serving Image"
    runs-on: ubuntu-latest
    needs: quality-gate
    if: needs.quality-gate.outputs.gate_passed == 'true'
    outputs:
      image-uri: ${{ steps.push.outputs.image-uri }}
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ secrets.AWS_ACCOUNT_ID }}:role/GitHubMLRole
          aws-region: ${{ env.AWS_REGION }}
      - uses: aws-actions/amazon-ecr-login@v2
      - uses: docker/setup-qemu-action@v3
      - uses: docker/setup-buildx-action@v3

      - name: Build multi-arch serving image
        id: push
        run: |
          IMAGE_URI=${{ env.ECR_REGISTRY }}/ml-serving:${{ github.sha }}
          docker buildx build \
            --platform linux/amd64,linux/arm64 \
            --file docker/Dockerfile.serve \
            --build-arg MODEL_VERSION="${{ needs.train-model.outputs.model_version }}" \
            --build-arg MLFLOW_RUN_ID="${{ needs.train-model.outputs.mlflow_run_id }}" \
            --tag $IMAGE_URI \
            --push \
            .
          echo "image-uri=$IMAGE_URI" >> $GITHUB_OUTPUT

      - name: Scan serving image
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ${{ steps.push.outputs.image-uri }}
          severity: CRITICAL,HIGH
          exit-code: 1
          ignore-unfixed: true

  # ══════════════════════════════════════════════════════════════
  # STAGE 7 — DEPLOY STAGING
  # ══════════════════════════════════════════════════════════════
  deploy-staging:
    name: "Deploy → Staging"
    runs-on: ubuntu-latest
    needs: build-serving-image
    environment:
      name: staging
      url: https://staging.ml-api.company.com/health
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ secrets.AWS_ACCOUNT_ID }}:role/GitHubMLRole
          aws-region: ${{ env.AWS_REGION }}

      - name: Update kubeconfig for staging
        run: |
          aws eks update-kubeconfig \
            --name ${{ env.EKS_CLUSTER_STAGING }} \
            --region ${{ env.AWS_REGION }}

      - name: Deploy to staging
        run: |
          kubectl set image deployment/ml-serving \
            serving="${{ needs.build-serving-image.outputs.image-uri }}" \
            --namespace ml-serving
          kubectl rollout status deployment/ml-serving \
            --namespace ml-serving \
            --timeout=300s

      - name: Run integration tests
        run: |
          pip install pytest httpx
          pytest tests/integration/ \
            -v \
            --timeout=120 \
            -m "not slow"
        env:
          API_BASE_URL: https://staging.ml-api.company.com
          API_KEY: ${{ secrets.STAGING_API_KEY }}

  # ══════════════════════════════════════════════════════════════
  # STAGE 8 — CANARY DEPLOY TO PRODUCTION
  # ══════════════════════════════════════════════════════════════
  deploy-production-canary:
    name: "Deploy → Production Canary"
    runs-on: ubuntu-latest
    needs: deploy-staging
    environment:
      name: production
      url: https://ml-api.company.com/health
    steps:
      - uses: actions/checkout@v4

      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ secrets.AWS_ACCOUNT_ID }}:role/GitHubMLRole
          aws-region: ${{ env.AWS_REGION }}

      - name: Update kubeconfig for production
        run: |
          aws eks update-kubeconfig \
            --name ${{ env.EKS_CLUSTER_PROD }} \
            --region ${{ env.AWS_REGION }}

      - name: Deploy canary (${{ inputs.canary_pct || '10' }}%)
        run: |
          CANARY_PCT="${{ inputs.canary_pct || '10' }}"
          STABLE_PCT="$((100 - CANARY_PCT))"

          # Update canary deployment
          kubectl set image deployment/ml-serving-canary \
            serving="${{ needs.build-serving-image.outputs.image-uri }}" \
            --namespace ml-serving
          kubectl rollout status deployment/ml-serving-canary \
            --namespace ml-serving \
            --timeout=300s

          # Update Istio VirtualService weights
          kubectl patch virtualservice ml-serving \
            --namespace ml-serving \
            --type=merge \
            -p "{\"spec\":{\"http\":[{\"route\":[{\"destination\":{\"host\":\"ml-serving-stable\",\"port\":{\"number\":80}},\"weight\":${STABLE_PCT}},{\"destination\":{\"host\":\"ml-serving-canary\",\"port\":{\"number\":80}},\"weight\":${CANARY_PCT}}]}]}}"

      - name: Update ArgoCD / k8s manifests repo
        run: |
          git clone https://x-access-token:${{ secrets.K8S_MANIFESTS_REPO_TOKEN }}@github.com/company/ml-platform-k8s /tmp/k8s
          cd /tmp/k8s
          kustomize edit set image ml-serving-canary="${{ needs.build-serving-image.outputs.image-uri }}" \
            --kustomization deployments/ml-serving/production/kustomization.yaml
          git config user.email "ci-bot@company.com"
          git config user.name  "CI Bot"
          git add .
          git commit -m "canary: update ml-serving to ${{ github.sha }} [skip ci]"
          git push origin main

      - name: Notify production canary deploy
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            {
              "channel": "${{ env.SLACK_CHANNEL }}",
              "text": "🚀 Canary deployed to production!\nModel: `${{ needs.train-model.outputs.model_version }}`\nImage: `${{ needs.build-serving-image.outputs.image-uri }}`\nTraffic: ${{ inputs.canary_pct || '10' }}% to canary\n"
            }
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

  # ══════════════════════════════════════════════════════════════
  # STAGE 9 — PROMOTE CANARY TO 100% (after bake time)
  # ══════════════════════════════════════════════════════════════
  promote-to-stable:
    name: "Promote Canary → Stable (100%)"
    runs-on: ubuntu-latest
    needs: deploy-production-canary
    # Wait 30 minutes for bake time; manual approval gate via environment protection rule
    environment:
      name: production-promote
    steps:
      - uses: actions/checkout@v4

      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::${{ secrets.AWS_ACCOUNT_ID }}:role/GitHubMLRole
          aws-region: ${{ env.AWS_REGION }}

      - name: Check canary error rate before promotion
        run: |
          python scripts/check_canary_metrics.py \
            --prometheus-url ${{ secrets.PROMETHEUS_URL }} \
            --canary-label "track=canary" \
            --max-error-rate 0.01 \
            --window-minutes 30

      - name: Promote canary to 100%
        run: |
          aws eks update-kubeconfig \
            --name ${{ env.EKS_CLUSTER_PROD }} \
            --region ${{ env.AWS_REGION }}

          # Move stable deployment to new image
          kubectl set image deployment/ml-serving-stable \
            serving="${{ needs.build-serving-image.outputs.image-uri }}" \
            --namespace ml-serving

          # Shift all traffic back to stable (now running new model)
          kubectl patch virtualservice ml-serving \
            --namespace ml-serving \
            --type=merge \
            -p '{"spec":{"http":[{"route":[{"destination":{"host":"ml-serving-stable","port":{"number":80}},"weight":100},{"destination":{"host":"ml-serving-canary","port":{"number":80}},"weight":0}]}]}}'

      - name: Promote model in MLflow registry
        run: |
          pip install mlflow
          python -c "
          import mlflow
          client = mlflow.tracking.MlflowClient()
          versions = client.search_model_versions(\"run_id='${{ needs.train-model.outputs.mlflow_run_id }}'\")
          if versions:
              client.transition_model_version_stage(
                  name='${{ env.MODEL_NAME }}',
                  version=versions[0].version,
                  stage='Production',
                  archive_existing_versions=True,
              )
              print(f'Promoted version {versions[0].version} to Production')
          "

      - name: Final notification
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            {"channel": "${{ env.SLACK_CHANNEL }}", "text": "✅ Production promotion complete!\nModel `${{ needs.train-model.outputs.model_version }}` is now serving 100% of traffic.\nCommit: `${{ github.sha }}`"}
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

Summary & Key Takeaways

Core Principles

  • ML CI/CD gates on code quality AND data quality AND model quality simultaneously
  • Treat model artifacts like software releases: version, test, deploy with rollback
  • Champion/challenger comparison adapts to data shift better than absolute thresholds
  • Run smoke training on PRs; full training only on merge to main or schedule
  • Never deploy a model without a quality gate — even to staging

Pipeline Orchestration

  • KFP v2 for GCP / Kubernetes shops with strong artifact typing needs
  • Metaflow for data-scientist-first teams on AWS with minimal infra overhead
  • ZenML for multi-cloud portability via the stack abstraction
  • Enable component caching to avoid reprocessing unchanged data (40–60% cost savings)

CI/CD Platform

  • GitHub Actions OIDC eliminates long-lived cloud credentials entirely
  • Use repository_dispatch to trigger retraining from monitoring alerts
  • GitLab CI's native model registry is compelling for self-hosted enterprise
  • Self-hosted GPU runners for CI jobs that need actual training validation

Safety & Reliability

  • Canary deployments are mandatory for production ML — never go straight to 100%
  • Behavioral tests catch regressions that accuracy metrics miss
  • Pin Docker base images by digest, not tag — tags are mutable
  • Trivy scan on every image build — fail CI on CRITICAL CVEs
  • GitOps with ArgoCD: cluster state always matches Git, no manual kubectl in prod
The ML CI/CD Maturity Ladder

Level 0: Manual training and deployment from local machines

Level 1: Automated CI (code tests + linting) but manual training

Level 2: CT — automated retraining on schedule or data change

Level 3: CT + automated quality gates blocking bad models

Level 4: Full CT+CD — auto-deploy to canary when gate passes, auto-promote on metrics

Level 5: Self-healing — monitoring alerts auto-trigger retraining with no human intervention
