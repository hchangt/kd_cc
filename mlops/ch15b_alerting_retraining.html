1. Distributed Tracing for ML

OpenTelemetry · Jaeger · Trace propagation

Metrics tell you what broke; traces tell you where and why. An ML inference request flows through a feature store, a model server, and a post-processing layer — without traces, a 200 ms latency spike is invisible. OpenTelemetry (OTel) is the CNCF standard that instruments all three hops with a single SDK.

OTel for ML — three pillars:
  • Traces — end-to-end request latency across services
  • Metrics — counters/histograms emitted from span data
  • Logs — correlated to trace IDs for fast triage
python · otel_ml_api.py 
"""OpenTelemetry instrumentation for an ML inference API."""
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.instrumentation.fastapi import FastAPIInstrumentor
from opentelemetry.instrumentation.requests import RequestsInstrumentor
import fastapi, uvicorn, time

# --- Bootstrap ---
exporter = OTLPSpanExporter(endpoint="http://otel-collector:4317", insecure=True)
provider = TracerProvider()
provider.add_span_processor(BatchSpanProcessor(exporter))
trace.set_tracer_provider(provider)
tracer = trace.get_tracer("ml.inference")

app = fastapi.FastAPI()
FastAPIInstrumentor.instrument_app(app)   # auto-instrument HTTP layer
RequestsInstrumentor().instrument()       # auto-instrument outbound calls

@app.post("/predict")
async def predict(payload: dict):
    with tracer.start_as_current_span("inference.pipeline") as span:
        span.set_attribute("model.name", "churn-v3")
        span.set_attribute("input.features", len(payload.get("features", [])))

        features = await _preprocess(payload)
        prediction = await _model_infer(features)
        result = await _postprocess(prediction)

        span.set_attribute("prediction.class", result["label"])
        span.set_attribute("prediction.score", result["score"])
        return result

async def _preprocess(payload: dict) -> list:
    with tracer.start_as_current_span("preprocess") as span:
        start = time.monotonic()
        # feature lookup, scaling, encoding …
        features = [float(v) for v in payload.get("features", [])]
        span.set_attribute("preprocess.latency_ms", (time.monotonic()-start)*1000)
        return features

async def _model_infer(features: list) -> dict:
    with tracer.start_as_current_span("model.infer") as span:
        span.set_attribute("model.version", "3.2.1")
        span.set_attribute("model.framework", "torch")
        # call triton / torchserve …
        raw = {"logits": [0.82, 0.18]}
        span.set_attribute("model.batch_size", 1)
        return raw

async def _postprocess(raw: dict) -> dict:
    with tracer.start_as_current_span("postprocess") as span:
        score = max(raw["logits"])
        label = "churn" if score > 0.5 else "retain"
        span.set_attribute("postprocess.threshold", 0.5)
        return {"label": label, "score": round(score, 4)}

Trace Propagation Across Services

When the inference API calls a feature store or a downstream service, the trace context must propagate via HTTP headers (traceparent, tracestate). The W3C TraceContext standard is OTel's default.

"""Inject / extract W3C trace context headers manually when SDK auto-inst isn't available."""
from opentelemetry import trace, propagate
from opentelemetry.propagators.b3 import B3MultiFormat
import httpx

propagate.set_global_textmap(B3MultiFormat())   # fallback for legacy B3 services

    ctx_headers: dict = {}
    propagate.inject(ctx_headers)               # injects traceparent / b3 headers
    async with httpx.AsyncClient() as client:
        resp = await client.get(
            f"http://feature-store/features/{entity_id}",
            headers=ctx_headers,
            timeout=0.1

    return resp.json()

def extract_context_from_request(request_headers: dict):
    ctx = propagate.extract(request_headers)    # reconstructs Span context

        tracer.start_span("feature_store.lookup", context=ctx),
        end_on_exit=True
    )

2. Alerting Strategy for ML

Severity levels · Runbooks · PagerDuty/OpsGenie

Alert fatigue is the #1 on-call killer. At Netflix, we learned that every noisy alert that wakes an engineer at 2 AM and resolves without intervention destroys trust in the alerting system. The fix is a severity taxonomy with hard rules about who gets paged and when.

Severity Levels for ML Alerts

P0 — Critical (page immediately, 24/7): Model serving down, error rate >10%, revenue-impacting degradation. SLA: response in 5 min.
P1 — High (page during business hours + on-call overnight): Accuracy drop >15% vs baseline, severe feature drift confirmed, p99 latency >5s. SLA: response in 30 min.
P2 — Medium (ticket + Slack, no page): Gradual drift detected, data quality issues, retraining job failure. SLA: respond next business day.
P3 — Low (dashboard annotation, weekly review): Minor distribution shift, model staleness warning, A/B test divergence. SLA: address in sprint planning.

PagerDuty / OpsGenie Webhook Integration

python · alerting_webhook.py 
"""Send structured ML alerts to PagerDuty (Events v2) or OpsGenie."""
import httpx, os, json
from datetime import datetime, timezone
from enum import Enum

class Severity(str, Enum):
    CRITICAL = "critical"   # P0
    ERROR    = "error"      # P1
    WARNING  = "warning"    # P2
    INFO     = "info"       # P3

PD_ROUTING_KEY = os.environ["PAGERDUTY_ROUTING_KEY"]
OG_API_KEY     = os.environ["OPSGENIE_API_KEY"]

async def page_pagerduty(
    summary: str,
    severity: Severity,
    model: str,
    details: dict,
) -> str:
    payload = {
        "routing_key": PD_ROUTING_KEY,
        "event_action": "trigger",
        "payload": {
            "summary": f"[ML Alert] {summary}",
            "severity": severity.value,
            "timestamp": datetime.now(timezone.utc).isoformat(),
            "source": f"ml-monitoring/{model}",
            "custom_details": {
                "model": model,
                **details,
            },
        },
        "links": [{"href": f"https://grafana.internal/d/ml/{model}", "text": "Dashboard"}],
    }
    async with httpx.AsyncClient() as client:
        r = await client.post(
            "https://events.pagerduty.com/v2/enqueue",
            json=payload, timeout=10,
        )
        r.raise_for_status()
    return r.json()["dedup_key"]

async def page_opsgenie(summary: str, severity: Severity, model: str, details: dict):
    priority_map = {
        Severity.CRITICAL: "P1", Severity.ERROR: "P2",
        Severity.WARNING: "P3", Severity.INFO: "P5",
    }
    payload = {
        "message": f"[ML] {summary}",
        "alias": f"ml-{model}-{severity.value}",   # dedup key
        "priority": priority_map[severity],
        "tags": ["ml", "monitoring", model],
        "details": details,
        "source": "ml-monitoring",
    }
    async with httpx.AsyncClient() as client:
        r = await client.post(
            "https://api.opsgenie.com/v2/alerts",
            json=payload,
            headers={"Authorization": f"GenieKey {OG_API_KEY}"},
            timeout=10,
        )
        r.raise_for_status()

# Example usage from a monitoring job:
async def check_and_alert(model_name: str, psi_score: float):
    if psi_score > 0.5:
        await page_pagerduty(
            summary=f"CRITICAL drift on {model_name} (PSI={psi_score:.3f})",
            severity=Severity.CRITICAL,
            model=model_name,
            details={"psi_score": psi_score, "threshold": 0.5, "action": "rollback"},
        )
    elif psi_score > 0.25:
        await page_pagerduty(
            summary=f"High drift on {model_name} (PSI={psi_score:.3f})",
            severity=Severity.ERROR,
            model=model_name,
            details={"psi_score": psi_score, "threshold": 0.25, "action": "retrain"},
        )

SageMaker vs Vertex AI — key differences:
  • Vertex requires a training dataset in GCS for skew detection; SageMaker works from a captured baseline job.
  • Vertex sampling is configured at monitor creation; SageMaker uses endpoint data capture rules.
  • Both emit violations to their native alert systems (CloudWatch vs Cloud Monitoring) — integrate with your existing on-call tooling via webhooks.

5. Continuous Retraining Triggers

Scheduled · Drift-based · Performance-based · Data-volume

There are four trigger types for automated retraining. Use the simplest one that satisfies your SLA — don't over-engineer.

Drift-Triggered Retraining Pipeline (Airflow)

python · retrain_dag.py 
"""Airflow DAG: drift-triggered retraining with automatic promotion."""
from __future__ import annotations
from airflow import DAG
from airflow.operators.python import PythonOperator, BranchPythonOperator
from airflow.providers.http.sensors.http import HttpSensor
from airflow.utils.dates import days_ago
from datetime import timedelta
import json, requests, mlflow

DRIFT_API   = "http://monitoring-api/drift/latest"
MLFLOW_URI  = "http://mlflow:5000"
MODEL_NAME  = "churn-classifier"
PSI_THRESH  = 0.25

default_args = {"owner": "mlops", "retries": 1, "retry_delay": timedelta(minutes=5)}

def check_drift(**ctx) -> str:
    resp  = requests.get(DRIFT_API, params={"model": MODEL_NAME}).json()
    psi   = resp["psi_score"]
    ctx["ti"].xcom_push(key="psi_score", value=psi)
    return "trigger_retrain" if psi > PSI_THRESH else "skip_retrain"

def trigger_retrain(**ctx):
    import subprocess
    psi = ctx["ti"].xcom_pull(key="psi_score")
    print(f"Drift PSI={psi:.3f} > threshold={PSI_THRESH}. Starting retraining.")
    subprocess.run(["python", "/pipelines/train.py", "--trigger", "drift"], check=True)

def evaluate_candidate(**ctx):
    client = mlflow.tracking.MlflowClient(MLFLOW_URI)
    runs   = client.search_runs(
        experiment_ids=["1"],
        order_by=["start_time DESC"],
        max_results=1,
    )
    run    = runs[0]
    acc    = run.data.metrics.get("eval_accuracy", 0)
    ctx["ti"].xcom_push(key="candidate_run_id", value=run.info.run_id)
    ctx["ti"].xcom_push(key="candidate_acc", value=acc)
    return "promote_model" if acc >= 0.82 else "rollback"

def promote_model(**ctx):
    run_id = ctx["ti"].xcom_pull(key="candidate_run_id")
    client = mlflow.tracking.MlflowClient(MLFLOW_URI)
    mv     = client.create_model_version(MODEL_NAME, f"runs:/{run_id}/model", MODEL_NAME)
    client.transition_model_version_stage(MODEL_NAME, mv.version, "Production")
    print(f"Promoted {MODEL_NAME} v{mv.version} to Production")

def rollback(**ctx):
    print("Candidate did not meet quality gate. Keeping current production model.")

with DAG(
    dag_id="drift_triggered_retrain",
    default_args=default_args,
    schedule_interval="@hourly",
    catchup=False,
    tags=["mlops", "retraining"],
) as dag:
    check  = BranchPythonOperator(task_id="check_drift",      python_callable=check_drift)
    train  = PythonOperator(task_id="trigger_retrain",        python_callable=trigger_retrain)
    skip   = PythonOperator(task_id="skip_retrain",           python_callable=lambda **_: print("No drift."))
    eval_  = PythonOperator(task_id="evaluate_candidate",     python_callable=evaluate_candidate)
    branch = BranchPythonOperator(task_id="quality_gate",     python_callable=evaluate_candidate)
    prom   = PythonOperator(task_id="promote_model",          python_callable=promote_model)
    rb     = PythonOperator(task_id="rollback",               python_callable=rollback)

    check >> [train, skip]
    train >> eval_
    eval_ >> [prom, rb]

Performance-Threshold Trigger

python · perf_trigger.py 
"""Evaluate rolling model accuracy and trigger retraining if below threshold."""
import pandas as pd, mlflow, boto3
from datetime import datetime, timedelta

ACCURACY_FLOOR = 0.82    # retrain if rolling 24h accuracy drops below this
LABEL_DELAY_H  = 6       # hours until ground truth labels are available

def get_rolling_accuracy(model_name: str, window_hours: int = 24) -> float:
    """Fetch predictions + ground truth from feature store and compute accuracy."""
    s3 = boto3.client("s3")
    cutoff = datetime.utcnow() - timedelta(hours=window_hours + LABEL_DELAY_H)
    # In practice: query prediction logs joined with ground-truth labels
    preds_df = pd.read_parquet(f"s3://my-bucket/predictions/{model_name}/recent.parquet")
    preds_df = preds_df[preds_df["timestamp"] >= cutoff]
    if len(preds_df) < 100:               # insufficient sample — skip
        return None
    accuracy = (preds_df["prediction"] == preds_df["label"]).mean()
    return float(accuracy)

def maybe_trigger_retrain(model_name: str):
    acc = get_rolling_accuracy(model_name)
    if acc is None:
        print("Not enough labelled samples yet.")
        return

    mlflow.log_metric("rolling_accuracy_24h", acc)
    print(f"Rolling accuracy ({model_name}): {acc:.4f}")

    if acc < ACCURACY_FLOOR:
        print(f"Accuracy {acc:.4f} < floor {ACCURACY_FLOOR}. Triggering retrain.")
        # Kick off Airflow DAG or Kubeflow Pipeline via REST
        import requests
        requests.post(
            "http://airflow:8080/api/v1/dags/drift_triggered_retrain/dagRuns",
            json={"conf": {"trigger": "perf_threshold", "accuracy": acc}},
            auth=("admin", "admin"),
        )
    else:
        print(f"Accuracy {acc:.4f} OK — no retraining needed.")

Automated Retraining Feedback Loop

flowchart LR A[Production\nModel] -->|Predictions| B[Prediction\nLogger] B --> C[Feature Store\n+ Labels] C --> D{Monitors} D -->|Drift detected| E[Retrain\nTrigger] D -->|Acc below floor| E D -->|Scheduled| E E --> F[Training\nPipeline] F --> G[Candidate\nModel] G --> H{Quality Gate\nacc ≥ 0.82\nPSI ≤ 0.1} H -->|Pass| I[Shadow Mode\n1 hour] I -->|Metrics OK| J[Promote to\nProduction] J --> A H -->|Fail| K[Alert ML Team\nRollback]
Rollback strategy: Always keep the previous N model versions registered in MLflow/SageMaker. On a failed promotion, a single CLI call restores the prior version — no redeployment needed. Set N=3 for most teams.

6. Complete Monitoring → Retrain Loop

Detect drift → alert → retrain → evaluate → promote

python · full_monitoring_loop.py 
"""
End-to-end monitoring loop:
  1. Compute drift and performance metrics
  2. Decide alert severity
  3. Page on-call if needed
  4. Optionally trigger automated retraining
  5. Evaluate candidate and promote / rollback
"""
import asyncio, logging
from dataclasses import dataclass
from typing import Optional

import mlflow
from evidently import ColumnMapping
from evidently.report import Report
from evidently.metrics import DataDriftTable, ClassificationQualityMetric
import pandas as pd

log = logging.getLogger("monitoring-loop")

@dataclass
class MonitoringResult:
    model: str
    psi_score: float
    rolling_accuracy: float
    retrain_triggered: bool
    promoted_version: Optional[str]

async def monitoring_cycle(model_name: str) -> MonitoringResult:
    """Run one complete monitoring cycle for a model."""

    # 1. Load reference and current data
    ref_data = pd.read_parquet(f"s3://my-bucket/reference/{model_name}.parquet")
    cur_data = pd.read_parquet(f"s3://my-bucket/live/{model_name}/latest.parquet")

    # 2. Compute drift with Evidently
    col_map = ColumnMapping(target="label", prediction="prediction")
    report  = Report(metrics=[DataDriftTable(), ClassificationQualityMetric()])
    report.run(reference_data=ref_data, current_data=cur_data, column_mapping=col_map)
    result_dict  = report.as_dict()
    dataset_drift = result_dict["metrics"][0]["result"]
    psi_score     = dataset_drift.get("share_of_drifted_columns", 0.0)
    accuracy      = result_dict["metrics"][1]["result"].get("current", {}).get("accuracy", 1.0)

    # 3. Determine alert level and notify
    from alerting_webhook import check_and_alert, Severity, page_pagerduty
    await check_and_alert(model_name, psi_score)

    retrain_triggered = False
    promoted_version  = None

    # 4. Trigger retraining if warranted
    if psi_score > 0.25 or accuracy < 0.82:
        log.warning(f"Retrain trigger: PSI={psi_score:.3f}, acc={accuracy:.3f}")
        retrain_triggered = True
        candidate_run_id  = await run_training_pipeline(model_name)

        # 5. Evaluate and promote / rollback
        client   = mlflow.tracking.MlflowClient()
        run      = client.get_run(candidate_run_id)
        cand_acc = run.data.metrics.get("eval_accuracy", 0)

        if cand_acc >= 0.82 and cand_acc >= accuracy:
            mv = client.create_model_version(model_name, f"runs:/{candidate_run_id}/model", model_name)
            client.transition_model_version_stage(model_name, mv.version, "Production")
            promoted_version = mv.version
            log.info(f"Promoted {model_name} v{mv.version} (acc={cand_acc:.3f})")
        else:
            await page_pagerduty(
                summary=f"Retrain candidate failed quality gate for {model_name}",
                severity=Severity.ERROR,
                model=model_name,
                details={"candidate_acc": cand_acc, "floor": 0.82},
            )

    return MonitoringResult(
        model=model_name,
        psi_score=psi_score,
        rolling_accuracy=accuracy,
        retrain_triggered=retrain_triggered,
        promoted_version=promoted_version,
    )

Summary & Key Takeaways

This chapter (15B) and its companion (ch15 — Prometheus, Evidently, drift detection) form a complete ML observability system. Here is what to take away from both.

From ch15 (Monitoring & Drift)

  • Prometheus + Grafana for infrastructure-level ML metrics
  • Evidently for feature drift (PSI, KS, JS divergence) and model quality reports
  • Log predictions + labels from day one — you cannot retroactively compute drift
  • Choose drift detectors matched to your data type (numerical vs categorical)

From ch15B (Alerting & Retraining)

  • OTel traces reveal where latency is hiding in your inference pipeline
  • Severity taxonomy (P0–P3) prevents alert fatigue; every alert needs a runbook URL
  • Start with scheduled retraining; add drift/perf triggers only when you need them
  • Never auto-promote without a quality gate and shadow mode evaluation
  • Managed monitors (SageMaker, Vertex) lower ops burden at the cost of cloud lock-in

The One Rule

A model in production without monitoring is not an ML system — it's a time bomb. The monitoring loop you build should be boring: drift fires, retraining kicks off, quality gate passes, new version is promoted. If your on-call engineers are manually triggering retrains and making rollback decisions under pressure at 2 AM, you have not finished building your MLOps platform.
