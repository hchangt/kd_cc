1. Cloud Fundamentals for ML Engineers

Why you're here, and what you need to know before writing a single line of infrastructure code.

Why Cloud for ML?

On-prem GPU clusters feel tangible — you can physically touch the hardware — but they impose hidden costs that crush iteration speed at every level of the stack. A single H100 server costs ~$300k capex, takes 6–18 months to procure in a supply-constrained market, requires a raised-floor data center, a facilities team, network engineers, and a storage team. When the experiment is done, the hardware sits idle.

Cloud flips the model: you pay for exactly what you use, spin up 512 H100s in under five minutes, and release them the moment training finishes. For ML specifically, this elasticity is not a convenience — it is the core enabling technology behind modern large-scale research and production deployment.

Cloud Advantages

  • + Elastic compute — scale from 0 to thousands of GPUs in minutes
  • + No capex — pay only for actual usage
  • + Spot/preemptible instances = 60–90% cost reduction for training
  • + Managed services (S3, GCS, SageMaker, Vertex AI) reduce ops burden
  • + Global presence — deploy inference endpoints close to users
  • + Network bandwidth between nodes far exceeds typical on-prem

When On-Prem Makes Sense

  • ! Extremely stable, predictable GPU utilization (>85% for 3+ years)
  • ! Hard regulatory/data-sovereignty constraints
  • ! Ultra-low latency inference with specialized hardware
  • ! Very large orgs with mature infra teams (Meta, Google internal)

2. AWS for ML Engineers

The services you will touch every single day — and the ones worth knowing deeply versus just reading the docs on demand.

Core AWS Services Map

Compute

  • EC2 — GPU VMs (p3, p4d, p5, g5, trn1)
  • EKS — Managed Kubernetes (preferred for ML)
  • ECS — Container orchestration (simpler, less flex)
  • AWS Batch — Managed batch jobs, ideal for training pipelines
  • Lambda — Serverless, lightweight pre/post-processing

Storage

  • S3 — Object store, primary data lake
  • EFS — Managed NFS, shared across instances
  • FSx for Lustre — Parallel FS for high-throughput training
  • EBS — Block storage attached to EC2
  • S3 Glacier — Cold archive for old datasets

ML-Specific

  • SageMaker — End-to-end ML platform
  • Bedrock — Foundation model API (Claude, Llama, etc.)
  • ECR — Container registry for training/serving images
  • Trainium (trn1) — AWS custom ML chip
  • Inferentia (inf2) — AWS custom inference chip

Networking

  • VPC — Isolated virtual network
  • Security Groups — Stateful firewall rules
  • NAT Gateway — Outbound internet for private subnets
  • VPN / Direct Connect — On-prem connectivity
  • EFA — Elastic Fabric Adapter (RDMA for distributed training)

Data & Databases

  • RDS / Aurora — Relational DB for metadata
  • DynamoDB — NoSQL for feature store, low-latency lookup
  • Redshift — Data warehouse for analytics
  • Glue — ETL and data catalog
  • Athena — Serverless SQL on S3

Observability & Ops

  • CloudWatch — Metrics, logs, alarms
  • CloudTrail — API audit log
  • X-Ray — Distributed tracing
  • Secrets Manager — Credentials management
  • Cost Explorer — Billing analysis

Choosing between p4d and p5

For most training runs under 70B parameters, p4d.24xlarge with spot pricing (~$8/hr) is the best value. p5.48xlarge is justified when you need the H100's 3x tensor core throughput for frontier models or when the EFA v3 3200 Gbps fabric is the bottleneck in multi-node all-reduce. Always benchmark with your actual batch size before committing.

S3 Best Practices for ML

  • Partitioning: Organize data as s3://bucket/dataset/year=2025/month=04/part-000.parquet. This enables partition pruning in Athena/Spark and reduces egress scan costs.
  • Multipart Upload: Always use multipart for files >100 MB. The threshold in boto3 is configurable via TransferConfig. Multipart also enables parallel upload from multiple threads.
  • Lifecycle Policies: Move training data to S3-IA after 30 days, Glacier after 90 days. Tag datasets with project and environment for cost allocation.
  • Requester Pays: For shared datasets across teams, enable requester-pays to charge egress to the consuming team.
  • S3 Express One Zone: For hot training data needing <10ms latency, use S3 Express One Zone — up to 10x lower latency and higher throughput than standard S3.
  • Bucket Policy vs ACL: Always use bucket policies, never ACLs. Enable BlockPublicAccess at the account level without exception.

s3_ml_operations.py — S3 operations for ML Python 
import boto3
from botocore.config import Config
from boto3.s3.transfer import TransferConfig
import os

# ── Client with retry config ──────────────────────────────────────────────────
s3 = boto3.client(
    "s3",
    region_name="us-east-1",
    config=Config(retries={"max_attempts": 10, "mode": "adaptive"}),
)

# ── Multipart upload for large training datasets ──────────────────────────────
def upload_dataset(local_path: str, bucket: str, key: str) -> None:
    transfer_config = TransferConfig(
        multipart_threshold=100 * 1024 * 1024,   # 100 MB
        max_concurrency=10,                        # parallel threads
        multipart_chunksize=100 * 1024 * 1024,    # 100 MB chunks
        use_threads=True,
    )
    s3.upload_file(
        local_path,
        bucket,
        key,
        Config=transfer_config,
        ExtraArgs={
            "StorageClass": "INTELLIGENT_TIERING",
            "Metadata": {
                "project": "llm-training-v2",
                "environment": "prod",
            },
        },
    )
    print(f"Uploaded {local_path} → s3://{bucket}/{key}")


# ── Stream-download checkpoint to local SSD ──────────────────────────────────
def download_checkpoint(bucket: str, key: str, local_path: str) -> None:
    transfer_config = TransferConfig(
        max_concurrency=20,
        multipart_chunksize=256 * 1024 * 1024,   # 256 MB chunks
    )
    os.makedirs(os.path.dirname(local_path), exist_ok=True)
    s3.download_file(bucket, key, local_path, Config=transfer_config)
    print(f"Downloaded s3://{bucket}/{key} → {local_path}")


# ── List all checkpoints for a run ───────────────────────────────────────────
def list_checkpoints(bucket: str, run_id: str) -> list[str]:
    paginator = s3.get_paginator("list_objects_v2")
    prefix = f"checkpoints/{run_id}/"
    keys = []
    for page in paginator.paginate(Bucket=bucket, Prefix=prefix):
        for obj in page.get("Contents", []):
            keys.append(obj["Key"])
    return sorted(keys)


# ── Set lifecycle policy on a bucket ─────────────────────────────────────────
def set_ml_lifecycle_policy(bucket: str) -> None:
    s3.put_bucket_lifecycle_configuration(
        Bucket=bucket,
        LifecycleConfiguration={
            "Rules": [
                {
                    "ID": "training-data-tiering",
                    "Status": "Enabled",
                    "Filter": {"Prefix": "datasets/"},
                    "Transitions": [
                        {"Days": 30,  "StorageClass": "STANDARD_IA"},
                        {"Days": 90,  "StorageClass": "GLACIER_IR"},
                        {"Days": 365, "StorageClass": "DEEP_ARCHIVE"},
                    ],
                },
                {
                    "ID": "checkpoint-cleanup",
                    "Status": "Enabled",
                    "Filter": {"Prefix": "checkpoints/"},
                    "Expiration": {"Days": 90},
                },
            ]
        },
    )
    print(f"Lifecycle policy set on {bucket}")

import boto3
import json

ec2 = boto3.client("ec2", region_name="us-east-1")


# ── Launch spot fleet for distributed training ────────────────────────────────
def launch_training_fleet(
    num_nodes: int,
    instance_type: str = "p4d.24xlarge",
    ami_id: str = "ami-0123456789abcdef0",
    subnet_id: str = "subnet-xxxxxxxxx",
    security_group_id: str = "sg-xxxxxxxxx",
    iam_instance_profile: str = "arn:aws:iam::123456789012:instance-profile/MLTrainingRole",
) -> str:
    """Launch a spot fleet for distributed training."""
    user_data = """#!/bin/bash
set -e
# Mount FSx Lustre
mount -t lustre -o relatime,flock fs-xxxxxxxxx.fsx.us-east-1.amazonaws.com@tcp:/xxxxxxxx /fsx
# Start training (managed by the orchestrator)
/opt/ml/start_training.sh
"""
    response = ec2.request_spot_fleet(
        SpotFleetRequestConfig={
            "IamFleetRole": "arn:aws:iam::123456789012:role/aws-ec2-spot-fleet-role",
            "TargetCapacity": num_nodes,
            "Type": "maintain",          # auto-replace interrupted nodes
            "AllocationStrategy": "lowestPrice",
            "LaunchSpecifications": [
                {
                    "ImageId": ami_id,
                    "InstanceType": instance_type,
                    "SubnetId": subnet_id,
                    "SecurityGroups": [{"GroupId": security_group_id}],
                    "IamInstanceProfile": {"Arn": iam_instance_profile},
                    "UserData": boto3.client("ec2").meta.events._emitter._lookup_cache.__class__(
                        __import__("base64").b64encode(user_data.encode()).decode()
                    ),
                    "Placement": {"GroupName": "ml-cluster-pg"},  # placement group
                }
            ],
            "TagSpecifications": [
                {
                    "ResourceType": "instance",
                    "Tags": [
                        {"Key": "Project", "Value": "llm-training"},
                        {"Key": "Environment", "Value": "prod"},
                    ],
                }
            ],
        }
    )
    fleet_id = response["SpotFleetRequestId"]
    print(f"Spot fleet launched: {fleet_id}")
    return fleet_id


# ── Describe running training instances ──────────────────────────────────────
def get_training_instances(project_tag: str) -> list[dict]:
    response = ec2.describe_instances(
        Filters=[
            {"Name": "tag:Project",     "Values": [project_tag]},
            {"Name": "instance-state-name", "Values": ["running", "pending"]},
        ]
    )
    instances = []
    for reservation in response["Reservations"]:
        for inst in reservation["Instances"]:
            instances.append({
                "id":         inst["InstanceId"],
                "type":       inst["InstanceType"],
                "private_ip": inst.get("PrivateIpAddress", ""),
                "state":      inst["State"]["Name"],
                "az":         inst["Placement"]["AvailabilityZone"],
            })
    return instances

3. GCP for ML Engineers

Google's cloud has always been ML-first — it's the platform that runs Google Brain, DeepMind, and the original TPU research. That heritage shows.

Core GCP Services Map

Compute

  • GCE A3 (H100) — 8x H100 80GB, highest GPU performance
  • GCE A2 (A100) — 1–16x A100 40/80GB
  • TPU v4/v5p Pods — Custom ML accelerators, massive scale
  • GKE — Managed Kubernetes, best-in-class for ML
  • Cloud Run — Serverless containers, inference endpoints
  • Cloud Functions — Event-driven lightweight compute

Storage

  • GCS — Object store, primary data lake (S3 equivalent)
  • Filestore — Managed NFS (EFS equivalent)
  • Hyperdisk ML — High-throughput block storage for model loading
  • Persistent Disk — Standard block storage for GCE
  • GCS FUSE — Mount GCS buckets as local filesystem

ML-Specific

  • Vertex AI — End-to-end ML platform (SageMaker equivalent)
  • Model Garden — Curated foundation model hub
  • Vertex AI Pipelines — Managed KFP-based orchestration
  • Feature Store — Online/offline feature serving
  • Model Monitoring — Drift and skew detection

Data & Analytics

  • BigQuery — Serverless data warehouse, ML-native (BQML)
  • Bigtable — NoSQL for low-latency serving (feature lookup)
  • Spanner — Global relational DB
  • Cloud SQL — Managed PostgreSQL/MySQL
  • Dataflow — Managed Apache Beam for streaming/batch ETL

Networking

  • VPC — Global (spans all regions, unlike AWS)
  • Firewall Rules — Network-level stateless + stateful
  • Cloud NAT — Outbound for private instances
  • Cloud Interconnect — Dedicated/partner on-prem link
  • GPUDirect RDMA — InfiniBand-class networking for A3/TPU pods

Observability

  • Cloud Monitoring — Metrics (Prometheus-compatible)
  • Cloud Logging — Centralized logs
  • Cloud Trace — Distributed tracing
  • Error Reporting — Exception aggregation
  • Secret Manager — Credentials management

TPU Recommendation

If your team writes JAX and is training transformer-based models >10B parameters, TPU v4/v5p pods are frequently 2–3x more cost-efficient than equivalent GPU clusters. The ICI interconnect eliminates the all-reduce bottleneck entirely. If you need PyTorch or model flexibility (RL loops, custom CUDA kernels), stick with GPU.

GCS Best Practices for ML

  • Location type: Use multi-region buckets (US, EU) for training data accessed by jobs across multiple regions. Use single-region buckets co-located with your training cluster for checkpoint I/O.
  • Uniform bucket-level access: Always enable this. Disables per-object ACLs and enforces IAM-only access control.
  • Parallel composite uploads: Use gsutil -m cp -Z or the Python storage client with composite uploads for files over 1 GB.
  • Object versioning: Enable on checkpoint buckets so you can roll back to a previous checkpoint after an experiment goes sideways.
  • Storage class: Standard for active training data, Nearline (30-day min) for datasets used monthly, Coldline (90-day min) for archives.
  • GCS FUSE: Mount buckets directly as a filesystem in GKE pods via the GCS FUSE CSI driver — eliminates explicit download steps for training data.

gcs_ml_operations.py — GCS operations for ML Python 
from google.cloud import storage
from google.cloud.storage import transfer_manager
import os

client = storage.Client(project="my-ml-project")


# ── Parallel upload of a directory of shards ─────────────────────────────────
def upload_dataset_directory(local_dir: str, bucket_name: str, prefix: str) -> None:
    bucket = client.bucket(bucket_name)
    file_paths = [
        os.path.join(dp, f)
        for dp, dn, filenames in os.walk(local_dir)
        for f in filenames
    ]
    blob_names = [
        os.path.join(prefix, os.path.relpath(fp, local_dir))
        for fp in file_paths
    ]
    results = transfer_manager.upload_many_from_filenames(
        bucket,
        file_paths,
        blob_name_prefix=prefix,
        max_workers=8,
    )
    for path, result in zip(file_paths, results):
        if isinstance(result, Exception):
            print(f"FAILED {path}: {result}")
        else:
            print(f"Uploaded {path}")


# ── Download checkpoint with exponential backoff ─────────────────────────────
def download_checkpoint(bucket_name: str, blob_name: str, dest_path: str) -> None:
    from google.api_core.retry import Retry
    bucket = client.bucket(bucket_name)
    blob = bucket.blob(blob_name)
    os.makedirs(os.path.dirname(dest_path), exist_ok=True)
    blob.download_to_filename(dest_path, retry=Retry())
    print(f"Downloaded gs://{bucket_name}/{blob_name} → {dest_path}")


# ── Set lifecycle policy ──────────────────────────────────────────────────────
def set_lifecycle_policy(bucket_name: str) -> None:
    bucket = client.get_bucket(bucket_name)
    bucket.add_lifecycle_delete_rule(age=90, matches_prefix=["checkpoints/"])
    bucket.add_lifecycle_transition_rule(
        age=30,
        storage_class="NEARLINE",
        matches_prefix=["datasets/"],
    )
    bucket.add_lifecycle_transition_rule(
        age=90,
        storage_class="COLDLINE",
        matches_prefix=["datasets/"],
    )
    bucket.patch()
    print(f"Lifecycle policy updated on {bucket_name}")

When to Choose AWS vs GCP

Choose AWS When…

  • Your org already has significant AWS commitments (Enterprise Discount Program)
  • You need FSx for Lustre for HPC-style training I/O
  • Your workload uses services with no GCP equivalent (EMR, Step Functions, etc.)
  • Your team has deep AWS expertise and significant infra already running
  • You want Bedrock for Claude/Anthropic foundation model APIs
  • You need AWS GovCloud for US federal compliance
  • Trainium cost economics work out for your specific PyTorch workload

Choose GCP When…

  • You are training with JAX and want TPU pods (no equivalent on AWS)
  • BigQuery is your primary data warehouse — the ML-native features are unmatched
  • You want Gemini-family models via Vertex AI
  • Your team is Kubernetes-heavy — GKE is best-in-class
  • You want the global VPC simplicity (single network, all regions)
  • Cloud Run's serverless model fits your inference latency / scale pattern
  • Vertex AI Pipelines for managed KFP is a better fit than SageMaker Pipelines

Multi-Cloud Considerations

Warning: Multi-Cloud is Harder Than It Sounds

Every VP who has never managed infrastructure thinks multi-cloud means "not locked in." Every infra engineer who has tried it knows it means double the IAM complexity, double the networking to manage, zero ability to use managed services that cross providers, and 2x higher operational burden. Use multi-cloud only when you have a compelling business reason (regulatory requirement, pricing leverage, specific service only on one cloud). Abstract at the API level (Kubernetes, Terraform) rather than the cloud-service level.

If multi-cloud is required, the least-painful strategy is:

  • All training and data pipelines on one primary cloud
  • Inference/serving replicated on secondary cloud for DR or latency
  • Object storage as the boundary — S3 and GCS both support cross-cloud replication policies
  • Kubernetes (EKS + GKE) with a unified control plane (Anthos or Rancher)
  • Terraform for all infra — the provider abstraction prevents cloud-specific drift

5. Networking for ML

Network topology determines whether your 8-node training job saturates at 60% GPU utilization or 95%. Get this right before writing a single training loop.

VPC Design for ML Workloads

The canonical ML VPC layout separates public and private subnets across multiple AZs. Training and inference nodes never have public IPs. All outbound internet access routes through a NAT gateway or NAT instance.

Key Networking Decisions

Placement Groups (AWS) / Compact Placement Policies (GCP)

For distributed training, always request a cluster placement group. This co-locates your EC2 instances in the same physical rack or row, minimizing the hop count between nodes. Critical for all-reduce operations in NCCL — the difference between a placement group and a randomly scattered fleet can be 2–3x in inter-node bandwidth.

Elastic Fabric Adapter (EFA) — AWS

EFA is AWS's RDMA-capable network interface for HPC/ML workloads. Supported on p4d, p5, trn1. Provides OS-bypass networking — data goes directly to the NIC without going through the OS kernel, eliminating latency. Requires: (1) EFA-enabled instance type, (2) EFA security group rules, (3) NCCL compiled with EFA plugin, (4) cluster placement group. The p5.48xlarge's EFA v3 provides 3200 Gbps aggregate — required for H100 NVLink-scale all-reduce across nodes.

VPC Endpoints

Always create VPC endpoints for S3, ECR, and Secrets Manager. Without endpoints, traffic to these services routes via the NAT gateway, which (a) costs $0.045/GB and (b) adds latency for high-throughput training data reads. S3 gateway endpoints are free. Interface endpoints for ECR, KMS, SageMaker cost ~$7.30/month per AZ but save orders of magnitude more in egress fees.

Security Groups for ML Clusters

Training nodes need: (1) inbound on port 22 from bastion only, (2) inbound on all ports from the same security group (for NCCL inter-node communication), (3) no inbound from 0.0.0.0/0 ever. Inference nodes need: (1) inbound on model serving port (8080, 8501, etc.) from ALB security group only, (2) same-SG rule for cluster gossip.

#!/usr/bin/env bash
# Create VPC and subnets for an ML training cluster (us-east-1)
set -euo pipefail

REGION="us-east-1"
VPC_CIDR="10.0.0.0/16"
PROJECT_TAG="llm-training"

# ── Create VPC ────────────────────────────────────────────────────────────────
VPC_ID=$(aws ec2 create-vpc \
  --cidr-block "$VPC_CIDR" \
  --region "$REGION" \
  --tag-specifications "ResourceType=vpc,Tags=[{Key=Name,Value=$PROJECT_TAG-vpc},{Key=Project,Value=$PROJECT_TAG}]" \
  --query 'Vpc.VpcId' --output text)
echo "VPC: $VPC_ID"

# ── Enable DNS hostnames (required for EFA) ───────────────────────────────────
aws ec2 modify-vpc-attribute --vpc-id "$VPC_ID" --enable-dns-hostnames "{\"Value\":true}"
aws ec2 modify-vpc-attribute --vpc-id "$VPC_ID" --enable-dns-support    "{\"Value\":true}"

# ── Create subnets ────────────────────────────────────────────────────────────
PRIVATE_SUBNET_AZ_A=$(aws ec2 create-subnet \
  --vpc-id "$VPC_ID" \
  --cidr-block "10.0.1.0/24" \
  --availability-zone "${REGION}a" \
  --tag-specifications "ResourceType=subnet,Tags=[{Key=Name,Value=$PROJECT_TAG-training-1a}]" \
  --query 'Subnet.SubnetId' --output text)

PUBLIC_SUBNET=$(aws ec2 create-subnet \
  --vpc-id "$VPC_ID" \
  --cidr-block "10.0.0.0/24" \
  --availability-zone "${REGION}a" \
  --tag-specifications "ResourceType=subnet,Tags=[{Key=Name,Value=$PROJECT_TAG-public-1a}]" \
  --query 'Subnet.SubnetId' --output text)

# ── Create cluster placement group for co-located GPU nodes ──────────────────
aws ec2 create-placement-group \
  --group-name "$PROJECT_TAG-cluster-pg" \
  --strategy cluster \
  --region "$REGION"
echo "Placement group: $PROJECT_TAG-cluster-pg"

# ── S3 VPC Gateway Endpoint (free, eliminates NAT egress for S3) ──────────────
RTB_ID=$(aws ec2 describe-route-tables \
  --filters "Name=vpc-id,Values=$VPC_ID" \
  --query 'RouteTables[0].RouteTableId' --output text)

aws ec2 create-vpc-endpoint \
  --vpc-id "$VPC_ID" \
  --service-name "com.amazonaws.$REGION.s3" \
  --route-table-ids "$RTB_ID"
echo "S3 VPC endpoint created"

# ── Security group for training cluster ──────────────────────────────────────
SG_ID=$(aws ec2 create-security-group \
  --group-name "$PROJECT_TAG-training-sg" \
  --description "ML training cluster SG" \
  --vpc-id "$VPC_ID" \
  --query 'GroupId' --output text)

# Allow all traffic within the security group (NCCL inter-node)
aws ec2 authorize-security-group-ingress \
  --group-id "$SG_ID" \
  --protocol all \
  --source-group "$SG_ID"

echo "Security group: $SG_ID"
echo "Setup complete. Training subnet: $PRIVATE_SUBNET_AZ_A"

FSx for Lustre on AWS

FSx for Lustre is the recommended storage layer when your GPU cluster's data loading is the bottleneck. It is a fully managed parallel filesystem that can be linked to an S3 bucket — training jobs read from the local Lustre mount, and FSx lazily imports objects from S3 on first access (and can be pre-warmed via create-data-repository-task).

FSx Lustre Performance Tiers

  • Scratch (HDD-backed): 200 MB/s per TiB, short-lived, no replication. Use for single training runs.
  • Scratch (SSD-backed): Same but SSD latency. Recommended default for training.
  • Persistent (HDD): 125/250 MB/s per TiB, 6x replication. Use for datasets accessed by multiple teams.
  • Persistent (SSD): 500/1000 MB/s per TiB. Use when random access patterns need <1ms latency.
fsx_lustre_setup.py — Create and link FSx Lustre filesystem to S3 Python 
import boto3

fsx = boto3.client("fsx", region_name="us-east-1")


def create_training_filesystem(
    subnet_id: str,
    security_group_id: str,
    s3_bucket: str,
    s3_prefix: str = "datasets/",
    storage_capacity_gib: int = 4800,  # minimum 1200 GiB, must be multiple of 2400
) -> str:
    """Create FSx for Lustre linked to S3 for high-throughput training data access."""
    response = fsx.create_file_system(
        FileSystemType="LUSTRE",
        StorageCapacity=storage_capacity_gib,
        StorageType="SSD",
        SubnetIds=[subnet_id],
        SecurityGroupIds=[security_group_id],
        LustreConfiguration={
            "ImportPath":           f"s3://{s3_bucket}/{s3_prefix}",
            "ExportPath":           f"s3://{s3_bucket}/fsx-exports/",
            "DeploymentType":       "SCRATCH_2",   # fast, no replication
            "PerUnitStorageThroughput": 200,        # MB/s per TiB
            "DataCompressionType": "LZ4",           # transparent compression
        },
        Tags=[{"Key": "Purpose", "Value": "ml-training"}],
    )
    fs_id = response["FileSystem"]["FileSystemId"]
    dns   = response["FileSystem"]["DNSName"]
    mount = response["FileSystem"]["LustreConfiguration"]["MountName"]
    print(f"FSx Lustre created: {fs_id}")
    print(f"Mount command: mount -t lustre {dns}@tcp:/{mount} /fsx")
    return fs_id


def prewarm_filesystem(fs_id: str) -> str:
    """Pre-import all S3 objects into Lustre metadata cache before training starts."""
    response = fsx.create_data_repository_task(
        Type="IMPORT_METADATA_AND_DATA_REPOSITORY",
        FileSystemId=fs_id,
        Paths=["/"],   # import all paths
        Report={
            "Enabled": True,
            "Path": "s3://my-ml-bucket/fsx-import-reports/",
            "Format": "REPORT_CSV_20191124",
            "Scope": "FAILED_FILES_ONLY",
        },
    )
    task_id = response["DataRepositoryTask"]["TaskId"]
    print(f"Pre-warm task submitted: {task_id}")
    return task_id

spot_training_launcher.py — Fault-tolerant spot training with checkpointing Python 
import boto3
import time
import signal
import sys
import os
import torch
from pathlib import Path

# ── Checkpoint utilities ──────────────────────────────────────────────────────
CHECKPOINT_DIR = Path("/fsx/checkpoints")
S3_CHECKPOINT_BUCKET = "corp-ml-checkpoints"
RUN_ID = os.environ.get("RUN_ID", "default-run")

s3 = boto3.client("s3")


def save_checkpoint(model, optimizer, step: int, loss: float) -> None:
    """Save checkpoint to local NVMe then async-upload to S3."""
    ckpt_path = CHECKPOINT_DIR / f"step-{step}.pt"
    CHECKPOINT_DIR.mkdir(parents=True, exist_ok=True)
    torch.save({
        "step":            step,
        "model_state":     model.state_dict(),
        "optimizer_state": optimizer.state_dict(),
        "loss":            loss,
    }, ckpt_path)
    # Upload to S3 (blocking here; use background thread in production)
    s3_key = f"{RUN_ID}/step-{step}.pt"
    s3.upload_file(str(ckpt_path), S3_CHECKPOINT_BUCKET, s3_key)
    print(f"Checkpoint saved: step={step}, s3://{S3_CHECKPOINT_BUCKET}/{s3_key}")


def load_latest_checkpoint(model, optimizer) -> int:
    """Find and load the latest checkpoint from S3."""
    paginator = s3.get_paginator("list_objects_v2")
    keys = []
    for page in paginator.paginate(Bucket=S3_CHECKPOINT_BUCKET, Prefix=f"{RUN_ID}/"):
        keys += [obj["Key"] for obj in page.get("Contents", [])]
    if not keys:
        print("No checkpoint found, starting from scratch.")
        return 0
    latest_key = sorted(keys, key=lambda k: int(k.split("step-")[1].replace(".pt", "")))[-1]
    local_path = CHECKPOINT_DIR / "latest.pt"
    s3.download_file(S3_CHECKPOINT_BUCKET, latest_key, str(local_path))
    ckpt = torch.load(str(local_path), map_location="cuda")
    model.load_state_dict(ckpt["model_state"])
    optimizer.load_state_dict(ckpt["optimizer_state"])
    start_step = ckpt["step"]
    print(f"Resumed from step {start_step} (key: {latest_key})")
    return start_step


# ── Spot interruption handler ─────────────────────────────────────────────────
_interrupted = False

def _handle_spot_interruption(signum, frame):
    """AWS sends SIGTERM 2 minutes before reclaiming a spot instance."""
    global _interrupted
    print("SPOT INTERRUPTION SIGNAL RECEIVED — saving checkpoint before shutdown.")
    _interrupted = True

signal.signal(signal.SIGTERM, _handle_spot_interruption)


# ── Main training loop with checkpointing ────────────────────────────────────
def train(model, optimizer, dataloader, total_steps: int, checkpoint_every: int = 500):
    global _interrupted
    start_step = load_latest_checkpoint(model, optimizer)

    for step, batch in enumerate(dataloader, start=start_step):
        if _interrupted:
            print(f"Saving emergency checkpoint at step {step}...")
            save_checkpoint(model, optimizer, step, float("nan"))
            sys.exit(0)   # exit cleanly; SQS/orchestrator will requeue

        loss = model(batch)
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()

        if step % checkpoint_every == 0:
            save_checkpoint(model, optimizer, step, loss.item())

        if step >= total_steps:
            break

    save_checkpoint(model, optimizer, total_steps, loss.item())
    print("Training complete.")

gcp_ml_bootstrap.sh — Bootstrap an ML environment on GCP Bash 
#!/usr/bin/env bash
# ── 0. Prerequisites ──────────────────────────────────────────────────────────
# gcloud CLI, kubectl, helm, python 3.11+
set -euo pipefail

PROJECT_ID="my-ml-project-001"
REGION="us-central1"
ZONE="us-central1-a"

echo "Bootstrapping ML environment in project $PROJECT_ID"

# ── 1. Enable required APIs ───────────────────────────────────────────────────
gcloud services enable \
  container.googleapis.com \
  storage.googleapis.com \
  aiplatform.googleapis.com \
  artifactregistry.googleapis.com \
  secretmanager.googleapis.com \
  monitoring.googleapis.com \
  --project="$PROJECT_ID"

# ── 2. GCS buckets ────────────────────────────────────────────────────────────
for SUFFIX in training-data checkpoints models artifacts; do
  BUCKET="${PROJECT_ID}-${SUFFIX}"
  gcloud storage buckets create "gs://$BUCKET" \
    --location="$REGION" \
    --uniform-bucket-level-access \
    --project="$PROJECT_ID" 2>/dev/null || true

  # Enable object versioning on checkpoints
  if [[ "$SUFFIX" == "checkpoints" ]]; then
    gcloud storage buckets update "gs://$BUCKET" --versioning
  fi

  echo "Bucket ready: gs://$BUCKET"
done

# ── 3. Artifact Registry ──────────────────────────────────────────────────────
gcloud artifacts repositories create ml-images \
  --repository-format=docker \
  --location="$REGION" \
  --description="ML training and serving images" \
  --project="$PROJECT_ID" 2>/dev/null || true

echo "Artifact Registry: ${REGION}-docker.pkg.dev/${PROJECT_ID}/ml-images"

# ── 4. GKE cluster with GPU node pool ────────────────────────────────────────
gcloud container clusters create "$PROJECT_ID-cluster" \
  --zone="$ZONE" \
  --machine-type="n2-standard-4" \
  --num-nodes=2 \
  --enable-autoscaling --min-nodes=1 --max-nodes=10 \
  --workload-pool="${PROJECT_ID}.svc.id.goog" \
  --enable-ip-alias \
  --no-enable-basic-auth \
  --project="$PROJECT_ID"

# Add GPU node pool (starts at 0, scales up on demand)
gcloud container node-pools create gpu-pool \
  --cluster="$PROJECT_ID-cluster" \
  --zone="$ZONE" \
  --machine-type="a2-highgpu-1g" \
  --accelerator="type=nvidia-tesla-a100,count=1" \
  --num-nodes=0 \
  --enable-autoscaling --min-nodes=0 --max-nodes=8 \
  --node-taints="nvidia.com/gpu=present:NoSchedule" \
  --project="$PROJECT_ID"

# Install NVIDIA drivers via DaemonSet
kubectl apply -f https://raw.githubusercontent.com/GoogleCloudPlatform/container-engine-accelerators/master/nvidia-driver-installer/cos/daemonset-preloaded.yaml

# ── 5. Enable Workload Identity for default namespace ─────────────────────────
gcloud container clusters get-credentials "$PROJECT_ID-cluster" \
  --zone="$ZONE" --project="$PROJECT_ID"

echo "GKE cluster ready: $PROJECT_ID-cluster"
echo "Run: kubectl get nodes -o wide"

Chapter 3: Infrastructure as Code

The CLI commands above are great for understanding what is being created, but production infrastructure should always be defined as code using Terraform. Chapter 3 covers Terraform in depth: provider configuration, state management, modules, workspaces, and full end-to-end ML platform definitions for both AWS and GCP. You will never run aws ec2 create-* by hand in production after reading it.

Key Takeaways

1.

VPC-first: Every ML resource lives inside a VPC. Training and inference nodes have no public IPs. All S3/GCS access goes through VPC endpoints, not NAT gateways.

2.

Spot/Preemptible for training: Implement checkpoint-and-resume before committing to on-demand. 60–90% cost savings make the engineering investment worthwhile after the second training run.

3.

Storage hierarchy matters: FSx Lustre / Filestore for active training data, S3/GCS for everything else. Never let training jobs pull from S3 directly at high throughput — the latency variance destroys GPU utilization.

4.

EFA / GPUDirect RDMA: On AWS, always use EFA with cluster placement groups for multi-node training. The difference in all-reduce bandwidth vs standard ethernet is 5–10x.

5.

IAM is not optional: Use IRSA (AWS) or Workload Identity (GCP) for all pod-level credentials. No JSON keys in containers. No wildcard s3:* permissions. Scope every role to the minimum required.

6.

GCP for JAX/TPU, AWS for PyTorch/FSx: Both clouds run excellent ML workloads. The tipping point is (a) TPU pods for JAX → GCP, (b) FSx Lustre for HPC-style I/O → AWS, (c) existing org commitments trump everything.

7.

BigQuery over Redshift: If you are on GCP, BigQuery is a serious operational simplification. Zero cluster management, automatic scaling, and native ML integration via BQML. Redshift requires tuning, cluster sizing, and vacuuming.

8.

Tag everything: Enforce cost allocation tags at the org/account level from day one. Retroactively attributing cloud spend to teams and projects in a $5M/month environment without tags is an exercise in pain.
