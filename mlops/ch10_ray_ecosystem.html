Section 1

Why Ray?

The Python Distributed Computing Gap

Python dominates ML workloads. Yet Python's GIL, single-process model, and library ecosystem were never designed for distributed execution. Before Ray, engineering teams faced a painful choice: rewrite training loops in Spark (JVM, not Python-native), hand-roll MPI scripts with brittle NCCL topology logic, or stitch together Celery + Redis for actor-style workloads — and then run separate infrastructure for hyperparameter search, serving, and preprocessing. Each tool brought its own cluster management story, its own serialization format, and its own failure modes.

Ray's thesis, published by the RISELab at UC Berkeley in 2018, was simple but radical: a single, Python-native distributed runtime that is general enough to express tasks, actors, and dataflows — and specialized enough to handle GPU-heavy ML natively. Today Ray is the backbone of workloads at OpenAI, Spotify, Instacart, Shopify, and dozens of AI labs.

Key components:

  • Global Control Store (GCS): Stores cluster metadata, object ownership tables, and actor locations. In Ray 2.x the GCS is fault-tolerant via Redis or an embedded store.
  • Raylet: Each node runs a raylet that acts as a local scheduler. It manages the node's resources, object store, and worker processes.
  • Plasma Object Store: A shared-memory store (Apache Arrow format) for zero-copy passing of large NumPy arrays and other objects between co-located processes.
  • Driver: The process that calls ray.init() and submits tasks/actors. On a cluster this runs on the head node.
  • Dashboard: A built-in web UI at port 8265 showing cluster utilization, task timelines, memory, and logs.

When Ray Shines (and When It Doesn't)

Ray excels at:

  • Large-scale distributed training (DDP, FSDP)
  • Parallel HPO with thousands of trials
  • Online inference with heterogeneous models
  • Python-heavy ML preprocessing pipelines
  • Multi-agent RL environments (RLlib)
  • Workloads mixing CPU and GPU workers

Consider alternatives when:

  • SQL analytics at petabyte scale (use Spark/Trino)
  • Existing heavy Spark investment with complex SQL DAGs
  • Simple job queuing with no ML (use Celery/SQS)
  • Purely streaming pipelines (Flink is more mature)
  • Team has zero Python experience

Ray Core

Ray Core provides three primitives: remote functions (tasks), remote classes (actors), and the distributed object store. Everything in Ray Train, Tune, Serve, and Data is built on top of these three primitives.

Tasks — @ray.remote Functions

A task is a stateless function that Ray schedules on any available worker. Tasks are submitted asynchronously and return object references (futures).

Example 1 — Ray tasks, actors, and object store
import ray
import numpy as np
import time

# Initialize Ray (auto-detects local CPUs, or connects to a cluster)
ray.init()  # or ray.init(address="ray://head-node:10001")

# ── TASKS ──────────────────────────────────────────────────────────────────────
@ray.remote
def train_fold(fold_id: int, data: np.ndarray, lr: float) -> dict:
    """Simulates training on one CV fold. Runs in a separate worker process."""
    time.sleep(0.1)  # simulate work
    loss = float(np.random.rand()) + lr * 0.01
    return {"fold": fold_id, "val_loss": loss, "lr": lr}

# Submit tasks — non-blocking, returns ObjectRef immediately
data = np.random.randn(10_000, 128)
refs = [train_fold.remote(i, data, lr=0.001 * (i + 1)) for i in range(5)]

# Block and collect results
results = ray.get(refs)
print(results)

# ── OBJECT STORE ───────────────────────────────────────────────────────────────
# Put large data into the object store once; pass the ref to many tasks.
# Zero-copy within the same node (Plasma shared memory).
large_dataset = np.random.randn(100_000, 512)
dataset_ref = ray.put(large_dataset)  # returns ObjectRef

@ray.remote
def preprocess_chunk(data_ref, start: int, end: int) -> np.ndarray:
    data = ray.get(data_ref)   # zero-copy on same node
    return data[start:end] * 2.0 - 1.0

chunk_refs = [
    preprocess_chunk.remote(dataset_ref, i * 10_000, (i + 1) * 10_000)
    for i in range(10)
]
chunks = ray.get(chunk_refs)
processed = np.vstack(chunks)
print(f"Processed shape: {processed.shape}")

# ── ACTORS ─────────────────────────────────────────────────────────────────────
@ray.remote
class ParameterServer:
    """Stateful actor — lives as a long-running process on a worker node."""
    def __init__(self, model_size: int):
        self.params = np.zeros(model_size)
        self.step = 0

    def apply_gradient(self, grad: np.ndarray, lr: float = 0.01) -> None:
        self.params -= lr * grad
        self.step += 1

    def get_params(self) -> np.ndarray:
        return self.params.copy()

    def get_step(self) -> int:
        return self.step

# Create actor (returns ActorHandle, actor lives until handle goes out of scope)
ps = ParameterServer.remote(model_size=1024)

# Multiple workers push gradients concurrently
@ray.remote
def worker_step(ps_handle, worker_id: int):
    grad = np.random.randn(1024) * 0.1
    ps_handle.apply_gradient.remote(grad)
    return worker_id

worker_refs = [worker_step.remote(ps, i) for i in range(8)]
ray.get(worker_refs)

params = ray.get(ps.get_params.remote())
step   = ray.get(ps.get_step.remote())
print(f"PS step={step}, param norm={np.linalg.norm(params):.4f}")

ray.shutdown()

Parallel Hyperparameter Search with Ray Core

Example 2 — Manual parallel HPO with Ray tasks
import ray
import numpy as np
from itertools import product
from typing import List, Dict

ray.init()

@ray.remote(num_cpus=2)
def evaluate_config(config: Dict) -> Dict:
    """Train a small model and return validation metric."""
    lr         = config["lr"]
    batch_size = config["batch_size"]
    dropout    = config["dropout"]

    # Simulate training: replace with real training loop
    np.random.seed(int(lr * 1e6) % 9999)
    val_loss = (
        0.5
        + 0.3 * np.log(1 / lr)
        + 0.1 * np.random.randn()
        + 0.05 * (dropout - 0.3) ** 2
        - 0.002 * batch_size
    )
    return {**config, "val_loss": float(val_loss)}

# Build search grid
lrs         = [1e-4, 3e-4, 1e-3, 3e-3]
batch_sizes = [32, 64, 128]
dropouts    = [0.1, 0.3, 0.5]

configs = [
    {"lr": lr, "batch_size": bs, "dropout": dr}
    for lr, bs, dr in product(lrs, batch_sizes, dropouts)
]
print(f"Total configs: {len(configs)}")

# Submit all in parallel — Ray schedules across available CPUs
refs = [evaluate_config.remote(cfg) for cfg in configs]
results: List[Dict] = ray.get(refs)

# Find best
best = min(results, key=lambda r: r["val_loss"])
print(f"Best config: {best}")

ray.shutdown()

    pass

# Scheduling strategies
from ray.util.scheduling_strategies import (
    NodeAffinitySchedulingStrategy,
    PlacementGroupSchedulingStrategy,
)

@ray.remote
class PinnedActor:
    pass

Performance Tip: Object Store Pinning

When passing a large NumPy array to many tasks, always use ray.put() first. Without it, Ray serializes and copies the array once per task submission. With ray.put(), the array lives in the Plasma store and is referenced by all tasks — zero copies on the same node.

Ray Client

Ray Client lets you connect to a remote Ray cluster from your laptop using ray.init("ray://head-node:10001"). Your driver code runs locally but tasks/actors execute on the cluster. This is useful for interactive development, but for production jobs use Ray Jobs API (ray job submit) which runs the driver on the head node for better fault isolation.

Ray Data — Distributed ML Preprocessing

Ray Data is a scalable data processing library built on top of Ray Core and Apache Arrow. It handles the "last mile" problem of getting data from storage into your training loop, including distributed preprocessing, format conversion, and streaming.

Example 6 — Ray Data preprocessing pipeline
import ray
import ray.data
import numpy as np
from typing import Dict

ray.init()

# ── READ ──────────────────────────────────────────────────────────────────────
# Reads lazily; actual I/O happens when consuming
ds = ray.data.read_parquet(
    "s3://my-bucket/training-data/",
    columns=["text", "label", "split"],
)
print(f"Dataset: {ds.count()} rows, schema: {ds.schema()}")

# ── MAP BATCHES (vectorized preprocessing) ────────────────────────────────────
from transformers import AutoTokenizer

# Use ActorPoolStrategy to keep the tokenizer loaded across batches
class Tokenizer:
    def __init__(self):
        self.tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")

    def __call__(self, batch: Dict[str, list]) -> Dict[str, np.ndarray]:
        encoded = self.tokenizer(
            batch["text"],
            padding="max_length",
            truncation=True,
            max_length=128,
            return_tensors="np",
        )
        return {
            "input_ids":      encoded["input_ids"],
            "attention_mask": encoded["attention_mask"],
            "label":          np.array(batch["label"]),
        }

tokenized_ds = ds.map_batches(
    Tokenizer,
    batch_size=256,
    compute=ray.data.ActorPoolStrategy(size=4),   # 4 persistent tokenizer actors
    num_cpus=2,
)

# ── FILTER ─────────────────────────────────────────────────────────────────────
# Keep only rows where label is valid
tokenized_ds = tokenized_ds.filter(lambda row: row["label"] in [0, 1, 2])

# ── REPARTITION for balanced shards ───────────────────────────────────────────
tokenized_ds = tokenized_ds.repartition(200)  # 200 blocks

# ── SPLIT for train/val/test ───────────────────────────────────────────────────
train_ds, val_ds, test_ds = tokenized_ds.split_proportionately([0.8, 0.1, 0.1])

# ── MATERIALIZE to object store (optional, for small datasets) ────────────────
# train_ds = train_ds.materialize()

print(f"Train: {train_ds.count()}, Val: {val_ds.count()}, Test: {test_ds.count()}")

ray.shutdown()
Example 7 — Ray Data with PyTorch Lightning
import ray
import ray.data
from ray.train.torch import TorchTrainer
from ray.train import ScalingConfig, RunConfig, CheckpointConfig
import torch
import torch.nn as nn
from torch.utils.data import DataLoader
import pytorch_lightning as pl

# ── DATASET ───────────────────────────────────────────────────────────────────
def build_datasets():
    ds = ray.data.read_parquet("s3://my-bucket/nlp-data/")
    train_ds, val_ds = ds.train_test_split(test_size=0.1)
    return train_ds, val_ds

# ── LIGHTNING MODULE ──────────────────────────────────────────────────────────
class TextClassifier(pl.LightningModule):
    def __init__(self, vocab_size=30522, hidden=256, num_classes=3):
        super().__init__()
        self.embed = nn.Embedding(vocab_size, hidden)
        self.pool  = nn.AdaptiveAvgPool1d(1)
        self.head  = nn.Linear(hidden, num_classes)

    def forward(self, x):
        e = self.embed(x)               # (B, T, H)
        e = self.pool(e.transpose(1,2)) # (B, H, 1)
        return self.head(e.squeeze(-1))

    def training_step(self, batch, _):
        logits = self(batch["input_ids"])
        loss   = nn.CrossEntropyLoss()(logits, batch["label"])
        self.log("train/loss", loss, prog_bar=True)
        return loss

    def configure_optimizers(self):
        return torch.optim.AdamW(self.parameters(), lr=3e-4)

# ── RAY TRAIN WORKER FUNCTION ─────────────────────────────────────────────────
def train_loop_per_worker(config):
    from ray.train import get_dataset_shard
    from ray.train.torch import get_device

    train_shard = get_dataset_shard("train")
    val_shard   = get_dataset_shard("val")

    def to_torch_dataset(ray_shard):
        """Convert Ray Data shard to PyTorch IterableDataset."""
        class RayIterableDataset(torch.utils.data.IterableDataset):
            def __iter__(self):
                for batch in ray_shard.iter_torch_batches(batch_size=32):
                    for i in range(len(batch["input_ids"])):
                        yield {k: v[i] for k, v in batch.items()}
        return RayIterableDataset()

    train_loader = DataLoader(to_torch_dataset(train_shard), batch_size=32)
    val_loader   = DataLoader(to_torch_dataset(val_shard),   batch_size=64)

    model   = TextClassifier()
    trainer = pl.Trainer(
        max_epochs=config["epochs"],
        accelerator="gpu" if torch.cuda.is_available() else "cpu",
        devices=1,
        enable_progress_bar=False,
    )
    trainer.fit(model, train_loader, val_loader)

# ── LAUNCH DISTRIBUTED TRAINING ───────────────────────────────────────────────
ray.init()
train_ds, val_ds = build_datasets()

trainer = TorchTrainer(
    train_loop_per_worker=train_loop_per_worker,
    train_loop_config={"epochs": 5},
    scaling_config=ScalingConfig(num_workers=4, use_gpu=True),
    datasets={"train": train_ds, "val": val_ds},
    run_config=RunConfig(name="text-clf-lightning"),
)
result = trainer.fit()
ray.shutdown()

Ray Train — Distributed Training

Ray Train abstracts the complexity of distributed training — process group setup, rank assignment, gradient synchronization, checkpointing, fault recovery — so you write a standard single-device training loop and Ray handles distribution.

TorchTrainer — Complete DDP Script

Example 8 — Ray Train TorchTrainer with DDP
import ray
from ray import train
from ray.train import ScalingConfig, RunConfig, CheckpointConfig
from ray.train.torch import TorchTrainer, get_device, prepare_model, prepare_data_loader
import torch
import torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset

# ── MODEL ─────────────────────────────────────────────────────────────────────
class MLP(nn.Module):
    def __init__(self, in_features=512, hidden=256, num_classes=10):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(in_features, hidden),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(hidden, hidden),
            nn.ReLU(),
            nn.Linear(hidden, num_classes),
        )

    def forward(self, x):
        return self.net(x)

# ── PER-WORKER TRAINING LOOP ──────────────────────────────────────────────────
def train_loop_per_worker(config: dict):
    # Unpack hyperparams
    lr         = config["lr"]
    batch_size = config["batch_size"]
    epochs     = config["epochs"]
    in_features = config.get("in_features", 512)

    # Build dataset (workers share the same random data for this example)
    torch.manual_seed(42 + train.get_context().get_world_rank())
    X = torch.randn(10_000, in_features)
    y = torch.randint(0, 10, (10_000,))
    dataset = TensorDataset(X, y)

    # prepare_data_loader handles DistributedSampler automatically
    loader = prepare_data_loader(
        DataLoader(dataset, batch_size=batch_size, shuffle=True),
        add_dist_sampler=True,
    )

    # prepare_model wraps in DistributedDataParallel
    model     = prepare_model(MLP(in_features=in_features))
    optimizer = torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=1e-4)
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=epochs)
    criterion = nn.CrossEntropyLoss()
    device    = get_device()

    for epoch in range(epochs):
        model.train()
        total_loss, correct, total = 0.0, 0, 0

        for xb, yb in loader:
            xb, yb = xb.to(device), yb.to(device)
            optimizer.zero_grad()
            logits = model(xb)
            loss   = criterion(logits, yb)
            loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            optimizer.step()
            total_loss += loss.item() * len(xb)
            correct    += (logits.argmax(1) == yb).sum().item()
            total      += len(xb)

        scheduler.step()

        epoch_loss = total_loss / total
        epoch_acc  = correct / total

        # Checkpoint + metrics reporting (only rank-0 saves by default)
        checkpoint = train.Checkpoint.from_dict({
            "epoch":       epoch,
            "model_state": model.module.state_dict(),  # .module unwraps DDP
            "optimizer":   optimizer.state_dict(),
            "lr":          scheduler.get_last_lr()[0],
        })
        train.report(
            {"loss": epoch_loss, "accuracy": epoch_acc, "epoch": epoch},
            checkpoint=checkpoint,
        )

# ── LAUNCH ────────────────────────────────────────────────────────────────────
ray.init()

trainer = TorchTrainer(
    train_loop_per_worker=train_loop_per_worker,
    train_loop_config={
        "lr": 3e-4,
        "batch_size": 128,

def train_loop_per_worker(config):
    from ray.train import get_dataset_shard

    rank       = train.get_context().get_world_rank()
    world_size = train.get_context().get_world_size()

    # Initialize DeepSpeed
    model_name = config["model_name"]
    model      = AutoModelForSequenceClassification.from_pretrained(
        model_name, num_labels=config["num_labels"]
    )

    optimizer = torch.optim.AdamW(model.parameters(), lr=config["lr"])

    # DeepSpeed init — wraps model with ZeRO-3 sharding
    engine, optimizer, _, _ = deepspeed.initialize(
        model=model,
        optimizer=optimizer,
        config=DEEPSPEED_CONFIG,
    )

    train_shard = get_dataset_shard("train")

    for epoch in range(config["epochs"]):
        engine.train()
        total_loss = 0.0

        for batch in train_shard.iter_torch_batches(batch_size=8):
            input_ids = batch["input_ids"].to(engine.local_rank)
            attn_mask = batch["attention_mask"].to(engine.local_rank)
            labels    = batch["labels"].to(engine.local_rank)

            outputs = engine(input_ids=input_ids,
                             attention_mask=attn_mask,
                             labels=labels)
            loss    = outputs.loss
            engine.backward(loss)
            engine.step()
            total_loss += loss.item()

        if rank == 0:
            print(f"Epoch {epoch}: loss={total_loss:.4f}")

        train.report({"epoch": epoch, "loss": total_loss})

Ray Tune — Hyperparameter Optimization

Ray Tune is the gold standard for distributed hyperparameter optimization in Python. It integrates with Optuna, Hyperopt, HyperBand, PBT, and dozens of other search algorithms, and it can scale from a single machine to thousands of concurrent trials.

Example 11 — Basic Ray Tune with ASHA + Optuna
import ray
from ray import tune
from ray.tune import TuneConfig
from ray.tune.schedulers import ASHAScheduler
from ray.tune.search.optuna import OptunaSearch
import torch
import torch.nn as nn
import numpy as np

# ── TRAINABLE FUNCTION ────────────────────────────────────────────────────────
def train_model(config):
    """One trial: train a model with the given hyperparameters."""
    # Build model
    model = nn.Sequential(
        nn.Linear(64, config["hidden_size"]),
        nn.ReLU(),
        nn.Dropout(config["dropout"]),
        nn.Linear(config["hidden_size"], 10),
    )
    optimizer = torch.optim.Adam(model.parameters(), lr=config["lr"])
    criterion = nn.CrossEntropyLoss()

    # Fake dataset
    X_train = torch.randn(5000, 64)
    y_train = torch.randint(0, 10, (5000,))
    X_val   = torch.randn(1000, 64)
    y_val   = torch.randint(0, 10, (1000,))

    for epoch in range(config["max_epochs"]):
        # Training
        model.train()
        perm  = torch.randperm(len(X_train))
        total_loss = 0.0
        bs = config["batch_size"]
        for i in range(0, len(X_train), bs):
            idx   = perm[i:i+bs]
            xb, yb = X_train[idx], y_train[idx]
            optimizer.zero_grad()
            loss = criterion(model(xb), yb)
            loss.backward()
            optimizer.step()
            total_loss += loss.item()

        # Validation
        model.eval()
        with torch.no_grad():
            val_logits = model(X_val)
            val_loss   = criterion(val_logits, y_val).item()
            val_acc    = (val_logits.argmax(1) == y_val).float().mean().item()

        # Report to Tune — ASHA uses this to prune bad trials early
        tune.report({"val_loss": val_loss, "val_accuracy": val_acc, "epoch": epoch})

# ── SEARCH SPACE ──────────────────────────────────────────────────────────────
search_space = {
    "lr":          tune.loguniform(1e-5, 1e-2),
    "hidden_size": tune.choice([64, 128, 256, 512]),
    "dropout":     tune.uniform(0.0, 0.5),
    "batch_size":  tune.choice([32, 64, 128]),
    "max_epochs":  20,
}

# ── ASHA SCHEDULER (early stopping of bad trials) ─────────────────────────────
asha = ASHAScheduler(
    metric="val_loss",
    mode="min",
    max_t=20,              # max epochs
    grace_period=3,        # run at least 3 epochs before pruning
    reduction_factor=2,    # halve the population at each rung
)

# ── OPTUNA SEARCH ALGORITHM ───────────────────────────────────────────────────
optuna_search = OptunaSearch(metric="val_loss", mode="min")

# ── TUNER ─────────────────────────────────────────────────────────────────────
ray.init()

tuner = tune.Tuner(
    tune.with_resources(
        train_model,
        resources={"CPU": 2, "GPU": 0},
    ),
    param_space=search_space,
    tune_config=TuneConfig(
        search_alg=optuna_search,
        scheduler=asha,
        num_samples=50,          # 50 trials total
        max_concurrent_trials=8, # 8 parallel trials
        metric="val_loss",
        mode="min",
    ),
    run_config=ray.train.RunConfig(
        name="mlp-hpo",
        storage_path="s3://my-bucket/tune-results",
    ),
)

results = tuner.fit()
best    = results.get_best_result(metric="val_loss", mode="min")
print(f"Best config: {best.config}")
print(f"Best val_loss: {best.metrics['val_loss']:.4f}")
ray.shutdown()
Example 12 — Population-Based Training (PBT)
from ray import tune
from ray.tune.schedulers import PopulationBasedTraining
import ray

def pbt_trainable(config):
    """Stateful trainable for PBT — must handle config perturbation."""
    import torch
    import torch.nn as nn

    model     = nn.Linear(32, 1)
    optimizer = torch.optim.SGD(model.parameters(), lr=config["lr"],
                                 momentum=config["momentum"])

    # Restore checkpoint if PBT exploited a better performer
    checkpoint = tune.get_checkpoint()
    step = 0
    if checkpoint:
        state = checkpoint.to_dict()
        model.load_state_dict(state["model_state"])
        optimizer.load_state_dict(state["optimizer_state"])
        step = state["step"]
        # PBT may have mutated config.lr — update optimizer
        for g in optimizer.param_groups:
            g["lr"] = config["lr"]

    criterion = nn.MSELoss()

    while True:   # PBT controls stopping via scheduler
        x = torch.randn(128, 32)
        y = torch.randn(128, 1)

        optimizer.zero_grad()
        loss = criterion(model(x), y)
        loss.backward()
        optimizer.step()
        step += 1

        ckpt = tune.Checkpoint.from_dict({
            "model_state":     model.state_dict(),
            "optimizer_state": optimizer.state_dict(),
            "step":            step,
        })
        tune.report({"loss": loss.item(), "step": step}, checkpoint=ckpt)

pbt = PopulationBasedTraining(
    metric="loss",
    mode="min",
    perturbation_interval=5,        # perturb every 5 iterations
    hyperparam_mutations={
        "lr":       tune.loguniform(1e-5, 1e-1),
        "momentum": tune.uniform(0.5, 0.99),
    },
    quantile_fraction=0.25,         # top 25% exploit bottom 25%
    resample_probability=0.25,
)

ray.init()
tuner = tune.Tuner(
    pbt_trainable,
    param_space={"lr": 0.01, "momentum": 0.9},
    tune_config=tune.TuneConfig(
        scheduler=pbt,
        num_samples=8,
        metric="loss",
        mode="min",
    ),
    run_config=ray.train.RunConfig(
        name="pbt-demo",
        stop={"training_iteration": 50},
    ),
)
results = tuner.fit()
print(results.get_best_result().config)
ray.shutdown()

Example 14 — Multi-model pipeline: preprocessing → model → postprocessing
import ray
from ray import serve
from ray.serve.handle import DeploymentHandle
from fastapi import FastAPI
from pydantic import BaseModel
from typing import List, Dict
import torch
import torch.nn as nn
import numpy as np

ray.init()
serve.start()

app = FastAPI()

# ── STAGE 1: PREPROCESSOR ─────────────────────────────────────────────────────
@serve.deployment(num_replicas=2, ray_actor_options={"num_cpus": 1})
class Preprocessor:
    def __init__(self):
        self.mean = np.zeros(64)
        self.std  = np.ones(64)

    async def preprocess(self, raw_features: List[float]) -> List[float]:
        x = (np.array(raw_features) - self.mean) / (self.std + 1e-8)
        return x.tolist()

# ── STAGE 2: PRIMARY MODEL ─────────────────────────────────────────────────────
@serve.deployment(num_replicas=3, ray_actor_options={"num_cpus": 2, "num_gpus": 1})
class PrimaryModel:
    def __init__(self):
        self.model = nn.Linear(64, 128)
        self.model.eval()

    async def embed(self, features: List[float]) -> List[float]:
        x = torch.tensor(features, dtype=torch.float32).unsqueeze(0)
        with torch.no_grad():
            emb = self.model(x)
        return emb.squeeze(0).tolist()

# ── STAGE 3: CLASSIFIER ───────────────────────────────────────────────────────
@serve.deployment(num_replicas=2, ray_actor_options={"num_cpus": 1})
class Classifier:
    def __init__(self):
        self.model = nn.Linear(128, 10)
        self.model.eval()

    async def classify(self, embedding: List[float]) -> Dict:
        x      = torch.tensor(embedding, dtype=torch.float32).unsqueeze(0)
        logits = self.model(x)
        probs  = torch.softmax(logits, dim=-1).squeeze(0)
        return {
            "class":      int(probs.argmax().item()),
            "confidence": float(probs.max().item()),
            "all_probs":  probs.tolist(),
        }

# ── PIPELINE ORCHESTRATOR ─────────────────────────────────────────────────────
class PredictRequest(BaseModel):
    features: List[float]

@serve.deployment(num_replicas=1)
@serve.ingress(app)
class Pipeline:
    def __init__(
        self,
        preprocessor: DeploymentHandle,
        primary_model: DeploymentHandle,
        classifier: DeploymentHandle,
    ):
        self.preprocessor  = preprocessor
        self.primary_model = primary_model
        self.classifier    = classifier

    @app.post("/pipeline/predict")
    async def predict(self, request: PredictRequest):
        # Async pipeline — each stage runs on its own replicas
        normalized = await self.preprocessor.preprocess.remote(request.features)
        embedding  = await self.primary_model.embed.remote(normalized)
        result     = await self.classifier.classify.remote(embedding)
        return result

# ── COMPOSE AND DEPLOY ────────────────────────────────────────────────────────
preprocessor  = Preprocessor.bind()
primary_model = PrimaryModel.bind()
classifier    = Classifier.bind()
pipeline      = Pipeline.bind(preprocessor, primary_model, classifier)

serve.run(pipeline, route_prefix="/")
Example 15 — Batched inference for throughput optimization
from ray import serve
import torch
import torch.nn as nn
from typing import List
import asyncio

@serve.deployment(
    num_replicas=2,
    ray_actor_options={"num_gpus": 1, "num_cpus": 2},
    max_concurrent_queries=200,
)
class BatchedClassifier:
    def __init__(self):
        self.model = nn.Sequential(
            nn.Linear(512, 256), nn.ReLU(), nn.Linear(256, 10)
        )
        self.model.eval()
        if torch.cuda.is_available():
            self.model = self.model.cuda()

    @serve.batch(
        max_batch_size=64,   # accumulate up to 64 requests
        batch_wait_timeout_s=0.01,  # wait max 10ms for a full batch
    )
    async def batch_predict(self, features_list: List[List[float]]) -> List[dict]:
        """Called with a batch of requests when batch is full or timeout fires."""
        x = torch.tensor(features_list, dtype=torch.float32)
        if torch.cuda.is_available():
            x = x.cuda()
        with torch.no_grad():
            logits = self.model(x)
            probs  = torch.softmax(logits, dim=-1).cpu()

        # Return one dict per request in the batch
        return [
            {"class": int(p.argmax()), "confidence": float(p.max())}
            for p in probs
        ]

    async def __call__(self, request):
        body = await request.json()
        return await self.batch_predict(body["features"])

serve.run(BatchedClassifier.bind(), route_prefix="/batched")

Ray Workflows — Durable ML Pipelines

Ray Workflows (introduced in Ray 1.7) provides durable execution of DAGs. Unlike plain Ray tasks, Workflow steps persist their outputs — if the cluster crashes, execution resumes from the last completed step. This is critical for long-running ML pipelines.

Example 16 — Ray Workflow for a full ML pipeline
import ray
from ray import workflow
from typing import List, Dict
import pandas as pd
import numpy as np

ray.init()
workflow.init()   # uses /tmp/ray/workflow_data by default; override with storage

# ── PIPELINE STEPS ────────────────────────────────────────────────────────────
@workflow.step
def ingest_data(source_path: str) -> pd.DataFrame:
    """Read raw data. If this step completes, it won't re-run on restart."""
    print(f"Ingesting data from {source_path}")
    # In production: pd.read_parquet(source_path) from S3
    return pd.DataFrame({"x": np.random.randn(10000), "y": np.random.randint(0, 2, 10000)})

@workflow.step
def validate_data(df: pd.DataFrame) -> pd.DataFrame:
    """Data quality checks."""
    assert len(df) > 0, "Empty dataset"
    assert "x" in df.columns and "y" in df.columns
    df = df.dropna()
    print(f"Validated: {len(df)} rows, {df['y'].value_counts().to_dict()}")
    return df

@workflow.step
def feature_engineering(df: pd.DataFrame) -> pd.DataFrame:
    """Transform features."""
    df["x_squared"] = df["x"] ** 2
    df["x_log"]     = np.log1p(np.abs(df["x"]))
    return df

@workflow.step
def train_model(df: pd.DataFrame, config: Dict) -> Dict:
    """Train model and return metrics + serialized model."""
    from sklearn.ensemble import GradientBoostingClassifier
    from sklearn.model_selection import train_test_split
    from sklearn.metrics import accuracy_score
    import pickle

    X = df[["x", "x_squared", "x_log"]].values
    y = df["y"].values

    X_train, X_val, y_train, y_val = train_test_split(X, y, test_size=0.2)
    clf = GradientBoostingClassifier(
        n_estimators=config.get("n_estimators", 100),
        learning_rate=config.get("lr", 0.1),
    )
    clf.fit(X_train, y_train)
    val_acc = accuracy_score(y_val, clf.predict(X_val))
    print(f"Validation accuracy: {val_acc:.4f}")
    return {"accuracy": val_acc, "model": pickle.dumps(clf)}

@workflow.step
def register_model(train_result: Dict, min_accuracy: float = 0.7) -> str:
    """Register model in MLflow if above threshold."""
    if train_result["accuracy"] < min_accuracy:
        raise ValueError(f"Model accuracy {train_result['accuracy']} < {min_accuracy}")
    # In production: mlflow.sklearn.log_model(...)
    model_uri = f"s3://my-bucket/models/run_latest"
    print(f"Model registered at {model_uri}")
    return model_uri

# ── RUN THE WORKFLOW ──────────────────────────────────────────────────────────
def run_pipeline(source_path: str, config: Dict) -> str:
    raw_df       = ingest_data.step(source_path)
    valid_df     = validate_data.step(raw_df)
    engineered   = feature_engineering.step(valid_df)
    train_result = train_model.step(engineered, config)
    model_uri    = register_model.step(train_result)
    return model_uri

# Execute workflow with a unique ID (allows resumption on failure)
model_uri = workflow.run(
    run_pipeline("s3://my-bucket/raw-data/", {"n_estimators": 200, "lr": 0.05}),
    workflow_id="ml-pipeline-2024-01-15",
)
print(f"Pipeline complete. Model at: {model_uri}")

ray.shutdown()

Workflows vs Orchestrators

Ray Workflows provides durability and DAG execution but is not a replacement for full orchestrators like Airflow or Prefect. Use Ray Workflows for within-Ray pipeline steps (data processing + training + registration). Use Airflow/Prefect for cross-system orchestration (triggering Ray jobs, waiting for data, sending alerts). The two layers complement each other — Airflow triggers a Ray Workflow via the Ray Jobs API.

A/B Testing with Ray Serve

Ray Serve's deployment composition makes A/B testing straightforward — route a fraction of traffic to a challenger model while monitoring metrics.

Example 17 — Complete ML serving platform with A/B testing
import ray
from ray import serve
from ray.serve.handle import DeploymentHandle
from fastapi import FastAPI, Header
from pydantic import BaseModel
from typing import Optional, List
import torch
import torch.nn as nn
import random
import time

ray.init()
serve.start()

app = FastAPI(title="ML Serving Platform")

# ── MODEL VERSIONS ────────────────────────────────────────────────────────────
@serve.deployment(name="model-v1", num_replicas=3, ray_actor_options={"num_gpus": 0.5})
class ModelV1:
    def __init__(self):
        self.model = nn.Linear(64, 10)
        self.model.eval()
        self.version = "v1"

    async def predict(self, features: List[float]) -> dict:
        x = torch.tensor(features, dtype=torch.float32).unsqueeze(0)
        with torch.no_grad():
            logits = self.model(x)
            probs  = torch.softmax(logits, dim=-1).squeeze(0)
        return {"class": int(probs.argmax()), "prob": float(probs.max()), "version": self.version}

@serve.deployment(name="model-v2", num_replicas=1, ray_actor_options={"num_gpus": 0.5})
class ModelV2:
    def __init__(self):
        self.model = nn.Sequential(
            nn.Linear(64, 128), nn.ReLU(), nn.Linear(128, 10)
        )
        self.model.eval()
        self.version = "v2-challenger"

    async def predict(self, features: List[float]) -> dict:
        x = torch.tensor(features, dtype=torch.float32).unsqueeze(0)
        with torch.no_grad():
            logits = self.model(x)
            probs  = torch.softmax(logits, dim=-1).squeeze(0)
        return {"class": int(probs.argmax()), "prob": float(probs.max()), "version": self.version}

# ── A/B ROUTER ────────────────────────────────────────────────────────────────
class PredictRequest(BaseModel):
    features: List[float]
    user_id:  Optional[str] = None

@serve.deployment(num_replicas=1)
@serve.ingress(app)
class ABRouter:
    def __init__(
        self,
        model_v1: DeploymentHandle,
        model_v2: DeploymentHandle,
        v2_traffic_pct: float = 10.0,  # 10% of traffic to challenger
    ):
        self.model_v1       = model_v1
        self.model_v2       = model_v2
        self.v2_traffic_pct = v2_traffic_pct
        self.stats          = {"v1_requests": 0, "v2_requests": 0, "v1_latency_ms": 0.0, "v2_latency_ms": 0.0}

    def _route_to_v2(self, user_id: Optional[str]) -> bool:
        """Deterministic routing: same user always goes to same variant."""
        if user_id:
            return (hash(user_id) % 100) < self.v2_traffic_pct
        return random.random() * 100 < self.v2_traffic_pct

    @app.post("/predict")
    async def predict(self, request: PredictRequest) -> dict:
        start = time.perf_counter()
        use_v2 = self._route_to_v2(request.user_id)
        if use_v2:
            result = await self.model_v2.predict.remote(request.features)
            self.stats["v2_requests"] += 1
            self.stats["v2_latency_ms"] += (time.perf_counter() - start) * 1000
        else:
            result = await self.model_v1.predict.remote(request.features)
            self.stats["v1_requests"] += 1
            self.stats["v1_latency_ms"] += (time.perf_counter() - start) * 1000
        return result

    @app.get("/ab-stats")
    async def ab_stats(self) -> dict:
        s = self.stats
        v1_avg = s["v1_latency_ms"] / max(s["v1_requests"], 1)
        v2_avg = s["v2_latency_ms"] / max(s["v2_requests"], 1)
        return {
            "v1_requests": s["v1_requests"],
            "v2_requests": s["v2_requests"],
            "v1_avg_latency_ms": round(v1_avg, 2),
            "v2_avg_latency_ms": round(v2_avg, 2),
            "v2_traffic_pct": self.v2_traffic_pct,
        }

    @app.put("/update-traffic")
    async def update_traffic(self, v2_pct: float) -> dict:
        self.v2_traffic_pct = v2_pct
        return {"message": f"Updated v2 traffic to {v2_pct}%"}

# Deploy
model_v1  = ModelV1.bind()
model_v2  = ModelV2.bind()
ab_router = ABRouter.bind(model_v1, model_v2, v2_traffic_pct=10.0)
serve.run(ab_router, route_prefix="/")

Common Performance Pitfalls

PitfallSymptomFix
Passing large objects without ray.put()High serialization time, OOM on head nodeUse ray.put() once, pass ObjectRef
Too many tiny tasksHigh scheduling overhead, low CPU utilizationBatch work into larger tasks; use map_batches
Blocking ray.get() in a loopLow parallelism, sequential executionSubmit all tasks first, then ray.get(all_refs)
Object store full — no spilling configuredOOM errors, worker crashesConfigure object_spilling_config or increase store size
Actor on wrong node (GPU mismatch)Slow training, no NVLink utilizationUse placement groups with PACK strategy
Head node doing compute workCluster instability, GCS slowdownsSet num-cpus=0 on head node
Uneven data partitioning in Ray DataStragglers, low throughputCall repartition() after filter/join operations
Too many concurrent trials in Ray TuneGPU memory OOMSet max_concurrent_trials; use fractional GPU (num_gpus=0.5)

Summary

Key Takeaways

Chapter 10 Key Takeaways

  • Ray Core provides three primitives — tasks, actors, and object store — sufficient to express any distributed ML workload. Master these before reaching for higher-level APIs.
  • Ray Train abstracts DDP/FSDP/DeepSpeed setup. Write a single-device training loop; Ray handles process groups, gradient sync, and fault recovery. Use prepare_model() and prepare_data_loader().
  • Ray Tune scales HPO to thousands of concurrent trials. Combine ASHA (early stopping) with Optuna (Bayesian search) for maximum efficiency. PBT is ideal for RL and adaptive learning rate schedules.
  • Ray Serve enables Python-native multi-model serving pipelines. Use @serve.batch for throughput, fractional GPU for dense packing, and deployment DAGs for preprocessing-model-postprocessing chains.
  • Ray Data closes the gap between storage and training. Use ActorPoolStrategy for expensive transforms (tokenization, image augmentation) to avoid per-batch initialization overhead.
  • Placement groups are essential for multi-GPU training — use PACK to ensure NVLink locality; use SPREAD for fault isolation in non-communication-heavy workloads.
  • KubeRay is the production path for Kubernetes. Define separate worker groups for CPU preprocessing nodes and GPU training nodes; enable autoscaling with appropriate minReplicas=0 for GPU nodes to save cost.
  • Object store hygiene: always ray.put() large arrays before broadcasting, configure object spilling for datasets larger than available RAM, and never block on ray.get() inside a task loop.
