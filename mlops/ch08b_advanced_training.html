1. 3D Parallelism: DP × TP × PP

Combining data, tensor, and pipeline parallelism into a unified training strategy.

No single parallelism axis suffices at 70B+ parameters. Production clusters combine all three: Data Parallelism (DP) across replica groups, Tensor Parallelism (TP) within a node (NVLink bandwidth), and Pipeline Parallelism (PP) across nodes (slower inter-node links). The total device count is DP × TP × PP.

2. Megatron-LM Deep Dive

NVIDIA's battle-tested framework for training transformers at scale.

Megatron-LM implements all three parallelism axes natively plus sequence parallelism (distributes LayerNorm/Dropout across TP ranks) and selective activation recomputation (recomputes only expensive ops like attention, not cheap ones). Together these cut memory ~30% vs naive recomputation.

Sequence Parallelism

In standard TP, the sequence dimension is replicated across TP ranks — wasting memory for activations. Sequence parallelism shards the sequence dimension during LayerNorm and Dropout, using AllGather before column-parallel linear layers and ReduceScatter after row-parallel layers. Net comm volume is identical, but activation memory scales as 1/TP.

Megatron-Core Transformer Layer (Simplified)

from megatron.core import tensor_parallel
from megatron.core.transformer import TransformerConfig
import torch, torch.nn as nn

class MegatronTransformerLayer(nn.Module):
    """Simplified Megatron-Core transformer layer with TP."""

    def __init__(self, config: TransformerConfig):
        super().__init__()
        self.config = config
        # Column-parallel: splits output features across TP ranks
        self.qkv_proj = tensor_parallel.ColumnParallelLinear(
            config.hidden_size, 3 * config.hidden_size,
            config=config, init_method=config.init_method,
            gather_output=False,  # keep split for attention
        )
        # Row-parallel: reduces across TP ranks via AllReduce/ReduceScatter
        self.out_proj = tensor_parallel.RowParallelLinear(
            config.hidden_size, config.hidden_size,
            config=config, init_method=config.output_layer_init_method,
            input_is_parallel=True,
        )
        # MLP: column then row (same pattern)
        self.mlp_fc1 = tensor_parallel.ColumnParallelLinear(
            config.hidden_size, 4 * config.hidden_size,
            config=config, gather_output=False,
        )
        self.mlp_fc2 = tensor_parallel.RowParallelLinear(
            4 * config.hidden_size, config.hidden_size,
            config=config, input_is_parallel=True,
        )
        # Sequence-parallel LayerNorm (operates on sharded seq dim)
        self.input_layernorm = nn.LayerNorm(config.hidden_size)
        self.post_attn_layernorm = nn.LayerNorm(config.hidden_size)

    def forward(self, hidden_states, attention_mask=None):
        # Pre-norm + attention
        residual = hidden_states
        hidden_states = self.input_layernorm(hidden_states)
        qkv, _ = self.qkv_proj(hidden_states)
        # ... flash attention omitted for brevity ...
        attn_out, _ = self.out_proj(qkv)
        hidden_states = residual + attn_out
        # Pre-norm + MLP
        residual = hidden_states
        hidden_states = self.post_attn_layernorm(hidden_states)
        hidden_states, _ = self.mlp_fc1(hidden_states)
        hidden_states = torch.nn.functional.silu(hidden_states)
        hidden_states, _ = self.mlp_fc2(hidden_states)
        return residual + hidden_states
Megatron-DeepSpeed Integration: Use --deepspeed flag with Megatron to layer ZeRO-1 optimizer sharding on top of TP+PP. ZeRO-1 shards optimizer states across DP ranks without touching activations — safe to combine. Avoid ZeRO-3 with Megatron TP: they conflict on parameter sharding.

import lightning as L
import torch
import torch.nn as nn
from torch.utils.data import DataLoader, DistributedSampler
from lightning.pytorch.strategies import FSDPStrategy
from lightning.pytorch.callbacks import ModelCheckpoint, LearningRateMonitor
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy
import functools

class LLMPretrainModule(L.LightningModule):
    def __init__(self, model, tokenizer, lr=3e-4, warmup_steps=2000,
                 total_steps=500_000, weight_decay=0.1):
        super().__init__()
        self.model = model
        self.tokenizer = tokenizer
        self.lr = lr
        self.warmup_steps = warmup_steps
        self.total_steps = total_steps
        self.weight_decay = weight_decay
        self.save_hyperparameters(ignore=["model", "tokenizer"])

    def forward(self, input_ids, attention_mask=None, labels=None):
        return self.model(input_ids, attention_mask=attention_mask, labels=labels)

    def training_step(self, batch, batch_idx):
        out = self(**batch)
        loss = out.loss
        self.log("train/loss", loss, on_step=True, on_epoch=False,
                 prog_bar=True, sync_dist=True)
        self.log("train/ppl", torch.exp(loss), on_step=True, sync_dist=True)
        return loss

    def validation_step(self, batch, batch_idx):
        with torch.no_grad():
            out = self(**batch)
        self.log("val/loss", out.loss, sync_dist=True, prog_bar=True)

    def configure_optimizers(self):
        # Separate weight decay for non-bias/layernorm params
        decay_params = [p for n, p in self.model.named_parameters()
                        if p.requires_grad and not any(nd in n for nd in
                        ["bias", "layer_norm", "layernorm", "ln_"])]
        no_decay_params = [p for n, p in self.model.named_parameters()
                           if p.requires_grad and any(nd in n for nd in
                           ["bias", "layer_norm", "layernorm", "ln_"])]
        optim = torch.optim.AdamW(
            [{"params": decay_params, "weight_decay": self.weight_decay},
             {"params": no_decay_params, "weight_decay": 0.0}],
            lr=self.lr, betas=(0.9, 0.95), eps=1e-8,
        )
        # Cosine LR with linear warmup
        def lr_lambda(step):
            if step < self.warmup_steps:
                return step / max(1, self.warmup_steps)
            progress = (step - self.warmup_steps) / max(1, self.total_steps - self.warmup_steps)
            return max(0.1, 0.5 * (1.0 + torch.cos(torch.tensor(progress * 3.14159)).item()))
        scheduler = torch.optim.lr_scheduler.LambdaLR(optim, lr_lambda)
        return {"optimizer": optim,
                "lr_scheduler": {"scheduler": scheduler, "interval": "step"}}

                                  transformer_layer_cls={transformer_layer_cls})

            param_dtype=torch.bfloat16,
            reduce_dtype=torch.float32,
            buffer_dtype=torch.bfloat16,
        ),
        limit_all_gathers=True,
    )

MFU (Model FLOP Utilization) Monitoring

MFU = achieved_TFLOPS / peak_TFLOPS. For a transformer: forward FLOPs ≈ 6 × N × T (N = params, T = tokens). Multiply by 3 for forward+backward. Target: >50% MFU on H100 with BF16.

import time, torch

# H100 SXM peak BF16: 989 TFLOPS
GPU_PEAK_TFLOPS = {
    "H100": 989e12,
    "A100-80G": 312e12,
    "A100-40G": 312e12,
    "V100": 130e12,
}

def estimate_model_flops(num_params: int, seq_len: int, batch_size: int) -> float:
    """Estimate FLOPs for one forward+backward pass (6×N×T rule of thumb)."""
    tokens = batch_size * seq_len
    return 6 * num_params * tokens  # factor 6 = 2 fwd + 4 bwd (remat)

class MFUMonitor:
    def __init__(self, num_params, seq_len, batch_size,
                 gpu_type="H100", log_interval=10):
        self.flops_per_step = estimate_model_flops(num_params, seq_len, batch_size)
        self.peak_flops = GPU_PEAK_TFLOPS.get(gpu_type, 989e12)
        self.log_interval = log_interval
        self._t0 = None
        self.mfu_history = []

    def start_step(self):
        if torch.cuda.is_available():
            torch.cuda.synchronize()
        self._t0 = time.perf_counter()

    def end_step(self, step):
        if torch.cuda.is_available():
            torch.cuda.synchronize()
        dt = time.perf_counter() - self._t0
        achieved = self.flops_per_step / dt
        num_gpus = torch.distributed.get_world_size() if torch.distributed.is_initialized() else 1
        mfu = achieved / (self.peak_flops * num_gpus)
        self.mfu_history.append(mfu)
        if step % self.log_interval == 0:
            avg_mfu = sum(self.mfu_history[-self.log_interval:]) / min(len(self.mfu_history), self.log_interval)
            tput = self.flops_per_step / dt / 1e12
            print(f"step={step:6d} | MFU={avg_mfu:.1%} | throughput={tput:.1f} TFLOPS/GPU | dt={dt*1000:.1f}ms")
        return mfu

5. Checkpointing at Scale

Saving 405B parameters every 1000 steps requires a strategy, not just torch.save().

StrategyHowSave TimeUse Case
Full (consolidated)Gather all shards to rank 0, save single fileSlow (all-gather)Final export, inference
ShardedEach rank saves its own shard in parallelFastMid-training resumption
Async (non-blocking)Copy to CPU, save in background threadNear-zero blockingFrequent checkpoints

Distributed Checkpoint with FSDP

import torch
import torch.distributed as dist
import torch.distributed.checkpoint as dcp
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp.fully_sharded_data_parallel import StateDictType
from torch.distributed.checkpoint.state_dict import get_state_dict, set_state_dict
import os

def save_fsdp_checkpoint(model: FSDP, optimizer, step: int, output_dir: str):
    """Save sharded FSDP checkpoint using PyTorch Distributed Checkpoint."""
    os.makedirs(output_dir, exist_ok=True)
    ckpt_dir = os.path.join(output_dir, f"step_{step:07d}")

    # Get sharded state dicts (each rank keeps its own shard)
    model_state, optim_state = get_state_dict(model, optimizer)
    state = {"model": model_state, "optimizer": optim_state, "step": step}

    # Async-capable distributed checkpoint
    storage_writer = dcp.FileSystemWriter(ckpt_dir, single_file_per_rank=True)
    dcp.save(state, storage_writer=storage_writer)

    if dist.get_rank() == 0:
        print(f"Checkpoint saved: {ckpt_dir}")


def load_fsdp_checkpoint(model: FSDP, optimizer, ckpt_dir: str):
    """Resume from sharded FSDP checkpoint."""
    model_state, optim_state = get_state_dict(model, optimizer)
    state = {"model": model_state, "optimizer": optim_state, "step": 0}

    storage_reader = dcp.FileSystemReader(ckpt_dir)
    dcp.load(state, storage_reader=storage_reader)

    set_state_dict(model, optimizer,
                   model_state_dict=state["model"],
                   optim_state_dict=state["optimizer"])
    return state["step"]

Async Checkpoint Saving

import threading, copy
from pathlib import Path

class AsyncCheckpointer:
    """Non-blocking checkpoint: copy to CPU, save in background thread."""

    def __init__(self, output_dir: str, keep_last: int = 3):
        self.output_dir = Path(output_dir)
        self.keep_last = keep_last
        self._thread = None
        self._saved = []

    def _save_worker(self, state_cpu: dict, path: Path):
        torch.save(state_cpu, path)
        self._saved.append(path)
        # Prune old checkpoints
        while len(self._saved) > self.keep_last:
            old = self._saved.pop(0)
            old.unlink(missing_ok=True)

    def save(self, model, optimizer, step: int):
        # Wait for previous async save to finish before copying
        if self._thread and self._thread.is_alive():
            self._thread.join()

        # Fast CPU copy (non-blocking from GPU perspective)
        state_cpu = {
            "model": {k: v.cpu() for k, v in model.state_dict().items()},
            "optimizer": copy.deepcopy(optimizer.state_dict()),
            "step": step,
        }
        path = self.output_dir / f"ckpt_{step:07d}.pt"
        self._thread = threading.Thread(target=self._save_worker,
                                        args=(state_cpu, path), daemon=True)
        self._thread.start()
        return path  # Returns immediately; save happens in background

    def wait(self):
        """Call at end of training to ensure last checkpoint completes."""
        if self._thread:
            self._thread.join()

6. Curriculum Learning and Data Ordering

Data order affects both convergence speed and final quality.

Curriculum learning presents easier examples first (shorter sequences, common domains) and increases difficulty over training. LLaMA 3 used a data mix that increased code and math proportions in later training phases. Key effects: faster early convergence, better final quality on hard domains, reduced loss spikes from outlier examples.

Warmup strategies: (1) Sequence length warmup — start with 512 tokens, ramp to 4096 over first 1% of tokens. (2) Domain warmup — saturate with high-quality web text first, introduce specialized domains gradually. (3) Batch size warmup — linear ramp from small to target batch size.

Custom DistributedSampler with Curriculum

import torch
from torch.utils.data import DistributedSampler
from typing import Optional, List
import math

class CurriculumDistributedSampler(DistributedSampler):
    """
    Distributed sampler with curriculum: samples by difficulty bucket,
    transitioning from easy to hard over training.
    """

    def __init__(self, dataset, difficulty_scores: List[float],
                 num_replicas=None, rank=None, shuffle=True,
                 curriculum_end_fraction=0.3, seed=42):
        super().__init__(dataset, num_replicas=num_replicas, rank=rank,
                         shuffle=shuffle, seed=seed)
        # Normalize difficulty scores [0, 1]
        scores = torch.tensor(difficulty_scores, dtype=torch.float)
        self.difficulty = (scores - scores.min()) / (scores.max() - scores.min() + 1e-8)
        self.curriculum_end_fraction = curriculum_end_fraction
        self.current_epoch = 0
        self.total_epochs = 1  # set externally before each epoch

    def set_epoch_and_total(self, epoch: int, total_epochs: int):
        self.current_epoch = epoch
        self.total_epochs = total_epochs
        super().set_epoch(epoch)

    def _compute_difficulty_threshold(self) -> float:
        """Linearly increase from 0.3 (easy) to 1.0 (all) over curriculum window."""
        progress = min(1.0, self.current_epoch / max(1, int(self.total_epochs * self.curriculum_end_fraction)))
        return 0.3 + 0.7 * progress  # allow bottom 30% initially, open up to 100%

    def __iter__(self):
        threshold = self._compute_difficulty_threshold()
        # Filter to allowed difficulty range
        eligible = (self.difficulty <= threshold).nonzero(as_tuple=True)[0].tolist()
        if len(eligible) < self.num_replicas:
            eligible = list(range(len(self.dataset)))  # fallback

        g = torch.Generator()
        g.manual_seed(self.seed + self.current_epoch)
        if self.shuffle:
            indices = [eligible[i] for i in torch.randperm(len(eligible), generator=g).tolist()]
        else:
            indices = eligible

        # Pad to be divisible by num_replicas
        padding = (self.num_replicas - len(indices) % self.num_replicas) % self.num_replicas
        indices += indices[:padding]

        # Subsample for this rank
        indices = indices[self.rank::self.num_replicas]
        return iter(indices)

    def __len__(self):
        threshold = self._compute_difficulty_threshold()
        eligible = int((self.difficulty <= threshold).sum().item())
        return math.ceil(eligible / self.num_replicas)

7. Large-Scale Training Stability

A loss spike at step 50,000 can ruin a 3-week run. Detect and recover automatically.

Training Stability Hooks

import torch, math, collections
from typing import Optional

class TrainingStabilityMonitor:
    """
    Monitors: gradient norms, loss spikes, NaN/Inf detection, rolling averages.
    """

    def __init__(self, spike_threshold=4.0, window=100, rollback_steps=500,
                 checkpoint_dir="/checkpoints"):
        self.spike_threshold = spike_threshold  # spike if loss > mean * threshold
        self.window = window
        self.rollback_steps = rollback_steps
        self.checkpoint_dir = checkpoint_dir
        self.loss_history = collections.deque(maxlen=window)
        self.grad_norm_history = collections.deque(maxlen=window)
        self.spike_count = 0

    def check_loss(self, loss: float, step: int) -> bool:
        """Returns True if spike detected."""
        if math.isnan(loss) or math.isinf(loss):
            print(f"[STABILITY] NaN/Inf loss at step {step}! Triggering rollback.")
            return True
        self.loss_history.append(loss)
        if len(self.loss_history) >= 20:
            rolling_mean = sum(list(self.loss_history)[:-5]) / (len(self.loss_history) - 5)
            if loss > rolling_mean * self.spike_threshold:
                self.spike_count += 1
                print(f"[STABILITY] Loss spike at step {step}: {loss:.4f} vs mean {rolling_mean:.4f}")
                return True
        return False

    def compute_grad_norm(self, model: torch.nn.Module,
                          norm_type: float = 2.0) -> float:
        """Compute total gradient norm across all parameters."""
        total_norm = 0.0
        for p in model.parameters():
            if p.grad is not None:
                if torch.isnan(p.grad).any() or torch.isinf(p.grad).any():
                    print("[STABILITY] NaN/Inf in gradient!")
                    return float('inf')
                param_norm = p.grad.detach().data.norm(norm_type)
                total_norm += param_norm.item() ** norm_type
        total_norm = total_norm ** (1.0 / norm_type)
        self.grad_norm_history.append(total_norm)
        return total_norm

    def get_smoothed_loss(self, beta=0.98) -> Optional[float]:
        """Exponential moving average of loss (like fast.ai)."""
        if not self.loss_history:
            return None
        ema = None
        for i, l in enumerate(self.loss_history):
            if ema is None:
                ema = l
            else:
                ema = beta * ema + (1 - beta) * l
        # Bias correction
        n = len(self.loss_history)
        return ema / (1 - beta ** n)

    def log_metrics(self, step: int) -> dict:
        grad_norm = (sum(self.grad_norm_history) / len(self.grad_norm_history)
                     if self.grad_norm_history else 0.0)
        return {
            "stability/grad_norm_avg": grad_norm,
            "stability/loss_smooth": self.get_smoothed_loss() or 0.0,
            "stability/spike_count": self.spike_count,
        }
Loss Spike Recovery: When a spike is detected: (1) rollback to last good checkpoint, (2) skip or re-sample the problematic batch, (3) reduce LR temporarily by 50%, (4) resume. LLaMA 3 training saw ~12 loss spikes over the full run — all recovered automatically within 500 steps.

8. Scaling Laws Applied

How to optimally allocate compute between model size and training tokens.

The Chinchilla paper (Hoffmann et al., 2022) showed that optimal training requires scaling tokens proportionally with parameters: N_opt ≈ C / (6 × T_opt) where C is compute budget (FLOPs), N is parameters, T is tokens. The optimal ratio is roughly 20 tokens per parameter for pure Chinchilla-optimal training. LLaMA 3 deliberately overtrained (15T tokens for 8B/70B) for better inference efficiency.

Scaling Law Calculator

#!/usr/bin/env python3
"""
Chinchilla scaling law calculator.
Hoffmann et al. 2022: L(N, D) = E + A/N^alpha + B/D^beta
Optimal: N_opt = (C / (6 * 20))^0.5 roughly
"""
import math

# Chinchilla constants (from paper Table 2, fit A)
E = 1.69  # irreducible loss
A = 406.4
B = 410.7
ALPHA = 0.34
BETA = 0.28

def chinchilla_loss(n_params: float, n_tokens: float) -> float:
    """Predict cross-entropy loss for model with n_params trained on n_tokens."""
    return E + A / (n_params ** ALPHA) + B / (n_tokens ** BETA)

def optimal_allocation(compute_budget_flops: float) -> dict:
    """
    Given FLOPs budget C, find optimal N and D.
    C ≈ 6 * N * D (forward + backward for non-embedding params)
    Chinchilla: D_opt ≈ 20 * N_opt
    """
    # From Chinchilla paper: N_opt = (C / (6 * 20))^0.5
    n_opt = math.sqrt(compute_budget_flops / (6 * 20))
    d_opt = compute_budget_flops / (6 * n_opt)
    predicted_loss = chinchilla_loss(n_opt, d_opt)
    return {
        "optimal_params": n_opt,
        "optimal_tokens": d_opt,
        "tokens_per_param": d_opt / n_opt,
        "predicted_loss": predicted_loss,
    }

def compute_budget(n_gpus: int, gpu_tflops: float, hours: float,
                   mfu: float = 0.45) -> float:
    """Estimate FLOPs from cluster config."""
    return n_gpus * gpu_tflops * 1e12 * hours * 3600 * mfu

# Example: 1024 H100s for 30 days at 45% MFU
if __name__ == "__main__":
    budgets = [
        ("1024 H100 × 7 days",  compute_budget(1024,  989, 7*24)),
        ("1024 H100 × 30 days", compute_budget(1024,  989, 30*24)),
        ("4096 H100 × 90 days", compute_budget(4096,  989, 90*24)),
    ]
    for label, C in budgets:
        r = optimal_allocation(C)
        print(f"\n{label}")
        print(f"  Budget:          {C:.2e} FLOPs")
        print(f"  Optimal N:       {r['optimal_params']/1e9:.1f}B params")
        print(f"  Optimal tokens:  {r['optimal_tokens']/1e12:.1f}T tokens")
        print(f"  Tokens/param:    {r['tokens_per_param']:.0f}x")
        print(f"  Predicted loss:  {r['predicted_loss']:.4f}")

Summary & Key Takeaways

Combined with Chapter 8 (DDP, ZeRO, FSDP, mixed precision), you now have the full picture of modern distributed training infrastructure.

From Chapter 8 (Foundations)

  • DDP: gradient AllReduce across replicas
  • ZeRO Stage 1/2/3: shard optimizer/grad/params
  • FSDP: PyTorch-native ZeRO-3 equivalent
  • Mixed precision: BF16 forward, FP32 master weights
  • Gradient checkpointing: memory vs compute trade-off

From Chapter 8B (Advanced)

  • 3D parallelism: TP within node, PP+DP across nodes
  • Megatron-LM: sequence parallelism, selective recomputation
  • Profiling: MFU is the single most important metric
  • Async checkpointing: save at full frequency, near-zero overhead
  • Scaling laws: 20 tokens/param optimal; overtrain for inference

Decision Framework

  1. Model <7B: DDP + ZeRO-2. Add FSDP if VRAM is tight. No need for 3D parallelism.
  2. 7B–70B: FSDP or DeepSpeed ZeRO-3. Consider TP=4 if on NVLink nodes. Megatron-LM for production scale.
  3. 70B–405B: Megatron-LM with TP=8 (within node), PP=4–16 (across nodes). Interleaved 1F1B schedule mandatory.
  4. 1T+: Add expert parallelism (MoE), context parallelism, FP8 compute. Vertical pipeline parallelism (VPP) to minimize bubble.
  5. Always: Measure MFU first. Profile before optimizing. Async checkpoint every 15–30 min. Monitor grad norms and loss for spikes.
