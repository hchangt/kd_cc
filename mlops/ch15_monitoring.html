1. Why ML Monitoring is Different

Traditional software monitoring answers: is the service up? ML monitoring must also answer: is the model still correct? A model can serve predictions with 200 OK while silently degrading — no exception is raised when a recommendation engine starts suggesting irrelevant content because user behavior shifted.

Failure taxonomy

Three distinct failure modes drive different detection strategies:

  • Data drift — input feature distribution shifts (X changes, model relationship P(Y|X) stays same)
  • Concept drift — the underlying relationship changes (P(Y|X) shifts, model is now wrong)
  • Model decay — compound degradation over time from both sources; often noticed only via business KPI drop
Silent failures are the real risk. In a recommendation system, CTR may drop 8% over 6 weeks while all infrastructure health checks stay green. No alarm fires. Revenue erodes quietly until a manual analysis uncovers stale embeddings trained before a major catalog refresh.

3. Prometheus & Grafana Stack

Prometheus pulls (scrapes) metrics from HTTP endpoints every N seconds. Each ML service exposes a /metrics endpoint using prometheus-client. Prometheus stores time-series in its TSDB; Grafana queries it via PromQL.

class MLMetricsCollector:
    """Collects and exposes ML-specific Prometheus metrics."""

    def __init__(self, model_name: str, model_version: str, window_size: int = 1000):
        self.model_name = model_name
        self.model_version = model_version
        self.window_size = window_size
        self._feature_buffers: dict[str, list] = {}
        self._training_baselines: dict[str, np.ndarray] = {}

    def record_prediction(self, score: float, predicted_class: str, latency: float):
        PREDICTION_COUNTER.labels(
            model_name=self.model_name,
            model_version=self.model_version,
            outcome_class=predicted_class
        ).inc()
        PREDICTION_SCORE.labels(model_name=self.model_name).observe(score)
        REQUEST_LATENCY.labels(
            model_name=self.model_name, endpoint="/predict"
        ).observe(latency)

    def record_features(self, features: dict[str, float]):
        for name, value in features.items():
            buf = self._feature_buffers.setdefault(name, [])
            buf.append(value)
            if len(buf) > self.window_size:
                buf.pop(0)
            if len(buf) >= 50:  # enough data
                arr = np.array(buf)
                FEATURE_MEAN.labels(
                    model_name=self.model_name, feature_name=name
                ).set(float(np.mean(arr)))
                FEATURE_STD.labels(
                    model_name=self.model_name, feature_name=name
                ).set(float(np.std(arr)))

    def load_training_baseline(self, feature_name: str, baseline_values: np.ndarray):
        self._training_baselines[feature_name] = baseline_values

    def update_drift_scores(self):
        for name, buf in self._feature_buffers.items():
            if name in self._training_baselines and len(buf) >= 100:
                psi = compute_psi(
                    np.array(self._training_baselines[name]),
                    np.array(buf)
                )
                DRIFT_SCORE.labels(
                    model_name=self.model_name, feature_name=name
                ).set(psi)

4. Data Drift Detection

Detecting drift requires choosing a reference window (training data or a known-good production window) and comparing the current serving window using a statistical test.

PSI (Population Stability Index)

PSI is the industry standard for tabular feature drift, especially in finance/risk. It measures the symmetric KL divergence between two distributions.

PSI = ∑(Actual% - Expected%) × ln(Actual% / Expected%)
PSI ValueInterpretationActionVisual
< 0.1No significant shiftMonitor normallyGREEN
0.1 – 0.2Moderate shift — investigateReview feature source, check upstream pipelineYELLOW
> 0.2Significant shift — action requiredTrigger retraining evaluation, alert teamRED
> 0.25Critical shiftConsider model rollback, urgent investigationCRITICAL

PSI Calculation from Scratch

# drift_detection.py
import numpy as np
from typing import Optional

def compute_psi(
    reference: np.ndarray,
    current: np.ndarray,
    n_bins: int = 10,
    epsilon: float = 1e-8
) -> float:
    """
    Compute Population Stability Index between reference and current distributions.
    Works for continuous and ordinal features.
    """
    # Use reference distribution to define bin edges
    _, bin_edges = np.histogram(reference, bins=n_bins)
    # Extend edges slightly to include all values
    bin_edges[0] -= 1e-6
    bin_edges[-1] += 1e-6

    ref_counts, _ = np.histogram(reference, bins=bin_edges)
    cur_counts, _ = np.histogram(current, bins=bin_edges)

    # Convert to proportions, add epsilon to avoid log(0)
    ref_pct = ref_counts / len(reference) + epsilon
    cur_pct = cur_counts / len(current) + epsilon

    # PSI formula
    psi_values = (cur_pct - ref_pct) * np.log(cur_pct / ref_pct)
    return float(np.sum(psi_values))


def compute_psi_categorical(
    reference: np.ndarray,
    current: np.ndarray,
    epsilon: float = 1e-8
) -> float:
    """PSI for categorical features."""
    all_categories = set(reference) | set(current)
    ref_total = len(reference)
    cur_total = len(current)

    psi = 0.0
    for cat in all_categories:
        ref_pct = (np.sum(reference == cat) / ref_total) + epsilon
        cur_pct = (np.sum(current == cat) / cur_total) + epsilon
        psi += (cur_pct - ref_pct) * np.log(cur_pct / ref_pct)
    return psi


def interpret_psi(psi: float) -> str:
    if psi < 0.1:
        return "stable"
    elif psi < 0.2:
        return "moderate_drift"
    else:
        return "significant_drift"

KS Test with scipy

# ks_drift.py
from scipy import stats
import numpy as np
import pandas as pd
from dataclasses import dataclass

@dataclass
class DriftResult:
    feature: str
    test: str
    statistic: float
    p_value: float
    drifted: bool
    psi: Optional[float] = None

def ks_drift_detection(
    reference_df: pd.DataFrame,
    current_df: pd.DataFrame,
    numeric_features: list[str],
    alpha: float = 0.05
) -> list[DriftResult]:
    results = []
    for feat in numeric_features:
        ref_vals = reference_df[feat].dropna().values
        cur_vals = current_df[feat].dropna().values

        # Two-sample KS test
        ks_stat, p_val = stats.ks_2samp(ref_vals, cur_vals)

        # Also compute PSI for interpretability
        psi_val = compute_psi(ref_vals, cur_vals)

        results.append(DriftResult(
            feature=feat,
            test="ks_2samp",
            statistic=float(ks_stat),
            p_value=float(p_val),
            drifted=(p_val < alpha),
            psi=psi_val
        ))
    return results


def chi2_drift_categorical(
    reference_df: pd.DataFrame,
    current_df: pd.DataFrame,
    categorical_features: list[str],
    alpha: float = 0.05
) -> list[DriftResult]:
    """Chi-squared test for categorical feature drift."""
    results = []
    for feat in categorical_features:
        all_cats = set(reference_df[feat].unique()) | set(current_df[feat].unique())
        ref_counts = reference_df[feat].value_counts().reindex(all_cats, fill_value=0)
        cur_counts = current_df[feat].value_counts().reindex(all_cats, fill_value=0)

        chi2, p_val = stats.chisquare(cur_counts, f_exp=ref_counts * len(current_df) / len(reference_df))
        results.append(DriftResult(
            feature=feat, test="chi2",
            statistic=float(chi2), p_value=float(p_val),
            drifted=(p_val < alpha)
        ))
    return results

5. Evidently AI

Evidently is an open-source ML observability library for generating data and model quality reports. It works both offline (HTML/JSON reports) and online (integrated into a monitoring service).

Data Drift Report

# evidently_reports.py
import pandas as pd
from evidently.report import Report
from evidently.metric_preset import DataDriftPreset, DataQualityPreset
from evidently.metrics import (
    DatasetDriftMetric,
    DataDriftTable,
    ColumnDriftMetric,
    ColumnSummaryMetric,
)

def generate_drift_report(
    reference_df: pd.DataFrame,
    current_df: pd.DataFrame,
    output_path: str = "drift_report.html"
) -> dict:
    """Generate and save an Evidently data drift report."""
    report = Report(metrics=[
        DataDriftPreset(drift_share=0.3),    # alert if >30% features drift
        DataQualityPreset(),
        ColumnDriftMetric(column_name="user_age"),
        ColumnDriftMetric(column_name="session_duration"),
        ColumnSummaryMetric(column_name="purchase_amount"),
    ])

    report.run(reference_data=reference_df, current_data=current_df)
    report.save_html(output_path)

    # Extract JSON summary for programmatic use
    result = report.as_dict()
    drift_metric = result["metrics"][0]["result"]
    return {
        "dataset_drift": drift_metric["dataset_drift"],
        "drift_share": drift_metric["share_of_drifted_columns"],
        "drifted_columns": drift_metric.get("number_of_drifted_columns", 0),
    }

Evidently Test Suite (Automated Checks)

# evidently_tests.py
from evidently.test_suite import TestSuite
from evidently.test_preset import DataDriftTestPreset, DataQualityTestPreset
from evidently.tests import (
    TestNumberOfDriftedColumns,
    TestShareOfDriftedColumns,
    TestColumnDrift,
    TestNumberOfMissingValues,
    TestHighlyCorrelatedColumns,
)

def run_quality_gates(
    reference_df: pd.DataFrame,
    current_df: pd.DataFrame,
    critical_features: list[str]
) -> tuple[bool, dict]:
    """Returns (passed, details). Use in CI/CD or scheduled checks."""
    suite = TestSuite(tests=[
        DataDriftTestPreset(drift_share=0.3),
        DataQualityTestPreset(),
        TestNumberOfDriftedColumns(lt=5),       # fail if >5 features drift
        TestShareOfDriftedColumns(lt=0.3),
        TestNumberOfMissingValues(lt=1000),
        *[TestColumnDrift(column_name=f) for f in critical_features],
    ])

    suite.run(reference_data=reference_df, current_data=current_df)
    result = suite.as_dict()

    all_passed = all(
        t["result"]["status"] == "SUCCESS"
        for t in result["tests"]
    )
    return all_passed, result

6. Model Performance Monitoring

The hardest problem in ML monitoring: ground truth labels arrive hours, days, or weeks after prediction. You cannot compute accuracy in real time for most use cases.

Performance Monitoring Service

# performance_monitor.py
import numpy as np
import pandas as pd
from prometheus_client import Gauge, Histogram
from dataclasses import dataclass
from scipy.stats import entropy

PREDICTION_ENTROPY = Gauge(
    "ml_prediction_entropy_mean",
    "Mean Shannon entropy of prediction probability vectors",
    ["model_name"]
)
ACCURACY_GAUGE = Gauge(
    "ml_accuracy_windowed",
    "Accuracy on most recent labeled window",
    ["model_name"]
)
AUC_GAUGE = Gauge(
    "ml_auc_windowed",
    "AUC-ROC on most recent labeled window",
    ["model_name"]
)

class PerformanceMonitor:
    def __init__(self, model_name: str, window_size: int = 5000):
        self.model_name = model_name
        self.window_size = window_size
        self._predictions: list[np.ndarray] = []   # probability vectors
        self._labeled_buffer: list[dict] = []

    def record_prediction_proba(self, proba: np.ndarray):
        """Record a probability vector for entropy monitoring."""
        self._predictions.append(proba)
        if len(self._predictions) > self.window_size:
            self._predictions.pop(0)

        if len(self._predictions) % 100 == 0:
            entropies = [entropy(p + 1e-10) for p in self._predictions[-1000:]]
            PREDICTION_ENTROPY.labels(model_name=self.model_name).set(
                float(np.mean(entropies))
            )

    def record_labeled_outcome(self, prediction_id: str, label: int,
                               predicted_class: int, score: float):
        """Store ground truth when it arrives."""
        self._labeled_buffer.append({
            "id": prediction_id,
            "label": label,
            "predicted": predicted_class,
            "score": score
        })
        if len(self._labeled_buffer) > self.window_size:
            self._labeled_buffer.pop(0)

        if len(self._labeled_buffer) >= 200:
            self._update_supervised_metrics()

    def _update_supervised_metrics(self):
        from sklearn.metrics import accuracy_score, roc_auc_score
        df = pd.DataFrame(self._labeled_buffer[-2000:])
        acc = accuracy_score(df["label"], df["predicted"])
        try:
            auc = roc_auc_score(df["label"], df["score"])
        except Exception:
            auc = 0.0
        ACCURACY_GAUGE.labels(model_name=self.model_name).set(acc)
        AUC_GAUGE.labels(model_name=self.model_name).set(auc)

7. WhyLogs / WhyLabs

WhyLogs produces compact statistical sketches ("profiles") of datasets using approximate algorithms (HLL, KLL, frequent items). Profiles are orders of magnitude smaller than raw data and can be merged, differenced, and shipped to WhyLabs for visualization.

Whylogs Profile Creation

# whylogs_profiling.py
import whylogs as why
import pandas as pd
from whylogs.core.constraints import ConstraintsBuilder
from whylogs.core.constraints.factories import (
    no_missing_values,
    column_is_in_range,
)

def profile_batch(df: pd.DataFrame, dataset_name: str) -> why.DatasetProfileView:
    """Create a whylogs profile for a batch of data."""
    result = why.log(df)
    profile_view = result.view()
    return profile_view


def profile_with_constraints(df: pd.DataFrame) -> tuple[why.DatasetProfileView, bool]:
    """Profile and validate data against defined constraints."""
    result = why.log(df)

    builder = ConstraintsBuilder(dataset_profile_view=result.view())
    builder.add_constraint(no_missing_values(column_name="user_id"))
    builder.add_constraint(column_is_in_range(column_name="age", lower=0, upper=120))
    builder.add_constraint(column_is_in_range(column_name="score", lower=0.0, upper=1.0))

    constraints = builder.build()
    report = constraints.generate_constraints_report()

    passed = all(c.passed for c in report)
    return result.view(), passed


def save_profile_locally(profile_view, path: str):
    profile_view.write(path)


def compare_profiles(reference_profile, current_profile) -> dict:
    """Compute drift metrics by comparing two profiles."""
    ref_cols = reference_profile.get_columns()
    cur_cols = current_profile.get_columns()
    drift_results = {}
    for col_name in ref_cols:
        if col_name in cur_cols:
            ref_dist = ref_cols[col_name].to_summary_dict()
            cur_dist = cur_cols[col_name].to_summary_dict()
            drift_results[col_name] = {
                "ref_mean": ref_dist.get("distribution/mean"),
                "cur_mean": cur_dist.get("distribution/mean"),
                "ref_nulls": ref_dist.get("counts/null"),
                "cur_nulls": cur_dist.get("counts/null"),
            }
    return drift_results

8. Log Aggregation for ML

Structured logs are the foundation for post-hoc debugging, audit trails, and training data recovery. Every prediction should produce a structured log entry containing the request ID, model version, feature values, and prediction output.

Structured Logging with structlog

# ml_logging.py
import structlog
import time
import uuid
from functools import wraps

# Configure structlog once at app startup
structlog.configure(
    processors=[
        structlog.stdlib.add_log_level,
        structlog.stdlib.add_logger_name,
        structlog.processors.TimeStamper(fmt="iso"),
        structlog.processors.StackInfoRenderer(),
        structlog.processors.format_exc_info,
        structlog.processors.JSONRenderer(),  # always emit JSON
    ],
    wrapper_class=structlog.make_filtering_bound_logger(20),  # INFO
    context_class=dict,
    logger_factory=structlog.PrintLoggerFactory(),
)

log = structlog.get_logger()


def log_prediction(
    model_name: str,
    model_version: str,
    request_id: str,
    features: dict,
    prediction: float,
    predicted_class: str,
    latency_ms: float,
    user_id: str | None = None,
):
    """Emit a structured JSON log line per prediction."""
    log.info(
        "ml.prediction",
        request_id=request_id,
        model_name=model_name,
        model_version=model_version,
        user_id=user_id,
        predicted_class=predicted_class,
        prediction_score=round(prediction, 6),
        latency_ms=round(latency_ms, 2),
        # Log feature values — redact PII as needed
        features={k: round(v, 4) if isinstance(v, float) else v
                  for k, v in features.items()},
    )


def prediction_instrumented(model_name: str, model_version: str):
    """Decorator: auto-logs prediction + latency for any predict() function."""
    def decorator(predict_fn):
        @wraps(predict_fn)
        def wrapper(features: dict, **kwargs):
            request_id = str(uuid.uuid4())
            t0 = time.perf_counter()
            try:
                result = predict_fn(features, **kwargs)
                latency_ms = (time.perf_counter() - t0) * 1000
                log_prediction(
                    model_name=model_name,
                    model_version=model_version,
                    request_id=request_id,
                    features=features,
                    prediction=result.get("score", 0.0),
                    predicted_class=result.get("class", "unknown"),
                    latency_ms=latency_ms,
                )
                return result
            except Exception as exc:
                log.error(
                    "ml.prediction_error",
                    request_id=request_id,
                    model_name=model_name,
                    model_version=model_version,
                    error=str(exc),
                    exc_info=True,
                )
                raise
        return wrapper
    return decorator

-- Query 1: P95 latency by model version (last 1 hour)
fields @timestamp, model_name, model_version, latency_ms
| filter ispresent(latency_ms)
| stats pct(latency_ms, 95) as p95_latency,
        pct(latency_ms, 50) as p50_latency,

  by model_name, model_version
| sort p95_latency desc

-- Query 2: Prediction score distribution bucketed
fields @timestamp, prediction_score
| filter ispresent(prediction_score)
| stats count(*) as cnt
  by bin(prediction_score, 0.1) as score_bucket
| sort score_bucket asc

-- Query 3: Error rate by model (last 15 min)
fields @timestamp, model_name, @message
| filter @message like /ml.prediction_error/
| stats count(*) as error_count by model_name
| sort error_count desc

-- Query 4: Feature null rate (detect upstream data issues)
fields @timestamp, features.user_age, features.session_duration
| stats
    (count_distinct(requestId) - count(features.user_age)) / count_distinct(requestId) * 100
      as user_age_null_pct,
    (count_distinct(requestId) - count(features.session_duration)) / count_distinct(requestId) * 100
      as session_null_pct
  by bin(5m)
| sort @timestamp desc

Summary & Key Takeaways

Key Takeaways

  • 1.ML monitoring extends classical monitoring. Software health checks are necessary but not sufficient — you must track statistical properties of inputs and outputs, not just service availability.
  • 2.Silent failures are the primary risk. A degrading model returns HTTP 200. Build proactive drift detection; don't wait for business KPIs to alert you.
  • 3.PSI is the practical drift metric. Use PSI for tabular features (threshold: 0.1/0.2), KS test for continuous distributions, chi-squared for categorical. Combine with p-values for statistical rigor.
  • 4.Four pillars: metrics, logs, traces, data quality. Each serves a different debugging scenario. Integrate all four before a production incident forces you to.
  • 5.Ground truth delay is unavoidable — use proxy metrics. Prediction entropy and distribution shift are imperfect but actionable. Design label feedback loops into your system architecture from day one.
  • 6.Evidently for batch, WhyLogs for streaming. Evidently excels at scheduled HTML reports and CI/CD quality gates. WhyLogs profiles are memory-efficient for high-throughput online inference.
  • 7.Structured logging is non-negotiable. Log every prediction as a structured JSON event with request ID, feature snapshot, model version, and prediction. This data powers both debugging and offline drift analysis.
