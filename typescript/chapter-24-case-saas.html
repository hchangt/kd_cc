1. Architecture Overview

DocuMind lets users upload PDFs, ask questions in natural language, and receive AI-generated answers grounded in their documents. The system combines a Next.js frontend, a Hono API server, a pgvector database for semantic search, Redis for rate limiting and job queues, Anthropic for inference, Stripe for billing, and S3 for file storage.

DocuMind system architecture — all layers typed end-to-end via the shared package
◆
Architecture Note

The key insight: a packages/shared library contains every domain type, Zod schema, and API contract. Both the Next.js client and the Hono server import from it — no type drift, no duplication.

2. Monorepo Structure

We use pnpm workspaces. Three packages: web (Next.js), api (Hono), and shared (types + schemas). The shared package is the contract layer — both apps depend on it, never on each other.

3. Database Schema (Prisma)

Five core models. The DocumentChunk model holds the pgvector embedding column — Prisma's Unsupported type lets us declare it without native support, while raw queries handle vector operations.

Prisma api/prisma/schema.prisma — key models 
model User { id String @id @default(cuid())
  email String @unique; workspaceId String
  workspace Workspace @relation(fields: [workspaceId], references: [id]) }

model Document { id String @id @default(cuid())
  name String; s3Key String; status DocumentStatus @default(PROCESSING)
  chunks DocumentChunk[]; workspaceId String }

model DocumentChunk { id String @id @default(cuid())
  content String; pageNum Int; documentId String
  embedding Unsupported("vector(1536)")?    // pgvector
  document Document @relation(fields: [documentId], references: [id]) }

model Subscription { id String @id; stripeCustomerId String @unique
  plan Plan @default(FREE); status SubStatus; workspaceId String @unique }
ⓘ
Info — pgvector in Neon

Enable the extension with CREATE EXTENSION vector; and create an HNSW index: CREATE INDEX ON "DocumentChunk" USING hnsw (embedding vector_cosine_ops);. Queries use raw SQL via prisma.$queryRaw.

4. Document Processing Pipeline

When a document upload completes, a background job processes it through five stages: download from S3, extract text, split into chunks, embed via OpenAI, store in pgvector, generate a Claude summary, then mark ready.

TS api/src/services/pipeline.ts 
export async function processDocument(docId: string): Promise {
  const doc = await prisma.document.findUniqueOrThrow({ where: { id: docId } })
  const buffer = await downloadFromS3(doc.s3Key)
  const text = await extractText(buffer)
  const chunks = chunkText(text, { size: 512, overlap: 64 })
  const embeddings = await embedBatch(chunks.map(c => c.content))
  await storeChunks(docId, chunks, embeddings)          // raw SQL + pgvector
  const summary = await summarizeWithClaude(text.slice(0, 8000))
  await prisma.document.update({
    where: { id: docId },
    data: { status: 'READY', summary }
  })
}
◆
Lesson Learned

Run the pipeline in a separate worker process (BullMQ + Redis), not inside the HTTP request. A PDF processing job can take 30–120 seconds. The API endpoint only enqueues the job and returns immediately.

5. RAG Query Engine

Retrieval-Augmented Generation: embed the user's question, find the nearest document chunks via cosine similarity, then stream a Claude response grounded in those chunks.

TS api/src/services/rag.ts 
export async function* ragQuery(
  question: string, docId: string
): AsyncGenerator {
  const qEmbedding = await embed(question)
  const chunks = await prisma.$queryRaw`
    SELECT content, 1 - (embedding <=> ${qEmbedding}::vector) AS score
    FROM "DocumentChunk" WHERE "documentId" = ${docId}
    ORDER BY embedding <=> ${qEmbedding}::vector LIMIT 5`
  const context = chunks.map(c => c.content).join('\n\n')
  const stream = await anthropic.messages.stream({
    model: 'claude-opus-4-5', max_tokens: 1024,
    messages: [{ role: 'user', content:
      `Context:\n${context}\n\nQuestion: ${question}` }]
  })
  for await (const chunk of stream) {
    if (chunk.type === 'content_block_delta') yield chunk.delta.text ?? ''
  }
}
★
AI Era Pattern

The generator signature AsyncGenerator<string> composes cleanly: the Hono route pipes it to an SSE response, the Next.js page reads it via the Vercel AI SDK. The streaming contract is typed, not ad-hoc.

async function uploadFile(file: File) {
  // 1. Get presigned URL from our API
  const { uploadUrl, s3Key, docId } =
    await api.documents.presign({ name: file.name, size: file.size })
  // 2. PUT directly to S3 — never through our server
  await fetch(uploadUrl, { method: 'PUT', body: file,
    headers: { 'Content-Type': file.type } })
  // 3. Trigger processing pipeline
  await api.documents.process(docId)
  return docId
}
✓
Tip — Presigned Uploads

Never proxy file uploads through your API server. A 50 MB PDF would tie up a server thread for seconds. Presigned S3 URLs let the browser upload directly to S3; your API only authorizes the operation.

Webhook Handler

TS api/src/routes/billing.ts — webhook 
app.post('/billing/webhook', async (c) => {
  const sig = c.req.header('stripe-signature')!
  const event = stripe.webhooks.constructEvent(
    await c.req.arrayBuffer(), sig, env.STRIPE_WEBHOOK_SECRET)
  if (event.type === 'customer.subscription.updated') {
    const sub = event.data.object
    await prisma.subscription.upsert({
      where: { stripeCustomerId: sub.customer as string },
      update: { plan: stripePlanToPlan(sub), status: sub.status },
      create: { stripeCustomerId: sub.customer as string,
        plan: stripePlanToPlan(sub), status: sub.status,
        workspaceId: sub.metadata.workspaceId }
    })
  }
  return c.json({ received: true })
})
⚠
Warning — Webhook Security

Always verify the Stripe signature with stripe.webhooks.constructEvent. Never read plan status from the checkout success redirect URL — that is easily spoofed. Trust only webhook events.

8. API Key System

Developers can query DocuMind programmatically. API keys are stored as bcrypt hashes. The middleware validates the key and attaches the workspace to the request context.

TS api/src/middleware/apiKey.ts 
export const apiKeyAuth: MiddlewareHandler = async (c, next) => {
  const key = c.req.header('x-api-key')
  if (!key) return c.json({ code: 'MISSING_KEY' }, 401)
  const prefix = key.slice(0, 8)
  const record = await prisma.apiKey.findFirst({ where: { prefix } })
  if (!record || !await bcrypt.compare(key, record.hash))
    return c.json({ code: 'INVALID_KEY' }, 401)
  c.set('workspaceId', record.workspaceId)
  await next()
}

Rate Limiting

TS api/src/middleware/rateLimit.ts 
export const rateLimit = (rpm: number): MiddlewareHandler => async (c, next) => {
  const key = `rl:${c.var.workspaceId}`
  const count = await redis.incr(key)
  if (count === 1) await redis.expire(key, 60)
  if (count > rpm) return c.json({ code: 'RATE_LIMITED' }, 429)
  await next()
}

10. Key TypeScript Patterns Used

  • Shared contract package One source of truth for domain types, Zod schemas, and API response shapes. Eliminates frontend/backend drift at compile time.
  • Discriminated unions for status 'processing' | 'ready' | 'error' on Document.status forces exhaustive handling in every switch — no forgotten error states.
  • AsyncGenerator for streaming AsyncGenerator<string> from the RAG engine composes with any streaming transport (SSE, WebSocket, NDJSON) without changing the core logic.
  • Branded types for IDs type DocumentId = string & { readonly __brand: 'DocumentId' } prevents passing a WorkspaceId where a DocumentId is expected — caught at compile time, not runtime.
  • Type-safe API client from shared types A factory function generates a fully-typed client directly from the shared route definitions — no separate schema file, no code generation step.

Type-Safe API Client

TS packages/shared/src/api.ts 
import type { Document, ChatMessage, Workspace } from './types'

export function createApiClient(baseUrl: string) {
  const get = (path: string) =>
    fetch(`${baseUrl}${path}`).then(r => r.json() as Promise)
  const post = (path: string, body: unknown) =>
    fetch(`${baseUrl}${path}`, { method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(body) }).then(r => r.json() as Promise)
  return {
    documents: {
      list: (wsId: string) => get(`/workspaces/${wsId}/documents`),
      presign: (body: { name: string; size: number }) =>
        post<{ uploadUrl: string; s3Key: string; docId: string }>('/documents/presign', body),
    },
    workspace: { get: (id: string) => get(`/workspaces/${id}`) },
  }
}
◆
Lesson Learned — The Shared Package Pays Off

When we renamed Document.status values from lowercase to uppercase to match Prisma enums, TypeScript found 23 mismatches across the frontend and API in one compilation pass. Without shared types that would have been 23 runtime bugs discovered in production.
