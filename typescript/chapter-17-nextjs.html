What is Next.js?

Next.js is the React framework from Vercel. It handles routing, rendering, data fetching, bundling, and deployment — everything you'd otherwise wire together yourself. The key insight: your frontend and backend live in one TypeScript codebase, sharing types from database to component.

App Router vs Pages Router

Next.js 13 introduced the App Router, a ground-up rethink based on React Server Components. It is the present and the future. The Pages Router still works and won't be removed, but all new features land in the App Router first.

Feature App Router Pages Router
Server Components Default No
Nested Layouts Native Manual
Server Actions Yes No
Streaming / Suspense Native Limited
Data fetching async/await in components getServerSideProps / getStaticProps

Getting started

terminal bash 
pnpm create next-app@latest my-app --typescript --tailwind --app --src-dir
cd my-app && pnpm dev
💡
Tip

Always pass --typescript. Next.js ships with a built-in TypeScript plugin that provides type-checking in the editor for Next.js-specific APIs like generateMetadata, params, and searchParams.

Environment variables

Variables prefixed NEXT_PUBLIC_ are bundled into the client. Everything else is server-only.

.env.local env 
DATABASE_URL=postgres://localhost/myapp     # server only
NEXT_PUBLIC_API_URL=https://api.example.com # exposed to browser
⚠️
Warning

TypeScript does not know which env vars exist. Use a validation library like @t3-oss/env-nextjs to parse and type your environment at startup — this catches missing secrets at build time instead of runtime.

App Router File Conventions

The App Router uses special filenames within route directories to control rendering. Each file exports a React component with a specific signature enforced by TypeScript.

File Purpose Key Props
page.tsx Unique UI for a route — makes the route publicly accessible params, searchParams
layout.tsx Shared UI that wraps child routes, persists on navigation children: React.ReactNode
loading.tsx Suspense fallback shown while the page streams in —
error.tsx Error boundary for the route segment — must be 'use client' error: Error, reset()
not-found.tsx Rendered when notFound() is called —
route.ts HTTP endpoint (API route) — no UI GET, POST, … exports
middleware.ts Runs before every request (root-level only) NextRequest

Dynamic routes & route groups

app/users/[id]/page.tsx TypeScript 
// Dynamic segment: [id] → params.id is typed as string
type Props = {
  params: Promise<{ id: string }>;      // Next.js 15: params is a Promise
  searchParams: Promise<{ tab?: string }>;
};

export default async function UserPage({ params }: Props) {
  const { id } = await params;
  const user = await fetchUser(id);
  return <UserProfile user={user} />;
}
✨
New in Next.js 15

params and searchParams are now Promises. Await them before use. The TypeScript plugin will flag synchronous access as a type error.

Route groups with (auth) — parentheses exclude the segment from the URL but allow a shared layout:

app/
├── (marketing)/ # URL: / — shared marketing layout
│ ├── layout.tsx
│ └── page.tsx
└── (auth)/ # URL: /login, /register
    ├── layout.tsx
    ├── login/page.tsx
    └── register/page.tsx

Server Components vs Client Components

This is the most important mental model in Next.js. Every component in the App Router is a Server Component by default. Server Components render on the server and send HTML — zero JavaScript shipped to the client. Use 'use client' only when you need interactivity.

Server / Client Component Boundary

Server Component — async data fetching

app/blog/page.tsx TypeScript 
// No 'use client' = Server Component
import { db } from '@/lib/db';

export default async function BlogPage() {
  // Direct DB access — runs server-side, never exposed to client
  const posts = await db.post.findMany({ orderBy: { createdAt: 'desc' } });

  return (
    <ul>
      {posts.map(post => (
        <li key={post.id}><a href={`/blog/${post.slug}`}>{post.title}</a></li>
      ))}
    </ul>
  );
}

Client Component — hooks & events

components/like-button.tsx TypeScript 
'use client';

import { useState } from 'react';

export function LikeButton({ initialCount }: { initialCount: number }) {
  const [count, setCount] = useState(initialCount);
  return (
    <button onClick={() => setCount(c => c + 1)}>
      ♥ {count}
    </button>
  );
}
ℹ️
Key Rule

Server Components can import Client Components, but not vice versa. Pass Server Component data to Client Components via props. You can also pass Server Components as children to Client Components — they still run on the server.

Data Fetching Patterns

fetch() with caching in Server Components

Next.js extends the native fetch API with caching semantics controlled by the cache and next options.

lib/api.ts TypeScript 
type Post = { id: string; title: string; body: string };

// Static: cached indefinitely (like getStaticProps)
export async function getPosts(): Promise<Post[]> {
  const res = await fetch('https://api.example.com/posts', {
    next: { revalidate: 3600 }, // ISR: revalidate every hour
  });
  if (!res.ok) throw new Error('Failed to fetch posts');
  return res.json();
}

// Dynamic: never cached (like getServerSideProps)
export async function getPost(id: string): Promise<Post> {
  const res = await fetch(`https://api.example.com/posts/${id}`, {
    cache: 'no-store',
  });
  if (!res.ok) notFound();
  return res.json();
}

Client-side fetching with TanStack Query

For real-time or user-specific data that changes after initial load, TanStack Query is the standard.

components/user-profile.tsx TypeScript 
'use client';

import { useQuery } from '@tanstack/react-query';

type User = { id: string; name: string; email: string };

export function UserProfile({ userId }: { userId: string }) {
  const { data, isPending } = useQuery({
    queryKey: ['user', userId],
    queryFn: (): Promise<User> =>
      fetch(`/api/users/${userId}`).then(r => r.json()),
  });

  if (isPending) return <Spinner />;
  return <div>{data?.name}</div>;
}

Server Actions

Server Actions are async functions that run on the server, triggered from a form or client event. They eliminate the need for a dedicated API route for most mutations. The 'use server' directive marks a function (or entire module) as a Server Action.

app/posts/actions.ts TypeScript 
'use server';

import { revalidatePath } from 'next/cache';
import { redirect } from 'next/navigation';
import { db } from '@/lib/db';
import { z } from 'zod';

const CreatePostSchema = z.object({
  title: z.string().min(3).max(100),
  body: z.string().min(10),
});

export async function createPost(formData: FormData) {
  const parsed = CreatePostSchema.safeParse({
    title: formData.get('title'),
    body: formData.get('body'),
  });

  if (!parsed.success) {
    return { error: parsed.error.flatten().fieldErrors };
  }

  const post = await db.post.create({ data: parsed.data });
  revalidatePath('/posts');        // bust the cache for /posts
  redirect(`/posts/${post.id}`);  // navigate to new post
}
app/posts/new/page.tsx TypeScript 
import { createPost } from '../actions';

export default function NewPostPage() {
  return (
    <form action={createPost}>  {/* action takes a Server Action directly */}
      <input name="title" placeholder="Title" required />
      <textarea name="body" placeholder="Content" required />
      <button type="submit">Publish</button>
    </form>
  );
}
🤖
AI Era

Server Actions are ideal for AI-powered mutations: call an LLM, stream the response, write to the DB, and revalidate the cache — all in a single typed function with no API surface to maintain. Pair with the Vercel AI SDK's streamText for streaming responses.

Route Handlers (API Routes)

Route Handlers live in route.ts files inside the app directory. Named exports match HTTP methods: GET, POST, PUT, DELETE, etc.

app/api/users/route.ts TypeScript 
import { NextRequest, NextResponse } from 'next/server';
import { db } from '@/lib/db';
import { z } from 'zod';

export async function GET() {
  const users = await db.user.findMany({ select: { id: true, name: true } });
  return NextResponse.json(users);
}

const CreateUserBody = z.object({ name: z.string(), email: z.string().email() });

export async function POST(req: NextRequest) {
  const body = await req.json();
  const parsed = CreateUserBody.safeParse(body);
  if (!parsed.success) {
    return NextResponse.json({ error: parsed.error.flatten() }, { status: 400 });
  }
  const user = await db.user.create({ data: parsed.data });
  return NextResponse.json(user, { status: 201 });
}

Dynamic route handlers

app/api/users/[id]/route.ts TypeScript 
import { NextRequest, NextResponse } from 'next/server';

type Context = { params: Promise<{ id: string }> };

export async function GET(req: NextRequest, { params }: Context) {
  const { id } = await params;
  const user = await db.user.findUnique({ where: { id } });
  if (!user) return NextResponse.json({ error: 'Not found' }, { status: 404 });
  return NextResponse.json(user);
}

export async function DELETE(req: NextRequest, { params }: Context) {
  const { id } = await params;
  await db.user.delete({ where: { id } });
  return new NextResponse(null, { status: 204 });
}
💡
Tip

Prefer Server Actions over Route Handlers for form mutations. Use Route Handlers when you need a public REST/JSON API consumed by third-party clients or mobile apps.

Middleware

middleware.ts sits at the project root and runs on the Edge Runtime before every matched request. It's the right place for auth checks, redirects, and A/B testing — anything that must happen before a page renders.

middleware.ts TypeScript 
import { NextRequest, NextResponse } from 'next/server';
import { getToken } from 'next-auth/jwt';

export async function middleware(req: NextRequest) {
  const token = await getToken({ req, secret: process.env.AUTH_SECRET });

  // Protect /dashboard and all nested routes
  if (req.nextUrl.pathname.startsWith('/dashboard') && !token) {
    const loginUrl = new URL('/login', req.url);
    loginUrl.searchParams.set('callbackUrl', req.url);
    return NextResponse.redirect(loginUrl);
  }

  return NextResponse.next();
}

// Only run middleware on matched paths — avoid running on static files
export const config = {
  matcher: ['/dashboard/:path*', '/api/protected/:path*'],
};
⚠️
Warning

Middleware runs on the Edge Runtime — a subset of Node.js APIs. You cannot use Prisma, native Node modules, or large npm packages. Keep it lightweight: read cookies/headers, decode JWTs, redirect.

Deployment

Vercel — zero config

Push to GitHub. Connect the repo in the Vercel dashboard. Done. Vercel auto-detects Next.js, builds on every push, manages preview deployments per branch, and sets production domains. Environment variables are managed in the Vercel dashboard and injected at build time.

💡
Tip

Use vercel env pull .env.local to sync Vercel environment variables to your local machine, keeping secrets in sync without manual copy-paste.

Docker — self-hosted

Dockerfile dockerfile 
FROM node:22-alpine AS base

FROM base AS deps
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile

FROM base AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN pnpm build

FROM base AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
EXPOSE 3000
CMD ["node", "server.js"]

Complete Example: Blog App

Let's put it all together. A minimal blog with a post listing page, a dynamic post page, and a Server Action to create posts — no separate backend required.

Post listing — Server Component

app/blog/page.tsx TypeScript 
import Link from 'next/link';
import { db } from '@/lib/db';

export const metadata = { title: 'Blog' };

export default async function BlogPage() {
  const posts = await db.post.findMany({
    select: { slug: true, title: true, publishedAt: true },
    orderBy: { publishedAt: 'desc' },
  });

  return (
    <div className="max-w-2xl mx-auto py-16 px-4">
      <h1 className="text-3xl font-bold mb-8">Blog</h1>
      <ul className="space-y-4">
        {posts.map(post => (
          <li key={post.slug}>
            <Link href={`/blog/${post.slug}`} className="text-lg font-medium hover:underline">
              {post.title}
            </Link>
            <p className="text-sm text-gray-500">
              {post.publishedAt.toLocaleDateString()}
            </p>
          </li>
        ))}
      </ul>
    </div>
  );
}

Individual post — dynamic route

app/blog/[slug]/page.tsx TypeScript 
import { notFound } from 'next/navigation';
import { db } from '@/lib/db';
import type { Metadata } from 'next';

type Props = { params: Promise<{ slug: string }> };

export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { slug } = await params;
  const post = await db.post.findUnique({ where: { slug } });
  return { title: post?.title ?? 'Not found' };
}

// Pre-render all known slugs at build time
export async function generateStaticParams() {
  const posts = await db.post.findMany({ select: { slug: true } });
  return posts.map(p => ({ slug: p.slug }));
}

export default async function PostPage({ params }: Props) {
  const { slug } = await params;
  const post = await db.post.findUnique({ where: { slug } });
  if (!post) notFound();

  return (
    <article className="max-w-2xl mx-auto py-16 px-4 prose">
      <h1>{post.title}</h1>
      <p>{post.body}</p>
    </article>
  );
}

Create post — Server Action

app/blog/new/page.tsx TypeScript 
import { revalidatePath } from 'next/cache';
import { redirect } from 'next/navigation';
import { db } from '@/lib/db';

async function createPost(formData: FormData) {
  'use server';
  const title = formData.get('title') as string;
  const body = formData.get('body') as string;
  const slug = title.toLowerCase().replace(/\s+/g, '-');

  await db.post.create({
    data: { title, body, slug, publishedAt: new Date() },
  });

  revalidatePath('/blog');
  redirect(`/blog/${slug}`);
}

export default function NewPostPage() {
  return (
    <form action={createPost} className="max-w-2xl mx-auto py-16 px-4 space-y-4">
      <h1 className="text-2xl font-bold">New Post</h1>
      <input name="title" placeholder="Title" required className="w-full border p-2 rounded" />
      <textarea name="body" placeholder="Content" rows={10} required className="w-full border p-2 rounded" />
      <button type="submit" className="bg-indigo-600 text-white px-4 py-2 rounded">
        Publish
      </button>
    </form>
  );
}
