1. The AI Application Layer

The modern AI stack has three layers. At the bottom: infrastructure — GPUs, distributed training, model serving. In the middle: the models themselves. At the top: the application layer, where TypeScript dominates. Every major AI SDK ships TypeScript types as first-class citizens. The tooling — evals, prompt registries, observability dashboards — is built in TypeScript. The applications users interact with are built in TypeScript.

The AI stack — TypeScript owns the application layer.

Types of AI applications

  • Chatbots: Multi-turn conversation with memory, persona, and tool access.
  • Coding assistants: Code generation, explanation, refactoring (think Cursor, GitHub Copilot).
  • RAG systems: Retrieval-Augmented Generation — answer questions from your own documents.
  • Agents: Autonomous systems that plan and use tools to complete multi-step tasks.
  • Pipelines: Batch processing, content generation, data extraction at scale.

Why TypeScript is the best language for AI apps

Three reasons TypeScript wins here specifically:

  1. Type safety for complex responses. LLM responses are rich, nested JSON. TypeScript lets you define exactly the shape you expect and validate it at runtime with Zod.
  2. LLMs understand TypeScript types. When you write a TypeScript interface for a tool's input schema, Claude reads that type and produces valid JSON. The type IS the prompt.
  3. The ecosystem. Every AI SDK — Anthropic, OpenAI, Google, Vercel — ships TypeScript types. The tooling is TypeScript-first.
AI Era Note

TypeScript types are one of the highest-leverage tools in prompt engineering. When you define a z.object() schema and pass it to generateObject(), you are simultaneously writing runtime validation logic and instructing the model on exactly what JSON to produce. One artifact, two jobs.

3. Streaming Responses

Without streaming, users stare at a blank page for 3–10 seconds before seeing any output. With streaming, they see the first token in under 500ms. For any user-facing AI feature, streaming is not optional — it is the baseline expectation.

Streaming with the Anthropic SDK

streaming.ts — basic streamingTypeScript
import { client } from './client'

async function streamResponse(userMessage: string): Promise<void> {
  const stream = await client.messages.stream({
    model: 'claude-sonnet-4-6',
    max_tokens: 1024,
    messages: [{ role: 'user', content: userMessage }],
  })

  // Iterate over stream events
  for await (const chunk of stream) {
    if (
      chunk.type === 'content_block_delta' &&
      chunk.delta.type === 'text_delta'
    ) {
      process.stdout.write(chunk.delta.text)
    }
  }

  // After the loop, get the complete final message with usage stats
  const finalMessage = await stream.finalMessage()
  console.log('\n\nTokens used:', finalMessage.usage)
}

await streamResponse('Write a TypeScript implementation of binary search.')

Stream event types

The stream emits a discriminated union of event types. TypeScript's narrowing makes handling them clean:

All stream event typesTypeScript
for await (const event of stream) {
  switch (event.type) {
    case 'message_start':
      // event.message — the initial message object (no content yet)
      break
    case 'content_block_start':
      // event.content_block — { type: 'text' | 'tool_use', ... }
      break
    case 'content_block_delta':
      if (event.delta.type === 'text_delta') {
        process.stdout.write(event.delta.text)
      }
      if (event.delta.type === 'input_json_delta') {
        // Streaming tool input JSON — partial JSON string
        process.stdout.write(event.delta.partial_json)
      }
      break
    case 'content_block_stop':
      // One content block finished
      break
    case 'message_delta':
      // event.delta.stop_reason — why the message ended
      // event.usage — output token count
      break
    case 'message_stop':
      // Stream is complete
      break
  }
}

Streaming in a Next.js API route

app/api/chat/route.ts — Next.js App RouterTypeScript
import { NextRequest } from 'next/server'
import Anthropic from '@anthropic-ai/sdk'

const anthropic = new Anthropic()

export async function POST(req: NextRequest) {
  const { messages } = await req.json()

  // Create a ReadableStream that pumps Anthropic SSE events
  const stream = new ReadableStream({
    async start(controller) {
      const encoder = new TextEncoder()

      const anthropicStream = await anthropic.messages.stream({
        model: 'claude-sonnet-4-6',
        max_tokens: 2048,
        messages,
      })

      for await (const chunk of anthropicStream) {
        if (
          chunk.type === 'content_block_delta' &&
          chunk.delta.type === 'text_delta'
        ) {
          // SSE format: "data: {text}\n\n"
          const data = `data: ${JSON.stringify({ text: chunk.delta.text })}\n\n`
          controller.enqueue(encoder.encode(data))
        }
      }

      controller.enqueue(encoder.encode('data: [DONE]\n\n'))
      controller.close()
    },
  })

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive',
    },
  })
}

Consuming SSE in a React component

components/ChatStream.tsxTypeScript
'use client'
import { useState } from 'react'

export function ChatStream() {
  const [response, setResponse] = useState('')
  const [loading, setLoading] = useState(false)

  async function sendMessage(userInput: string) {
    setLoading(true)
    setResponse('')

    const res = await fetch('/api/chat', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ messages: [{ role: 'user', content: userInput }] }),
    })

    if (!res.body) return
    const reader = res.body.getReader()
    const decoder = new TextDecoder()

    while (true) {
      const { done, value } = await reader.read()
      if (done) break

      const lines = decoder.decode(value).split('\n')
      for (const line of lines) {
        if (!line.startsWith('data: ')) continue
        const data = line.slice(6)
        if (data === '[DONE]') { setLoading(false); break }
        const { text } = JSON.parse(data)
        setResponse(prev => prev + text)
      }
    }
  }

  return (
    <div>
      <button onClick={() => sendMessage('Explain async/await in TypeScript')} disabled={loading}>
        {loading ? 'Thinking...' : 'Ask Claude'}
      </button>
      <pre style={{ whiteSpace: 'pre-wrap' }}>{response}</pre>
    </div>
  )
}

4. Tool Use (Function Calling)

Tool use lets Claude call functions you define. Claude decides when to call them, extracts the arguments from context, and you execute the actual logic. This is the primitive that makes agents possible.

The tool use loop — Claude decides when to call tools; you execute them.

The complete tool use loop

tool-loop.ts — full implementationTypeScript
import Anthropic from '@anthropic-ai/sdk'
import { weatherTool, searchTool } from './tools/weather'

const client = new Anthropic()

// --- Type-safe tool input types ---
interface WeatherInput {
  location: string
  unit?: 'celsius' | 'fahrenheit'
}

interface SearchInput {
  query: string
  num_results?: number
}

// --- Mock tool implementations (replace with real APIs) ---
async function getWeather(input: WeatherInput): Promise<string> {
  // Real implementation would call a weather API
  const unit = input.unit ?? 'celsius'
  return JSON.stringify({
    location: input.location,
    temperature: unit === 'celsius' ? 18 : 64,
    unit,
    conditions: 'Partly cloudy',
    humidity: '62%',
    wind: '12 km/h SW',
  })
}

async function webSearch(input: SearchInput): Promise<string> {
  // Real implementation would call a search API
  return JSON.stringify({
    results: [
      { title: 'Result 1', snippet: 'Relevant content...', url: 'https://example.com' },
    ],
  })
}

// --- Tool dispatcher — maps tool name to implementation ---
async function executeTool(
  name: string,
  input: Record<string, unknown>
): Promise<string> {
  switch (name) {
    case 'get_weather':
      return getWeather(input as WeatherInput)
    case 'web_search':
      return webSearch(input as SearchInput)
    default:
      throw new Error(`Unknown tool: ${name}`)
  }
}

// --- The tool use loop ---
export async function runWithTools(userMessage: string): Promise<string> {
  const messages: Anthropic.MessageParam[] = [
    { role: 'user', content: userMessage },
  ]

  // Loop until Claude stops requesting tools
  while (true) {
    const response = await client.messages.create({
      model: 'claude-sonnet-4-6',
      max_tokens: 4096,
      tools: [weatherTool, searchTool],
      messages,
    })

    // If Claude is done, return the final text
    if (response.stop_reason === 'end_turn') {
      const textBlock = response.content.find(b => b.type === 'text')
      return textBlock?.type === 'text' ? textBlock.text : ''
    }

    // Collect all tool_use blocks from this response
    const toolUseBlocks = response.content.filter(
      (b): b is Anthropic.ToolUseBlock => b.type === 'tool_use'
    )

    if (toolUseBlocks.length === 0) break

    // Add Claude's response to the conversation
    messages.push({ role: 'assistant', content: response.content })

    // Execute all tools (possibly in parallel) and collect results
    const toolResults = await Promise.all(
      toolUseBlocks.map(async (toolUse) => {
        const result = await executeTool(
          toolUse.name,
          toolUse.input as Record<string, unknown>
        )
        return {
          type: 'tool_result' as const,
          tool_use_id: toolUse.id,
          content: result,
        }
      })
    )

    // Add tool results back into the conversation
    messages.push({ role: 'user', content: toolResults })
  }

  return 'No response generated.'
}

// --- Usage ---
const answer = await runWithTools(
  "What's the weather in Tokyo and Paris right now? Which city is warmer?"
)
console.log(answer)
Info — Parallel Tool Calls

Claude can request multiple tools in a single response — notice the toolUseBlocks array above. Always use Promise.all() to execute them concurrently. A single response with three tool calls that you execute sequentially is 3x slower than it needs to be.

Type-safe tool inputs with Zod

Validating tool inputs with ZodTypeScript
import { z } from 'zod'

// Define the schema once — derive both the type and the JSON Schema from it
const WeatherInputSchema = z.object({
  location: z.string().describe('City name, optionally with country code'),
  unit: z.enum(['celsius', 'fahrenheit']).default('celsius'),
})

type WeatherInput = z.infer<typeof WeatherInputSchema>

async function safeGetWeather(rawInput: unknown): Promise<string> {
  // Validate at the boundary — Claude might produce invalid JSON
  const input = WeatherInputSchema.parse(rawInput)
  // input is now fully typed as WeatherInput
  return getWeather(input)
}

// In your dispatcher:
case 'get_weather':
  return safeGetWeather(input)

5. Building a RAG System

Retrieval-Augmented Generation (RAG) is the most commonly deployed AI architecture in production. Instead of relying solely on the model's training data, you retrieve relevant documents from your own knowledge base and inject them into the context window. The model answers based on your data, not its parametric memory.

RAG architecture — documents are embedded offline; queries retrieve the most relevant chunks at runtime.

Complete TypeScript RAG implementation

rag/embed.ts — create embeddingsTypeScript
import OpenAI from 'openai'

// Anthropic does not yet have a public embeddings endpoint.
// Use OpenAI text-embedding-3-small — it is cheap and excellent.
const openai = new OpenAI()

export async function createEmbedding(text: string): Promise<number[]> {
  const response = await openai.embeddings.create({
    model: 'text-embedding-3-small', // 1536 dimensions
    input: text.replace(/\n/g, ' '), // newlines hurt embedding quality
  })
  return response.data[0].embedding
}

export async function createEmbeddingsBatch(
  texts: string[]
): Promise<number[][]> {
  const response = await openai.embeddings.create({
    model: 'text-embedding-3-small',
    input: texts.map(t => t.replace(/\n/g, ' ')),
  })
  return response.data.map(d => d.embedding)
}
rag/vector-store.ts — pgvector integrationTypeScript
import { Pool } from 'pg'

const pool = new Pool({ connectionString: process.env.DATABASE_URL })

export interface Document {
  id: string
  content: string
  metadata: Record<string, unknown>
  embedding: number[]
}

export interface SimilarDocument {
  id: string
  content: string
  metadata: Record<string, unknown>
  similarity: number
}

// Assumes this schema (from Chapter 14):
// CREATE TABLE documents (
//   id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
//   content TEXT NOT NULL,
//   metadata JSONB DEFAULT '{}',
//   embedding vector(1536)
// );
// CREATE INDEX ON documents USING ivfflat (embedding vector_cosine_ops);

export async function insertDocument(doc: Omit<Document, 'id'>): Promise<string> {
  const { rows } = await pool.query<{ id: string }>(
    `INSERT INTO documents (content, metadata, embedding)
     VALUES ($1, $2, $3)
     RETURNING id`,
    [doc.content, doc.metadata, JSON.stringify(doc.embedding)]
  )
  return rows[0].id
}

export async function findSimilarDocuments(
  queryEmbedding: number[],
  limit = 5,
  threshold = 0.7
): Promise<SimilarDocument[]> {
  const { rows } = await pool.query<SimilarDocument>(
    `SELECT
       id,
       content,
       metadata,
       1 - (embedding <=> $1::vector) AS similarity
     FROM documents
     WHERE 1 - (embedding <=> $1::vector) > $2
     ORDER BY embedding <=> $1::vector
     LIMIT $3`,
    [JSON.stringify(queryEmbedding), threshold, limit]
  )
  return rows
}
rag/query.ts — the complete RAG query functionTypeScript
import Anthropic from '@anthropic-ai/sdk'
import { createEmbedding } from './embed'
import { findSimilarDocuments, type SimilarDocument } from './vector-store'

const client = new Anthropic()

function buildRAGPrompt(question: string, contexts: SimilarDocument[]): string {
  const contextXml = contexts
    .map(
      (doc, i) => `
  <document index="${i + 1}" similarity="${doc.similarity.toFixed(3)}">
    <source>${JSON.stringify(doc.metadata)}</source>
    <content>${doc.content}</content>
  </document>`
    )
    .join('\n')

  return `You are a helpful assistant. Answer the question using ONLY the provided documents.
If the answer is not in the documents, say "I don't have information about that."
Always cite the document index when you use information from it (e.g., [1], [2]).

<documents>
${contextXml}
</documents>

<question>${question}</question>`
}

export async function ragQuery(question: string): Promise<{
  answer: string
  sources: SimilarDocument[]
  tokensUsed: number
}> {
  // 1. Embed the query
  const queryEmbedding = await createEmbedding(question)

  // 2. Retrieve top-k similar documents
  const contexts = await findSimilarDocuments(queryEmbedding, 5)

  if (contexts.length === 0) {
    return {
      answer: "I couldn't find any relevant documents to answer your question.",
      sources: [],
      tokensUsed: 0,
    }
  }

  // 3. Build the augmented prompt
  const prompt = buildRAGPrompt(question, contexts)

  // 4. Generate the answer
  const response = await client.messages.create({
    model: 'claude-sonnet-4-6',
    max_tokens: 1024,
    messages: [{ role: 'user', content: prompt }],
  })

  const answerBlock = response.content.find(b => b.type === 'text')
  const answer = answerBlock?.type === 'text' ? answerBlock.text : ''

  return {
    answer,
    sources: contexts,
    tokensUsed: response.usage.input_tokens + response.usage.output_tokens,
  }
}

// Usage:
const result = await ragQuery('How do I configure pgvector indexes?')
console.log(result.answer)
console.log('Sources:', result.sources.map(s => s.metadata))
console.log('Tokens used:', result.tokensUsed)

Ingestion pipeline

rag/ingest.ts — batch document ingestionTypeScript
import { readdir, readFile } from 'node:fs/promises'
import path from 'node:path'
import { createEmbeddingsBatch } from './embed'
import { insertDocument } from './vector-store'

interface ChunkedDocument {
  content: string
  metadata: { file: string; chunkIndex: number }
}

function chunkText(text: string, chunkSize = 512, overlap = 64): string[] {
  const words = text.split(/\s+/)
  const chunks: string[] = []
  let i = 0
  while (i < words.length) {
    chunks.push(words.slice(i, i + chunkSize).join(' '))
    i += chunkSize - overlap
  }
  return chunks
}

export async function ingestDirectory(dirPath: string): Promise<void> {
  const files = await readdir(dirPath)
  const markdownFiles = files.filter(f => f.endsWith('.md') || f.endsWith('.txt'))

  for (const file of markdownFiles) {
    const content = await readFile(path.join(dirPath, file), 'utf-8')
    const chunks = chunkText(content)

    console.log(`Ingesting ${file}: ${chunks.length} chunks`)

    // Batch embed chunks (more efficient than one-at-a-time)
    const embeddings = await createEmbeddingsBatch(chunks)

    // Insert all chunks
    await Promise.all(
      chunks.map((chunk, i) =>
        insertDocument({
          content: chunk,
          metadata: { file, chunkIndex: i },
          embedding: embeddings[i],
        })
      )
    )
  }

  console.log('Ingestion complete.')
}

await ingestDirectory('./docs')
Cost Warning — Embeddings at Scale

Embedding costs are low per token, but ingesting a large document corpus can still add up. Cache embeddings aggressively — if a document has not changed, do not re-embed it. Store a content hash in metadata and skip ingestion when the hash matches.

6. Building AI Agents

An agent is an AI system that autonomously uses tools to complete tasks that require multiple steps, decisions, and observations. The difference between a chatbot and an agent is that an agent does things — it reads files, calls APIs, writes code, searches the web — rather than just generating text.

The agent loop — think, act, observe, repeat until task complete.

A complete TypeScript agent

// --- Tool executor ---
import { readFile, writeFile } from 'node:fs/promises'
import { exec } from 'node:child_process'
import { promisify } from 'node:util'

const execAsync = promisify(exec)

async function executeTool(
  name: string,
  input: Record<string, unknown>
): Promise<string> {
  try {
    switch (name) {
      case 'read_file': {
        const content = await readFile(input.path as string, 'utf-8')
        return content
      }
      case 'write_file': {
        await writeFile(input.path as string, input.content as string, 'utf-8')
        return `File written successfully to ${input.path}`
      }
      case 'run_command': {
        const { stdout, stderr } = await execAsync(input.command as string, {
          timeout: 30_000,
        })
        return stdout || stderr || '(no output)'
      }
      default:
        return `Error: unknown tool "${name}"`
    }
  } catch (err) {
    return `Error: ${err instanceof Error ? err.message : String(err)}`
  }
}

// --- Agent configuration ---
interface AgentConfig {
  model?: string
  maxIterations?: number
  systemPrompt?: string
}

// --- The agent ---
export async function runAgent(
  task: string,
  config: AgentConfig = {}
): Promise<string> {
  const {
    model = 'claude-sonnet-4-6',
    maxIterations = 20,
    systemPrompt = `You are a capable software engineering assistant.
Complete tasks step by step. Think carefully before acting.
Always verify your work — read files after writing them.
When the task is complete, summarize what you did.`,
  } = config

  const messages: Anthropic.MessageParam[] = [
    { role: 'user', content: task },
  ]

  let iterations = 0

  while (iterations < maxIterations) {
    iterations++
    console.log(`\n--- Agent iteration ${iterations} ---`)

    const response = await client.messages.create({
      model,
      max_tokens: 4096,
      system: systemPrompt,
      tools: TOOLS,
      messages,
    })

    console.log(`Stop reason: ${response.stop_reason}`)

    // Log any text Claude produces (its "thinking out loud")
    for (const block of response.content) {
      if (block.type === 'text' && block.text) {
        console.log('Claude:', block.text.slice(0, 200))
      }
    }

    // Task complete — return the final answer
    if (response.stop_reason === 'end_turn') {
      const textBlock = response.content.find(b => b.type === 'text')
      return textBlock?.type === 'text' ? textBlock.text : 'Task completed.'
    }

    // Execute tool calls
    const toolUseBlocks = response.content.filter(
      (b): b is Anthropic.ToolUseBlock => b.type === 'tool_use'
    )

    if (toolUseBlocks.length === 0) break

    // Add Claude's response to history
    messages.push({ role: 'assistant', content: response.content })

    // Execute all tools in parallel
    const toolResults = await Promise.all(
      toolUseBlocks.map(async (toolUse) => {
        console.log(`Executing tool: ${toolUse.name}`, toolUse.input)
        const result = await executeTool(
          toolUse.name,
          toolUse.input as Record<string, unknown>
        )
        console.log(`Tool result (first 200 chars):`, result.slice(0, 200))
        return {
          type: 'tool_result' as const,
          tool_use_id: toolUse.id,
          content: result,
        }
      })
    )

    // Add results to history
    messages.push({ role: 'user', content: toolResults })
  }

  return `Agent stopped after ${maxIterations} iterations.`
}

// Usage:
const result = await runAgent(
  'Read package.json, check the TypeScript version, ' +
  'then create a summary.md with the project dependencies.'

Agent memory

Agents have two types of memory:

  • Short-term (context window): The messages array you pass on each iteration. Limited to the model's context window (~200K tokens for Claude). Free — no extra storage needed.
  • Long-term (external storage): A database or vector store the agent writes to and queries via tools. Persistent across sessions. Required for agents that work over multiple conversations or need to remember past actions.
Warning — Agents Need Guardrails

Never give an agent unrestricted shell access in production. Sandbox tool execution: use Docker containers, restrict allowed commands, rate-limit writes, and require human approval for irreversible actions. The run_command tool above is for illustration — harden it before deploying.

Error handling for AI calls

lib/ai-client.ts — robust error handlingTypeScript
import Anthropic from '@anthropic-ai/sdk'

const client = new Anthropic({ maxRetries: 3 })

export class AIError extends Error {
  constructor(
    message: string,
    public readonly code: string,
    public readonly retryable: boolean
  ) {
    super(message)
    this.name = 'AIError'
  }
}

export async function safeComplete(
  params: Anthropic.MessageCreateParamsNonStreaming
): Promise<Anthropic.Message> {
  try {
    return await client.messages.create(params)
  } catch (err) {
    if (err instanceof Anthropic.APIError) {
      // Rate limit — the SDK retries automatically, but surface it clearly
      if (err.status === 429) {
        throw new AIError('Rate limit exceeded', 'RATE_LIMIT', true)
      }
      // Context window exceeded
      if (err.status === 400 && err.message.includes('max_tokens')) {
        throw new AIError('Context window exceeded', 'CONTEXT_LIMIT', false)
      }
      // Server errors — retryable
      if (err.status >= 500) {
        throw new AIError(`Anthropic server error: ${err.message}`, 'SERVER_ERROR', true)
      }
      throw new AIError(err.message, 'API_ERROR', false)
    }
    throw err
  }
}

Prompt caching

Anthropic's prompt caching lets you cache large, repeated portions of your context (system prompts, documents, tool definitions) across API calls. Cached tokens cost ~10% of normal input token price.

// response.usage.cache_creation_input_tokens — tokens written to cache
Cost Warning — When to Use Caching

Prompt caching has a minimum cacheable size (typically 1024 tokens) and charges a small fee to write the cache. It pays off when: (1) your system prompt is large and repeated, (2) you have many users hitting the same RAG documents, or (3) you pass large tool definitions on every call. For short prompts or one-off requests, caching adds cost.

Rate limiting and cost control

lib/rate-limiter.tsTypeScript
import Anthropic from '@anthropic-ai/sdk'

// Simple token-bucket rate limiter
class RateLimiter {
  private tokens: number
  private lastRefill: number

  constructor(
    private readonly maxTokens: number,
    private readonly refillRatePerSecond: number
  ) {
    this.tokens = maxTokens
    this.lastRefill = Date.now()
  }

  async acquire(cost = 1): Promise<void> {
    this.refill()
    if (this.tokens < cost) {
      const waitMs = ((cost - this.tokens) / this.refillRatePerSecond) * 1000
      await new Promise(resolve => setTimeout(resolve, waitMs))
      this.refill()
    }
    this.tokens -= cost
  }

  private refill(): void {
    const now = Date.now()
    const elapsed = (now - this.lastRefill) / 1000
    this.tokens = Math.min(this.maxTokens, this.tokens + elapsed * this.refillRatePerSecond)
    this.lastRefill = now
  }
}

// 60 requests per minute
const limiter = new RateLimiter(60, 1)

export async function rateLimitedComplete(
  params: Anthropic.MessageCreateParamsNonStreaming,
  anthropic: Anthropic
): Promise<Anthropic.Message> {
  await limiter.acquire()
  return anthropic.messages.create(params)
}

  const content = JSON.stringify({ system: params.system, first: params.messages[0] })

evals/eval-runner.ts — LLM-as-judge patternTypeScript
import Anthropic from '@anthropic-ai/sdk'
import { z } from 'zod'

const client = new Anthropic()

interface EvalCase {
  input: string
  expectedOutput?: string
  rubric: string
}

const EvalResultSchema = z.object({
  score: z.number().min(0).max(10),
  reasoning: z.string(),
  pass: z.boolean(),
})

async function evaluateResponse(
  evalCase: EvalCase,
  actualOutput: string
): Promise<z.infer<typeof EvalResultSchema>> {
  const response = await client.messages.create({
    model: 'claude-opus-4-7', // Use the strongest model as judge
    max_tokens: 512,
    messages: [{
      role: 'user',
      content: `You are an evaluator. Score the AI response on a scale of 0-10.

<rubric>${evalCase.rubric}</rubric>
<input>${evalCase.input}</input>
<expected>${evalCase.expectedOutput ?? 'No reference answer — evaluate on rubric only.'}</expected>
<actual>${actualOutput}</actual>

Respond with JSON only:
{"score": number, "reasoning": "string", "pass": boolean}`,
    }],
  })

  const text = response.content.find(b => b.type === 'text')?.text ?? ''
  return EvalResultSchema.parse(JSON.parse(text))
}

// Run an eval suite
export async function runEvalSuite(
  cases: EvalCase[],
  systemUnderTest: (input: string) => Promise<string>
) {
  const results = await Promise.all(
    cases.map(async (c) => {
      const actual = await systemUnderTest(c.input)
      return evaluateResponse(c, actual)
    })
  )

  const avgScore = results.reduce((s, r) => s + r.score, 0) / results.length
  const passRate = results.filter(r => r.pass).length / results.length

  console.log(`Average score: ${avgScore.toFixed(1)}/10`)
  console.log(`Pass rate: ${(passRate * 100).toFixed(0)}%`)
  return results
}

import Anthropic from '@anthropic-ai/sdk'

const client = new Anthropic()

interface Conversation {
  messages: Anthropic.MessageParam[]
  systemPrompt: string
}

export function createConversation(systemPrompt: string): Conversation {
  return { messages: [], systemPrompt }
}

export async function chat(
  conversation: Conversation,
  userMessage: string
): Promise<string> {
  // Add user message to history
  conversation.messages.push({ role: 'user', content: userMessage })

  const response = await client.messages.create({
    model: 'claude-sonnet-4-6',
    max_tokens: 2048,
    system: conversation.systemPrompt,
    messages: conversation.messages,
  })

  const assistantText = response.content
    .filter((b): b is Anthropic.TextBlock => b.type === 'text')
    .map(b => b.text)
    .join('')

  // Add assistant response to history
  conversation.messages.push({ role: 'assistant', content: assistantText })

  // Trim history if context window is getting full (~180K tokens)
  if (conversation.messages.length > 100) {
    // Keep system prompt + last 50 turns
    conversation.messages = conversation.messages.slice(-50)
  }

  return assistantText
}

    .replace(/^```(?:json)?\n?/, '')
    .replace(/\n?```$/, '')

}

AI Era Note — The Composability Principle

The patterns in this section compose cleanly: run moderation on user input, embed it for RAG retrieval, inject the retrieved context into a structured extraction prompt, parse the result with Zod, log the token usage, and cache the system prompt — all in a single request pipeline. TypeScript's type system ensures the data shapes are correct at every boundary. This composability is why TypeScript has become the language of the AI application era.

Anthropic Tip — Designing for Reliability

Three practices that dramatically improve production AI reliability:

  • Always validate outputs with Zod. Claude is very good but not perfect — schema validation catches the 1-in-100 malformed responses before they reach your database.
  • Log every request. When something goes wrong, you need the prompt, the response, and the token counts. Storage is cheap; debugging without logs is expensive.
  • Build evals before you ship. Write a small eval suite (20–50 test cases) for every AI feature. Run it in CI. A prompt change that breaks 30% of cases is indistinguishable from a good change without evals.
